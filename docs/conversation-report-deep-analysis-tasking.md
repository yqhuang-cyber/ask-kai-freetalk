## 1. 用户能得到什么

老师布置作业 → 学生在事先告知文本 / 音频用途并获相应授权后进行主题对话 → 结束并提交 → 系统读取该次尝试中的实际学生识别文本、Kai 已输出文本、获准的学生语音片段和任务目标 → 并行执行上下文语义分析与真实音频发音评测 → 汇总有来源的听懂情况、口语表达、发音及针对性练习 → 学生与老师查看适合各自的反馈。分析失败时提交仍成功，界面提供明确状态与可重试路径。

报告应回答：这次在聊什么；学生对哪些问题作出相关回应、哪些地方请求重复或澄清；实际使用了哪些词句、如何组织表达、有哪些可核对的语言问题或亮点；获得了哪些可确认的帮助；下次练什么、为什么，以及如何练。每条重要观察都连接原始文本证据和上下文，明确“观察 / 待核对 / 证据不足”。

**发音分析与听懂情况、口语语义分析共同构成本 feature 的核心交付；自动等级仍不是前置。** 文本支持情境理解和文字表达分析，发音必须读取获准的学生真实音频，并分别验证声母 / 韵母、声调与语流维度。不能单凭转写判断听觉通道或声学表现。字幕、英文、拼音、示范和播放状态有不确定性时，明确说明，不能把语义相关回应直接说成纯听力能力或独立完成。

## 2. 当前现状与目标边界

| 项目 | 当前已实现 | 本 feature 目标 |
| --- | --- | --- |

所有模型 / 发音服务分析均走 M4 的提交后异步路径，不增加实时语音响应依赖，也不让提交回执等待提供方。语义 / 发音分支可并行，汇总按依赖执行；“离线”仍可需要网络访问云服务。结束先保存封口、明确提交后建分析 job，关页不自动提交，关页后已获准 job 仍可执行。单次对话因未授权、声音质量差或来源不足不能评发音时，允许正常提交并显示部分报告及原因；这不豁免产品对正常、获准且质量合格对话的发音分析交付要求。

## 4. 任务细化

### M4-01 / M4-02：数据归属与独立异步服务

- **M4-01（架构设计已确认）：**对话文本、必要学生音频、覆盖 manifest、提交、分析任务、候选与报告作为 M4 的本次 `TeachingRecord` 聚合，独立于静态画像与长期掌握；M2 仅负责有界采集 / 归属 / 封口与授权转交，M5 提供文本 / 声学能力。详细职责见[架构确认](conversation-report-m4-architecture.md)。
- **M4-02（待实施）：**将分析 Worker 与 M4 权威数据 / 授权 API 分成独立子进程。通过内部受认证的任务委托、claim / read / heartbeat / stage-commit / report-commit 运行；数据服务保持唯一 SQLite writer，Worker 不自行打开共享 DB 或实例化有会话恢复副作用的业务服务。
- submission / job 原子提交后立即回执；Worker 领取固定快照，语义与发音分支按资源限额并行，分别校验后汇总并写回 M4；浏览器退出仍可完成分析。外部调用在事务外，队列 / 任务恢复不要求先引入 Redis 或外部 HSKai。
- 验收：Worker 停止 / 重启 / 超时不终止实时对话、不阻塞数据 API 或明确提交；无 Worker 时任务可持久排队。lease / 输入 hash / epoch 的原子提交阻止重复领取和迟到覆盖，外呼状态未知不静默重试。授权 / 删除 / TTL 和师生投影由 M4 权威执行。

### DR-01：文本与报告契约（对应 TA-12 / TA-15）

- 设计 `ConversationRecord` / `TranscriptSegment` / `AudioSegment` / `TranscriptManifest` / `AudioManifest` / `AnalysisCandidate` / `AnalysisResult` 版本化契约，明确所属 learner / assignment / attempt / session / 已发布 plan hash / 权限代次及创建、封口、版本和保留信息。
- 学生段：仅 accepted、归属有效的 `user.final`，保留事件与轮次、ASR 文本、接收顺序、识别不确定 / 丢失状态。接收时间不是实际说话结束时间；若未取得可信协议依据则说话时间 unknown。
- Kai 段：只记录通过安全和输出门且实际转发的文本，按 response / turn 聚合 delta；保留 completed / cancelled / interrupted / incomplete 和缺段状态。已输出或已转发不等于真实播放或学生听到；无法确认的播放 / 字幕 / 帮助归因保持 unknown。控制语句与内容分开，不作为学习成果。
- 学生音频段：绑定 attempt / session、采样范围与编码、独立 audio hash、说话人 / 轮次归属、文本对齐版本及置信度、噪声 / 削波 / 丢帧 / 重叠和缺口、授权 / 过期时间；没有可靠对齐时不得假定 ASR final 的到达时刻就是词语发生时刻。
- 为每段提供稳定、不跨尝试的来源 ID 与可验证文字范围；候选引用指向学生还是 Kai、完整还是中断及其必要前后文。快照 hash 绑定有序文本、覆盖和 plan 版本；不能把规则命中数当作覆盖率。
- `TranscriptManifest` 至少包括已接受输入总数、已持久输入数、已转发回复数、可分析文本数、丢失 / 截断 / 迟到 / 不确定、封口状态及原因。按计数和范围说明分母，不把无法确认的总量标成完整。区分授权不可用、片段缺失和真正空会话。
- 完成：示例覆盖非点餐主题、长会话、打断 / 缺口 / 跨会话与旧版记录；明确实际内部事件来自现有适配与实测，不从业务模型推断 provider 事件或保证。

### DR-02：告知、授权与数据生命周期（对应 TA-17）

- 开聊前清楚告知：记录学生识别文本、Kai 回复，以及用于本次发音评测的必要学生语音片段；文本与音频分别说明用途、接收服务和保留期限，学生能选择是否进行相应记录 / 分析。关闭或撤回时停止对应数据记录和分析，学生仍可继续或结束练习；保留已有提交状态；不悄悄退化为“已分析”。身份、课程与学习记录通过现有授权的本地 Mock HSKai 边界。
- 文本与音频分开管理：本功能在音频用途已告知并获准后，记录完成对话发音分析所必需的学生语音片段；不因此归档环境录音或原始供应商流。加密传输 / 本机存储权限、按角色最小访问、日志脱敏、删除和派生报告处理有明确实现；真实 transcript、音频、原始 provider traces 与密钥不进 Git / 常规日志。
- POC 建议文本与必要学生音频均采用可配置的短保留期，本地阶段 A 初始设为 **7 天**，文本 / 音频可分别配置为 1～30 天；从 attempt 创建起算，后续选择与重试不延长；清理与显式删除覆盖文本、语音片段、对齐文件、声学结果、回听缓存、待执行任务和可识别派生报告，并阻止迟到结果复活。删除 / 授权代次应在读取、外呼前、写回前重复检查。
- 提供已保存、删除中 / 完成 / 失败和授权撤销的可理解状态；区分 Mock 删除回执、本地 SQLite / WAL / 临时文件及供应商侧实际处理。向文本模型或音频评测服务发送对应数据前，先落实该用途告知、相应授权和供应商使用 / 留存边界；无法确认时保持模型分析关闭。
- 真实学生 / 未成年人使用前另做正式授权、监护、数据地区、供应商与删除审查。本 tasking 不声称本地 Mock 已满足这些条件。

### DR-03：完整对话文本记录（对应 TA-12）

- 在现有网关已接受输入和已转发安全输出的位置接入独立 recorder：累积学生 final 与 Kai 回复；保留角色、关联、状态和可用顺序。不得截取前五轮、仅保留已命中表达，或只存开场 / 结尾。
- 对话期间经授权的本地业务服务增量持久化，采用有界队列 / 批写、幂等 segment ID、序列去重和版本迁移；不把网络 / DB 写入放进实时首音关键路径。明确满队列、断网 / DB 失败、重启、文本过长、单会话 / 全局容量上限：标注具体缺口与影响，不能静默丢弃或假报完整。
- 响应增量按拥有者聚合；中断时保留实际转发的部分并标 partial，不把整个生成文本或未展示部分冒充输出。对输出清空 / 恢复、中途刷新、断开和重复包按实际门控状态记录；敏感 / 风险披露按既有安全策略限制，不进入普通报告。
- 验收：10 分钟 / 超过 5 轮及容量边界；final 重复、并发响应、取消 / 旧音频与文字、无事件 ID / 响应归属、ASR late-final、断电重启和队列压力；学生、教师、session 隔离。对记录总数 / 实际写入数 / 丢失范围做断言，并验证不会拖慢语音关键路径。

### DR-04：封口、提交与来源隔离（对应 TA-12 / TA-14）

- 结束时停止采集与播放，给予有界 flush；固化本次 attempt 的文本 / 音频 fence、覆盖状态与版本。超时记缺口并结束，不把未持久化文本当成功；允许后续报告显示部分证据，是否允许提交按现有提交回执逻辑明确处理。
- 只有明确提交后创建分析 job；submission / job 原子写入或通过等价可靠 outbox。job 输入固定 `attempt_id + plan_hash + transcript_version/hash + audio_manifest_version/hash + auth/deletion epoch + analyzer版本`。重试幂等；新 attempt、重连或旧版本报告绝不与当前提交混合。
- 学生取消、断线、拒绝、授权撤回、危险内容限制、分析进行中删除 / 重开 / 重算分别定义状态和写回屏障。后续版本不能覆盖已发布报告 / 教师已审阅版本；旧对话未保存部分只能标 unavailable。
- 验收：提交响应丢失、重复提交 / job、超时与迟到 final、结束前后竞态、进程重启、旧版本结果后到、删除进行中 / 授权变化及跨学生构造均有明确结果。

### DR-05：文本分析模型与异步作业（对应 TA-15 / TA-19）

- 新增与备课、实时语音分离的 `ConversationReportAnalyzer` 端口；可复用现有 MiniMax 文本 transport 的已验证接口，但模型、配置、提示词 / schema 版本、开关、预算、失败和来源独立记录。备课用的模型调用或合成规则不自动构成报告模型能力。
- 模型输入：单次授权提交的计划 / 目标摘要、分角色且带状态的文本、覆盖 manifest、获准的相关背景；不输入其他学生、未授权画像、密钥或原始音频。明确学生 / 教师内容是数据、不能更改系统约束，防止对话内指令污染分析。
- 根据实际模型上下文窗口和会话上限先估算 token：短会话按完整文本处理；较长会话用前后重叠窗口逐段抽取有引用的候选，再跨窗口汇总。每个窗口覆盖范围、失败与重复去重可追踪；不得只截前几轮或把模型摘要替代原始来源。
- 明确队列领取、root deadline / 每窗口预算、最多一次格式修复、并发 / token 限额、取消、超时、提供方错误及手动幂等重试。预算数值先通过样本测量再冻结，不凭猜测承诺延迟。提交成功与报告生成独立；失败、超时、未配置、来源不可用要可见。
- 每条候选包含 `dimension / observation / evidence_refs / explanation / support / uncertainty / suggestion / status` 及适用范围；只记录必要元数据（模型 / prompt / schema / capability / rubric / data 版本、耗时 / 状态 / token 用量），不默认保存完整 prompt、响应或原始 provider trace。不要伪装合成结果为真实模型运行。

### DR-06：听懂情况与口语深入分析（对应 LST-02 / SPK-02）

- **情境理解：**参考 Kai 的实际问题和学生回应，分析对应信息、切题程度、明确澄清 / 重复请求、对问题的多轮推进。引用问题与回答并保留上下文；问题没有输出完整、答案早于或晚于问题不可判定、字幕 / 翻译 / 提示不明时，说明限制。不能把沉默、拒绝、断线、ASR 错误或没有机会当作听不懂。
- **口语表达：**分析表达意图是否清晰、内容完整性与连贯性、词汇选择、句式 / 语法自然度、话题参与、补充、追问和自我修正；引用学生的实际话语和相关上下文。覆盖同义表达、简单回答、混合语言和不同目标，不限制为作者预写模板。
- **语言问题：**对可从文本和上下文核对的具体用词 / 语法问题提出候选，保留学生本意，给出更自然的例句及简短原因；合法变体、识别不确定、缺少语境或教学事实存疑时标待核对，不强行纠错。一次观察不写“总是”；重复需不同有效来源。
- **支持与行动：**仅在证据支持时描述已发生的提示和支持；独立 / 依赖帮助不能从缺少提示记录倒推。优先 1～2 条与观察直接对应的练习，给例句 / 场景 / 下次可观察的目标；证据不足时提供明确标注的探索建议，不生成虚构弱项。
- **与发音融合：**文本模型可以结合 AUD-03 已核验的结构化声学结果解释问题和组织建议，不得自行编造发音诊断。词汇 / 语法建议与声母 / 韵母 / 声调建议分开说明依据；重复问题需要不同可靠音频来源。
- **限制：**不把任一报告转写为整体 HSK、正式考试成绩、长期 mastered 或学生 A/B/C/D；不把一次 ASR 正确 / 错误判作发音。原 attempted-only 学习记录不被修改。

### AUD-01：腾讯新版自然对话发音能力验证（P0，必须提前执行）

- 用户已确认腾讯云智聆口语评测（新版）选型。从自然对话中实际说出的中文入手，验证该已选服务对**自由说话**的适用性、输入要求与真实输出。分别检查声母 / 韵母清晰度、声调（包括语境变调）及语流中的停顿 / 节奏；每个维度记录可测范围、不支持项、置信度 / 质量门和供应商 / 模型版本。
- 不能预设现有 Doubao 全双工或 MiniMax 文本接口具备发音诊断能力。若候选服务只支持按已知文本朗读，不能直接把自然对话 ASR 转写当作正确参考答案：要验证参考文本确认、对齐和自由说话评测路径。额外目标词跟读可以作补充，不能替代对本次自然对话发音的核心分析。
- 用授权的作者 / 测试者语音和中文语音专业标注，比较正确发音、真实发音问题、ASR 听错但声音正确、口音 / 合法变体、变调、短答、长答、噪声及多人 / Kai 回声。转写一致或模型声称“听懂”均不算评测通过。
- 产物：腾讯能力实验与接入约束、支持矩阵、接口 / 数据 / 延迟 / 成本 / 删除边界和失败记录；在独立盲测前冻结核心维度及通过线。若已选方案不能满足核心要求，记录实际缺口并继续解决 / 提出明确选型调整，不以文档推断全部能力已具备，不标 feature 完成，不默默把发音改成可选项。

### AUD-02：音频采集、归属、分段与对齐（P0）

- 与 DR-03 同期实现学生侧有效语音采集和经授权的服务端记录。覆盖整场有效学生表达，不仅记录固定目标词或规则命中句；有界分段与总容量 / 缺口可见。只保存评测所必需的学生语音，环境静音、无关背景、Kai 输出声音及混合声不能冒充干净的学生样本。
- 基于实际音频帧 / 采样计数与已验证的会话和事件关系建立来源；验证 VAD / 分段、重叠、输入尚未结束、final 晚到 / 重识别、回声和重连。需要词级定位时使用经验证的对齐能力；无法可靠定位或确认说话人则降级，不杜撰 provider 时间戳 / 保证。
- 每片段关联文字及其版本、发音评测目标是否已确认、可评范围、质量与对齐置信度。文本误识别和音频发音错误是不同候选问题；无法区分时请核对原音，不强行归责学生。
- 音频和文本共同封口、固定 hash / 版本，经有界队列持久化；断线、撤回、删除、超限及 flush 失败都保留精确缺口。单独控制音频访问与 TTL，不进源码、常规日志或默认导出。验证采音 / 分段不会改变全双工、打断与原语音延迟。

### AUD-03：真实发音评测与教学反馈（P0）

- 实现独立 `AudioAssessmentPort`，输入获准且质量合格的学生音频、已确认或明确不确定的文本参考、语言 / 任务及来源；输出维度、具体词 / 音节 / 时间区间、可验证的声学问题或本次可评片段表现、置信度、适用范围与未评原因。元数据绑定音频 hash、对齐 / 参考版本和评测版本。
- 提交后异步评测，按实际能力分段 / 聚合；有预算、并发限制、取消、失败、幂等重试及权限 / 删除代次屏障。结果只回自己的提交；音频不可用不阻塞已确认提交，也不制造评测成功。
- 报告交付具体且可教的内容：哪个词或音节、观察到了什么、引用哪段声音、标准发音 / 拼音或必要示范、优先 1～2 个练习点与重说方法。没有可靠错误时给“本次可评片段未检测到该问题”及覆盖范围，不强行找错或宣称整场完美。
- 声母 / 韵母、声调和语流逐维准入。噪声、口音差异、对齐不稳、说话人不明、转写疑错和缺音频时分别标待核对 / 未评估；供应商分数不能未经校准就成为学生等级、百分制或长期能力标签。诊断到口型 / 舌位的映射需专业验证。

### AUD-03-TX01：接入腾讯云智聆口语评测新版（P0，明确实施任务）

- 自由说与句子 / 声调能力分别映射；确认参考文本 / 对齐后才用于局部声学诊断，不用 ASR 文本误差制造发音问题。无效 / 空值、未配置、服务未开通、鉴权 / 配额 / 频率、超时、取消、格式 / 超长音频、丢连接与部分结果均给明确状态。

- 完成条件：合成协议与故障检查通过；作者测试音频经**真实腾讯 API**获得实际结果；普通新入口的浏览器采音 → M4 保存 / 明确提交 → 独立 Worker → 腾讯 → M4 报告链路通过。专业准确性仍另需 AUD-04。未配账号 / 服务 / 密钥或未实际外呼时，本任务不得标完成。

### AUD-04：发音准确性与教学验收（P0，整体完成门）

- 建立与开发样本分离的真实声音 holdout，包含至少三主题及不同水平 / 口音、正确 / 错误 / 自我修正、变调、短词与长句、噪声 / 回声 / 多人、ASR 错但音准、拒绝 / 无有效样本、原音删除与跨提交注入。由中文发音专业人员标注声音和可教的问题，不能把 TTS 生成的“错误字”直接当作已标注的真实发音错误。
- 逐维报告误报 / 漏报、定位与参考文本错误、合法发音被误纠、可评价覆盖率、置信度降级、建议正确性、耗时 / token 或服务用量及全部失败。阈值由产品 / 语音专业评审在 holdout 前冻结，保留分母与 unknown；高覆盖不能抵消错误诊断。
- 分开验证声学服务本身、真实浏览器学生采音到报告全链路，以及真人设备 / 听感与专业教学评审。synthetic 数据仅验证工程和故障，不证明声音诊断准确。正常且获准、音频合格的对话必须实际产出可定位的发音反馈或有声学证据支持的表现描述，不能整页只有未评估。
- 放行前确认有权限的师生可按证据回听相关学生片段，标准示范与原音区分，删除后不能通过链接 / 缓存重新取得。错误说话人诊断、伪造音频来源、无声学依据的具体纠错或权限泄露为硬阻断。

### DR-07：模型结果与来源校验（对应 TA-15）

- 对文本与音频输出先做严格 schema / 字段 / 数量 / 长度 / 状态校验；音频诊断需核验音频 hash、说话人 / 时间范围、对齐和参考版本、质量 / 置信度与实际准入维度。核验所有引用属于同一授权提交、同一快照，引用范围实际存在且角色 / 轮次 / 状态正确，能定位到原文。拒绝伪造、错角色、旧版本、跨 learner、无依据示范 / 播放 / 支持或被打断内容冒充完整回应。
- **来源匹配只证明引用存在，不证明解读正确。** 为错误诊断和结论提供语义校验 / 可复核机制与独立教学评估；存在歧义或质量门未通过时保持候选 / 待核对或未评估。不能只让模型给自己打高置信度就放行。
- 本 feature 要替换当前仅允许 `validateReport` 与固定规则结果完全相等的发布策略：保留现有规则分析器兼容，按分析器版本进入各自校验器。新模型不能绕过 source fence、epoch、学生字段白名单或 grade=null；不得因更换模型悄悄重算历史报告。
- 不输出私人安全披露、无授权画像、系统提示、原始模型返回、第三方学生片段；异常不回显完整文本。来源不全或验证失败时，结果不发布；显示原因类别并允许在来源仍可用时重试。
- 验收：注入伪造引用、错角色、跨会话、无关原文拼接、否定 / 引语、模型提示注入、危险 / 隐私内容、部分失败、旧 job 和权限变更；逐一断言拒绝、降级或待核对。

### DR-08：报告、文本查看与任务体验（对应 TA-15 / TA-16）

- 学生：主题与本次表现、理解观察、表达亮点 / 一个可核对的再练点、具体发音表现 / 优先练习点、可回听证据、文字与发音练习建议；按维度展示覆盖、待核对或未评原因；措辞友好，必要时给自己的短原句例子。不得出现教师专属等级、内部备注、未授权数据或把候选当定论。
- 教师：按维度查看事实、推断与待核对；可展开最小文本证据及上下文、对应目标、实际支持是否已确认、文本 / 音频覆盖、声学质量与对齐限制、版本和下一步教学建议。角色认证通过后按本次已授权关系查看相关完整对话文本，不默认公开给其他教师或学生。
- 对话文字查看应标识学生 ASR 文本 / Kai 已转发文字、取消 / 中断 / 缺口；字幕或文本转发并不证明已听到。明确完成 / 分析中 / 证据不足 / 失败 / 已过期、重试与文本已删除的状态；报告保留策略与文本策略须一致。
- 配合现有 UI 的明确结束 / 提交与响应丢失查询。展示延迟实测，不能以 loading 无限转圈冒充处理中；低覆盖或质量校验失败时呈现诚实的部分结果或失败，不显示虚构的完整报告。

### DR-09：分层验证与放行（对应 TA-18 / TA-19 / TA-20 的非等级部分）

- **合成 / 契约**：作者编写至少 3 个主题（点餐、昆虫描述、叙事或指定句式），涵盖不同水平、长短回答、同义改述、6 轮以后、反例 / 错误 / 修正、错角色、字幕 / 帮助、ASR 错误与中断、未授权、删除竞态。文本 / 报告 source fence 和双端权限逐项断言，运行 `npm run verify`、`npm run replay` 和受影响的教师浏览器 / FreeTalk 隔离检查。
- **真实文本模型**：在经配置、可外呼的独立试验环境，先用作者虚构文本，不上传真实学习者音频 / 逐字稿。记录全部尝试、失败、模型 / prompt / 数据版本、窗口数、实际耗时 / token、来源错误和不可评项；对照固定规则基线，看模型是否带来更多有用且可核对的分析，而不只增加字数。若受网络 / 密钥 / 配额限制，标未执行。
- **教学盲审**：建议至少 36 个独立案例，其中至少 12 个冻结 holdout、不用于调 prompt；覆盖上述三主题及足够的反例，每案固定输入与目标。独立教师或中文教研人员先标观察与依据，再盲审模型；分项记录引用可追溯率、事实 / 角色错误、语法纠错正确率、建议有用性、证据不足处理、可评价覆盖率与人模型分歧；明确分母和 unknown。通过线由产品与教研在运行 holdout 前冻结，不能事后挑选；严重虚构事实、跨学生泄露、错误发音诊断、安全 / 权限违规为硬阻断。
- **真实 provider / 浏览器与真人设备**：分别记录真实豆包经新入口的实际转写 / 回复、浏览器采音与播放 / 提交 / 报告、以及真人麦克风 / 听感 / 教学走查；独立于合成回放和真实文本模型。真实试验须使用获准或作者测试材料，不能把模拟播放回执称作真人已听到。
- **发音完成门**：AUD-04 是整体 feature 完成的必需条件，文本语义通过只算阶段成果；单个低质量样本可以未评估，产品缺少发音评测不能用统一占位放行。
- **等级边界**：本任务交付描述性报告的质量，不完成 TA-20 自动评级；对缺少证据的维度保留 unknown，grade=null，学生页面没有等级。

## 5. 完成定义

一个新主题作业的正常对话，在明确用途和相应授权下，保存从开场到结束的实际可用学生文本、Kai 回复，以及完成本次发音评测所需的学生语音片段，并明确任何缺口。提交后，上下文模型与经过验证的音频评测路径共同生成可追溯的**情境理解、口语表达、发音 / 声调 / 语流分析和练习建议**。有权限的师生能定位相关文本和原音，区分观察、诊断候选及不确定性；失败、删除、撤回和迟到均有正确状态。

**M4-02、DR-01～10、AUD-01～04 与 AUD-03-TX01 均为本 feature 的必要交付。** 文本闭环可以先完成并单独试用，但只算阶段成果；没有自然对话发音评测，或仅放“未评估”字段，均不能宣布“对话报告深入分析 feature”完成。个案确因未授权、质量不足或没有可评声音而未评估是正常结果，必须说明具体原因；不能因此把发音核心能力从范围中移除。自动 A/B/C/D 仍按 TA-20 单独准入，不是本 feature 的完成条件。
