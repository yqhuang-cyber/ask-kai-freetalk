# P0 Task 02 — 慢速与语速选择

2026-10-09。工程实现完成，真实供应商听感与停顿效果待本地试听。

## 会话行为

已审核的 Seeduplex `1.2.6.1` 会话默认使用慢速。Web 首页“Kai 的语速”可在开始前选择；创建到结束期间锁定，结束后可为下一次会话切换。不在播放中发额外 `session.update`，避免与取消／教学上下文 ACK 竞争。

| 档位 | `session.audio.output.speed` | 说明 |
| --- | --- | --- |
| 慢速（默认） | -20 | 首个产品候选值，真人试听后可校准；不是已经验证的最佳语速 |
| 正常 | 0 | 显式使用供应商默认语速 |

参数依据用户提供的《豆包语音：端到端实时语音》PDF（2026-10-04 提供），`session.create` 的 `session.audio.output.speed`：数值，默认 0，范围 [-50,100]，值越大语速越快。[对应官方文档](https://docs.volcengine.com/docs/DoubaoVoice/endtoend-realtime-voice-full-duplex-version?lang=zh)。网页本次读取只返回 JavaScript 提示，因此以附件中的协议为实现依据，仍需真实账号确认效果。

服务端复制审核配置，为每个会话写入预设值；不会修改共享源配置。Web 会话中的选择会覆盖该配置原有的 speed；没有传入档位的独立适配器调用保留配置值。模板显式设 -20，所有协议／ACK 审核开关仍默认关闭。无效、非数值或越界 speed 会阻止专用适配器启动。

继续使用 16kHz 输入、24kHz 输出、16bit PCM 和原播放速率；不通过修改采样率或浏览器 playbackRate 实现慢速。麦克风持续上传、回复归属、迟到隔离、打断与 ACK 规则保持原有机制。

教学指令增加版本化 `kai-speech-v1` 风格：清楚自然、短句／意群边界停顿、不拖长单字、不朗读设置。初始提示和后续教学／记忆更新均保留该指令。停顿是模型风格指导，不保证具体毫秒；学生停顿和误打断另属 Task 03，播放同步字幕属 Task 06。

## 接口与诊断

- `GET /api/speech-paces` 返回服务配置支持情况、默认档和选项，不代表供应商已经连接。默认预览和未审核语速字段的通用适配器显示不可选。
- 已授权 `POST /api/sessions` 可附加 `speech_pace: "slow" | "normal"`；专用协议省略时默认 slow。任意原始 speed、未知档位、身份注入仍被拒绝；不支持的协议拒绝显式请求档位。
- 档位绑定单次票据，传给实际创建的适配器和教学会话。WebSocket `session.config.speech` 返回本次适配器配置，Web 展示本次档位。
- 在 `/?diagnostics=1` 导出的 `session.config` 中记录 `speech_pace`、`speech_pace_supported`、`output_speed`、`speed_explicit`。只有白名单枚举／布尔／数值，不记录文本、录音或密钥。这是配置证据，不是供应商速度回执或听感验收。

## 本地试听

1. 沿用 README 的本地豆包密钥与协议审核；独立 POC 自动启动 mock HSKai 并签发身份，无需外部 HSKai 配置或 iOS SDK。
2. 打开 `http://127.0.0.1:4310/?diagnostics=1`，选择 E01，使用默认慢速完成短会话并导出；结束后选择正常档，用相同场景和设备再测。
3. 听是否清楚自然、有没有拖字和不自然停顿；再测 E06 真正插话、E08 长回复，观察取消和字幕积压。慢速不能代替回复缩短或字幕同步，后续 03–06 继续处理。
4. 对比报告中的档位、speed、回复字符数、收到的 PCM 时长和队列；字数／时长不能直接证明语速或教学体验合格。耳机和扬声器分别试听，不将真实报告或语音提交仓库。

语言规则“先中文、再英文”已明确纳入 P0 Task 04（双语共用长度预算）、06（字幕顺序）、09–10（内容和真人验收）；本任务没有提前改语言生成规则。

## 验证边界

`npm run verify`、`npm run replay` 和 `npm run test:browser` 检查配置、范围、并发隔离、票据到实际 session.create 的链路、教学更新保留风格、诊断导出以及 Web 默认／切换／锁定。浏览器音频输入和供应商 peer 均为明确标记的 synthetic，不能证明真实豆包已生效或真人听感达标。

本次工程验证：97 项自动测试和 3 个合成回放通过；Chromium 153 的 Web 选择、会话锁定、实际请求参数、诊断导出、移动宽度与原生音频链路检查通过。未调用真实豆包账号。
