# 中泰口头告别后未立即挂断：诊断

2026-10-29。按用户要求只查看原因，本轮没有修改产品结束规则、页面处理或运行服务。

后续按用户要求已完成[中泰页面最小修复](2026-10-29-thai-closing-fix.md)；下文保留修复前诊断和复现记录。

## 原因

**中泰页面监听了错误的结束状态事件名称。**

- `apps/realtime-gateway/src/closing-coordinator.js:14` 发出 `session.closing`，包括准备总结、正在告别、等待播放完成和保存小结等阶段。
- `apps/free-talk-thai/public/web.js:71` 却只处理 `closing.state`。真实结束状态到达页面后被忽略，没有传入 `ClosingPlayback.update()`。
- `ClosingPlayback` 需要同时知道本次结束标识、所属回复、总结版本与播放状态，才发送 `closing.playback` 回执。中泰页面没有传入状态，因此字幕和音频即便完成，也不会发送该回执。
- 服务端无法按播放确认及时结束，只能走 `ClosingCoordinator.expire()` 的兜底。默认等待播放确认超时为 35 秒，从告别回复数据完成开始计，不是从实际播放完开始计。不能因此断言永远不会挂断；若用户实际超过该超时仍不挂断，还需单独核对那次会话是否进入结束状态或被新输入取消。

原中英页面正确处理 `session.closing`。检查 `cab1354` 的中泰页面，错误名称已存在，未由此次字幕计时或 Dao 画像调整引入。原中泰页面浏览器检查只覆盖按钮结束，遗漏了口头告别后的播放确认挂断。

## 复现

通过未修改的中泰真实页面和当前独立字幕组件，注入合成“再见”ASR 与中泰告别文字、500 ms 静音 PCM。页面就绪依赖在测试器中显式替换，产品真实就绪规则未改。只把临时测试宿主的播放回执超时缩短到 1,600 ms。

- 服务端在约 392 ms 发出 `session.closing / awaiting_playback`，确认已进入结束流程。
- 约 1,078 ms 已出现完整告别字幕，连接仍保持；客户端 `closing.playback` 数量为 **0**。
- 约 1,985 ms 超时进入保存阶段，约 1,988 ms 收到会话关闭；说明最终靠测试超时兜底结束。
- 页面错误 0。对照原中英的 `npm run test:browser:closing`：所属播放回执、暂停不误关、自动关闭、小结读回与麦克风释放全部通过。

这是合成浏览器复现，**没有真实供应商、真人麦克风或用户会话录音验证**；不能据此还原用户那次实际 ASR 或其等待时长。

## 最小修复位置

只需让中泰页面处理现有 `session.closing` 并把状态传给已有播放回执组件，同时补中泰口头结束、插话取消、暂停和旧回执隔离的页面回归。无需为此改变再见识别规则、profile 或原中英流程。本轮未执行该修复。

复现脚本：`scripts/thai-support-spike/closing-diagnostic.js`。它刻意断言当前回执缺失，修复后应改为成功回归，而不能继续当作正常自动结束测试。[安全汇总](2026-10-29-thai-closing-diagnostic.json)只含状态、计数和时间，不含原始供应商报文或真实学习者数据。
