# VS-01 第三阶段：归属诊断、能力收窄与批次回传

2026-10-26。**本轮推进了工具能力及批次协议验证；输入归属仍未核验，普通 Agent 未接入。** 新增内容不依赖文本生成后再合成，仍使用豆包原生全双工 S2S。

## 1. 关键结果

| 项目 | 实际观察 | 结论边界 |
| --- | --- | --- |
| FC 字段及编号关系 | 两个真实多轮连接共四次调用，只有 type／event_id／items 和 name／arguments／call_id；event_id 未匹配上行编号，call_id 不等于或包含已知输入编号 | 没发现遗漏的直接关联字段；不能用编号格式猜话轮 |
| 查询输入上下文 | 一个真实两轮连接、两次 retrieve，返回已知输入记录，字段为 id／role／timestamp／content，无 call_id 或父调用 | 能确认输入存在，不能据此确认 FC 属于该输入 |
| 原 23 条自然意图回归 | 收窄能力后，23 条均就绪并正常关闭；12 条回看到预期模拟页，11 条反例均无工具调用／无切页 | 结构通过；文字审阅另列，不是全体验验收 |
| 同批独立查询 | 一次真实连接中返回两个不同的只读调用；宿主用一个消息回传两项原 call_id 结果，随后正常回复 | 证明本次原生多项批次与聚合回传可工作；工具仅用于诊断 |
| 同名连续相对调用 | 两次尝试均只返回一项，未得到期望的同批两次 previous | 未执行，不计作批次成功；不等于供应商不支持所有同名多调用 |
| 会中收窄能力 | 在原结果及对应回复完成后更新工具／指令、取得 ACK；三次均在第 1 页接住第 3 页请求并正确暂缓，无额外调用或切页 | 只覆盖这条预排作者时序，不证明任意全双工插话时序 |

当前可确认的进展是：**后续页误调用有了可验证的能力约束方向，同批多项回传有了真实证据。输入归属没有通过。**

## 2. 实施变化

新增 slidesReviewTools，从宿主已确认页和历史编译本次可用能力。没有更早可回看目标时，不注册导航工具；其他页只提供实际有用的 previous／recent，并收窄 goto 最大页码。模型仍负责语义理解，宿主仍在派发前校验授权、实际页和历史；工具声明不能替代执行校验。当前只用于隔离 probe，未接普通 Provider／Gateway。

第 1 页的明确后续页请求直接暂缓；当前页请求直接说明已经在该页；没有更早历史则如实说明。补充“继续讲”仅继续当前交流的规则，避免套用后续页暂缓话术。没有通过 ASR 关键词补执行。

批次 probe 最多支持两项诊断调用，整批校验通过后才执行，逐项结果绑定原 call_id 后一次回传；不合法第二项或重复 call_id 使整批不执行。只读诊断工具不进入普通 Agent 的工具集合。缺 final、FC 早于 final、迟到调用晚于新输入的确定性隔离均补了 synthetic 测试，不能写成已获得真实供应商顺序保证。

## 3. 失败、修正与样本分母

本阶段共 **62 次真实连接尝试，40 次 ready，22 次 ready 前失败**。各版本、分组、源文件哈希与有限结构见[去敏汇总](2026-10-26-voice-slides-control-stage3.json)。不是 62 次全通过，也不是同一最终版本上的统一评测。

- 首次增加整数 enum 的能力变体中，22 条在 ready 前出现 error，第 1 页无导航工具的一条正常完成。移除该枚举、保留已核验的范围约束后恢复。该观察不构成所有整数枚举均不受支持的供应商保证。实验入口已改为 ready 前失败即停止整批，避免重复扩散配置问题。
- 同名连续 previous 批次两次只生成一项，实验严格停止，页面未应用。随后以两个独立只读查询验证多项批次成功。不能把只读协议成功换算成两次真实 UI 动作成功。
- 23 条回归中的“继续讲”虽无操作，但文字曾不必要地转成后续页暂缓；修正提示后独立复测正常继续当前交流。另对合法上一页、明确后续页做了最终提示版本的针对性复测。原 23 条的源版本保留，不追溯改成最终提示版本全套通过。
- **在原工具结果返回前更新配置**的两次实验均取得 ACK 且没有多余切页，但模型对明确页码继续追问，并承诺帮助切过去，不满足语义要求。移到原结果及文本／音频回复完成边界后，三次复验均正确暂缓。这支持采用安全边界的方向，仍不是配置 ACK 必然保证语义遵守的证明。

原 23 条作者文本的标准化 ASR 完全匹配为 14 条；数字写法和同音字等差异另有记录。不能将不完全匹配直接等同于 S2S 意图失败。回复文字由本助手审阅，独立 Judge 调用与真人听感验收均为零；没有自动把 semantics_accepted 设为 true。

## 4. 验证与剩余条件

| 层 | 本轮结果 |
| --- | --- |
| synthetic／合同 | 完整 verify 568 项通过，含 14 项协调器、14 项单输入／能力／批次、10 项生命周期测试；normal／interruption／failure 三条 replay 符合预期终态 |
| 真实 provider | 上述 62 次尝试逐组保留；所有页面历史及执行均为 synthetic，不是实际浏览器回执 |
| 浏览器／设备 | 本轮未新增；没有真实豆包＋浏览器联调、浏览器音频或真人设备验收；第一阶段独立组件检查不替代这些项目 |

输入归属仍是阻止普通接入的必要条件：调用可能迟到，旧轮未完成时新输入也能产生调用。原 call_id 配对解决的是“结果属于哪个调用”，不是“调用属于哪个学习者输入”。reply question_id、页面 revision、应用 action_id 均不能自动替代这项来源证据。

已经排查实际字段、event_id 回带、call_id 与输入编号关系、输入上下文查询，均没有得到可用关联。现有公开协议也未明确给出重叠输入下的 FC 归属或独占生命周期保证。下一项具体依赖是供应商确认关联字段、结束／取消顺序或受支持的替代关联方案；已整理成[可转发的问题清单](../voice-slides-control-provider-questions.md)，尚未发送给第三方。

VS-04／05 继续等待这项确认；不能把本轮能力收窄、工具结果回传或良好的单样本表现，当作已解决任意迟到调用。实验代码、模块和文档均未提交／推送，普通 Agent 的工具拒绝策略保持原状。
