# 课件回看控制：VS-01～03 阶段结果

日期：2026-10-25。对应 [PRD](../prd/voice-slides-control-prd-v1.md)、[实施清单](../voice-slides-control-tasking.md)。结果元数据见 [JSON 汇总](2026-10-25-voice-slides-control-stage1.json)。

## 1. 结论和当前状态

**独立原生实验、执行协调器和被动展示组件已实现；普通 Agent 尚未接入，VS-01 准入未通过。**

真实豆包能在作者样本中识别回看并调用工具，也能在多个后续页请求中自然暂缓；工具等待时持续采音正常。实际发现的限制是：FC 事件没有输入／回复关联字段；在等待工具时插入新输入，发送取消后没有观察到取消 ACK，却产生了第二个 FC。不能将新调用直接归到“最近输入”并执行，也不能擅自回传旧结果。

因此没有修改普通 provider 对工具的拒绝，没有连接生产 Gateway／教学链路，没有开启新功能开关。按实施清单的前置要求，VS-04／05 接入等待归属和取消路径解决；没有改为 ASR 规则识别、文本生成后 TTS，或要求用户手动确认翻页来替代目标功能。

## 3. 真实供应商：单输入两轮实验

两轮均使用相同的 23 条固定作者文本，通过本机 Tingting 生成 PCM，原生 S2S 持续按 20ms 上送。每条单独连接；初始展示历史和执行回执是 **synthetic**，没有真人录音或真实学习者资料。工具结果等待约 1.2 秒后回传。

| 指标 | V1 | V2 |
| --- | --- | --- |
| 真实 ready／正常关闭 ACK | 23／23 | 23／23 |
| 12 条有效回看：调用并到达预期模拟目标 | 12／12 | 12／12 |
| 11 条不应改变页面的样本：页面保持 | 11／11 | 11／11 |
| 不应调用却发生调用 | 1：回退后请求曾展示的第 3 页 | 1：同一反例，宿主拒绝 |
| 有工具样本在结果前观察到文本／音频 | 0／13 | 0／13 |
| 完整结构条件符合预期 | 22／23 | 22／23 |

“结构条件”检查调用／目标／顺序及结束，**不是语义通过率**。ASR 的严格字面匹配与意图行为分开记录；部分转写存在数字写法差异，也有明显同音误识别，不能将字面不匹配一概当作正常。此处只检验固定作者音频下的实际工具和回复行为，没有证明真实学习者泛化能力。

部分“刚才那页”表达选择了 previous，而非 recent；在本批连续页历史中目标相同，因此按实际目标记录结构结果。跳过某页的历史与更复杂近指歧义尚未做真实实验，不能据此宣称 recent 的历史定位已全面通过。

V1 的两处文本问题是：已在最后一页仍说稍后会学到，以及将“下一页用英语怎么说”当成提前查看。V2 调整了语义优先级和明确当前／末页状态，定向重测与完整复测均分别回应“只有三页，没有下一页”和 `next page`。没有改变作者输入或期待结果。

V2 剩余反例仍发出 `goto(3)`，宿主拒绝后，模型给出暂缓回应，没有向后跳页。不过这仍违反“正常暂缓分支不调用工具”，保留为未通过项；其“还没学到”的解释也不能当成真实课程进度事实。

以上内容检查由本助手审阅作者样本的回复文字与工具结果，独立 Judge 调用为 0，人工听感验收为 0。没有将 `semantics_accepted` 自动标为 true。

## 4. 真实供应商：多轮及打断

| 实验 | 实际观察 | 能证明什么／仍缺什么 |
| --- | --- | --- |
| sequential | 同一连接两段作者输入，模拟页 3→2→1；两个工具结果，回复归属于各自输入；等待中无观察到的输出；关闭有 ACK | 观察到顺序场景可工作；FC 本身仍无输入身份，不能外推任意并发归属 |
| interrupt-cancel | 第一个 FC 等待中注入第二段作者音频；新输入首字识别时发 response.cancel；第二个 final 和 FC 到达；有界等待内没有 response.canceled | 两个动作均未执行、旧结果未回传，最终关闭有 ACK；取消及旧工具终态仍未核验 |
| close-waiting | FC 尚未回传时发送 session.close，收到关闭 ACK | 已核验该有限场景可关闭隔离；这不是保持原会话连续交流的解决方案 |

实际 FC 没有直接可用的 question／response／input 身份，不能把 call_id 当 turn_id。现阶段探针仅使用事先保留的单输入实验槽；生命周期实验中的顺序只是观察，不增加生产归属保证。

`interrupt-cancel-result` 的诊断分支已用合成测试验证；真实 cancel 未 ACK，因此没有执行该分支、没有把旧取消结果回填新话轮。未测试并行批次的真实行为、长期连接、同一真实页面＋豆包端到端或真人设备音频。

## 5. Synthetic／合同回归

- 最终 `npm run verify`：550／550，通过语法、JSON、合同和现有回归；本功能新增 20 项。
- `npm run replay`：normal、interruption、failure 三个 synthetic replay 均保持预期结果；failure 场景按设计进入 failed。
- 覆盖了重复／冲突请求、两次 previous 串行、recent 不漂移、派发前后续页复核、队列到期／容量、未知冻结、快照屏障、迟到恢复、外国会话／旧代次拒绝和结束清理。

受限执行环境的一次完整回归因禁止本机监听端口失败；允许测试所需的临时本机服务后，完整回归通过。该环境失败没有计入产品成功或真实供应商分母。

## 6. 浏览器组件检查

通过真实 IAB、独立 synthetic 宿主和组件完成：

1. 初始第 1 页、演示标识、无历史时禁用回看。
2. 测试宿主依次展示后，手动从第 3 页回看第 2 页。
3. 历史选择器回到第 1 页，之后只提供当前／更早允许目标。
4. 重发同一命令不再渲染或增加宿主 revision。
5. 伪造向第 3 页请求被拒绝，页面不变。
6. 丢失 ACK 后，通过同一有序通道的快照屏障核对成功，没有重复回退。
7. 暂停 ACK 和核对后进入 unknown，操作禁用，不能报告原页不变。
8. 释放迟到快照后恢复真实页及 revision，不重执行，也不再次结算旧结果。

这是手动自动化操作的组件检查，没有接真实豆包、麦克风或播放链路，不代表普通页面端到端或浏览器音频验收。截图只留本地忽略目录。

## 7. 下一步

后续方案已明确将应用动作与语音确认分开：先补验“不主动取消已接受工具”的插话路径，而非继续默认在新输入首字即取消。既有缺 ACK 仅说明该诊断路径未通过，不证明所有正常接入路径都依赖此 ACK。规则和待做实验见[技术方案 §5.6](../voice-slides-control-design.md#56-插话的实现顺序与下一轮原生实验)。此补充不更改上述实验结果或增加通过数。

先解决 VS-01 的归属和取消终态：需要供应商明确 FC 与输入／回复的关联方式，以及新输入、response.cancel 与旧工具批次的关系；或获得可验证、不会将旧调用归入新输入的独占生命周期控制。不能凭有限时序样本宣称协议保证。

同时可继续在隔离实验中收紧后续页工具能力与描述，验证 remaining goto 误调用。达到准入要求后，才进行 VS-04／05 的普通 Provider／Gateway 接入；随后补完整快照、教学证据隔离、调速／收尾协作和真实浏览器语音验收。当前不标记整项 feature 完成。
