# 课件回看：第六阶段普通页面自动化与复杂联调

日期：2026-10-26。范围：用户指定的“普通页面自动化＋复杂场景联调”。**这两项工程验证已完成；功能默认关闭，完整产品质量和真人设备验收仍未完成。** 本报告接续[第五阶段](2026-10-26-voice-slides-control-stage5.md)，不改写此前阶段的失败和分母。机器可读汇总及代码 SHA-256 见[同名 JSON](2026-10-26-voice-slides-control-stage6.json)。

## 本轮结论与修复

普通 HTML／web.js 在真实 IAB 中的 12 个共享自动化场景全部通过，包含真实组件回执与浏览器播放链路；语音供应商与 Planner 是明确标注的合成依赖。另用真实豆包经普通 Gateway／Provider 验证了两种插话：普通问题保留原页面动作，明确追加累计回看。最终两次真实运行中，第二输入都先于原页面回执，旧回复文字和音频转发数均为 0。

发现并修复三处运行行为：

1. **旧确认第一次才迟到**：原回看已接受、学生先说了新问题，而旧轮回复随后才开始，原实现仍可能转发旧确认。现在启用课件控制时，按实际原生语音输入／回复身份本地丢弃旧回复，保留页面事务，不发无目标的原生取消，不清除当前计划。
2. **丢弃回复的音频稍后开始**：文字优先的旧回复已被丢弃，其匿名音频后来才到。保留该未完成旧回复的 lane 专门丢弃，不把音频归到新回复；若两个未完成 lane 重叠则安全失败。已完成旧 ID 的重复开始继续忽略。
3. **等待中的队列状态没有及时发布**：第二个动作已排队但页面仍看到 queued=0。现在入队后立即发布 pending／queued，实际执行仍串行。

这里加强的是语音输出隔离和应用执行状态，不代表取得了供应商 FC 的原生输入身份。页面动作仍归属于授权会话／call／可撤销权限代次；同一有效代次中缺失的原始语音顺序不能凭宿主收到顺序补造。

## 普通页面的 12 个场景

| 场景 | 实际检查 |
| --- | --- |
| 手动与语音共用状态 | 手动 3→2，再语音 2→1；允许目标只剩当前页，音频输入持续 |
| 明确追加 | 两次独立回看排队，pending／queued 可见，按 3→2→1 应用 |
| 明确撤销 | 取消未派发项；已派发项继续到 2，不回滚 |
| 明确改口 | 替换未派发项；原已派发项先到 2，再到修正的第 1 页 |
| 迟到旧确认 | 旧页面动作完成，旧轮首次迟到的文字／音频不展示，新轮回应显示，无原生取消 |
| 调速＋回看 | 放慢与回看完成；浏览器 PCM／字幕确认与完整 page／speed／tools 配置一致 |
| Planner 晚到竞争 | 保持旧计划，交错手动和语音回看；释放旧／新结果后只保留最新建议，确认页和工具集合不被覆盖 |
| 丢失 ACK | 先查询组件状态再确认，不重复派发相对动作 |
| 结果持续未知 | 丢弃全部回执，5 秒后冻结；实际 DOM 已到第 2 页但宿主不宣称确认，不继续盲目回退 |
| 重连与换人 | 旧连接关闭，新授权会话重新建立作者展示历史，旧代次不串入 |
| 展示框降级 | 课件资源失败，握手超时后进入无工具普通聊天，音频输入继续 |
| 真实就绪守卫 | 使用产品真实就绪策略时，合成 ready 不开启输入，不能伪装豆包连接成功 |

这些场景的语音转写、FC 和 Planner 提案由夹具预先编排，验证给定事件下的行为；不能把 12／12 写成真实模型意图准确率。

## 可复用工具与隔离方式

所有实验仍集中在 `scripts/voice-slides-control/`，未散落到 scripts 根目录：

- `ordinary-web-host.js`：启动独立 loopback 测试宿主，复用正常授权、Gateway 和 Seeduplex 适配器；对端语音与 Planner 为 synthetic。普通 HTML／web.js 原样提供，仅隔离宿主替换音频输入与就绪策略依赖，使用持续静音输入、真实浏览器输出，不请求麦克风。
- `web-test-audio.js`／`web-test-readiness.js`：显式测试依赖。页面显示“合成联调／豆包未连接”，产品就绪策略仍只接受明确真实供应商 ready；产品服务没有合成模式入口。
- `ordinary-web-checks.js`：12 场景共享检查，接受 CUA locator facade 或 Playwright Page；页面交互通过浏览器自动化，供应商故障通过独立作者夹具控制。
- `ordinary-web-browser-check.js`：供 CI 的 Chromium 驱动与 `npm run test:browser:slides` 入口。**本轮实际执行 CUA 驱动，没有执行独立 Chromium CLI。** 驱动文件存在不等于 CI 已运行。
- `gateway-probe.js --live --interrupt-question / --interrupt-add`：普通 Gateway＋真实豆包的两种插话补验；依赖固定作者材料，不上传真实学习者录音。

测试控制端口与本地 mailbox 仅存在于隔离宿主，普通产品无测试控制路由；关闭时清理宿主自己的 mailbox。详细运行方式见[脚本说明](../../scripts/voice-slides-control/README.md)。本地忽略目录保存元数据、作者回应和截图；提交报告只含去敏汇总，不包含供应商原始 trace、密钥、真实学习者转录或音频。

## 失败与修正记录

最终通过之前保留这些实际问题，不将整个过程描述成一次全通过：

- 新增“旧回复首次迟到”测试初次失败，修复本地旧回复隔离后通过。
- 浏览器追加场景暴露 queued 未发布，修复后在最终运行时重跑完整 12 项。
- 匿名 PCM 首次修复过于严格，破坏已有“完成旧 ID 重复开始可忽略”的回归；收窄到未完成且本地丢弃的回复后，完整 624 项通过。
- 浏览器工具准备曾遇本地网络不可用，改用显式测试 mailbox；另外修复多匹配定位器、夹具把文本命令释放为二进制帧、重启后回调仍绑定旧 mailbox 路径。文本帧问题新增回归测试。这些属于测试环境／驱动问题，未当成供应商失败或产品成功。
