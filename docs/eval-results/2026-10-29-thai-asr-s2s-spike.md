# 中泰 Free Talk：前置语言识别 → 当前 S2S 验证

2026-10-29。用户授权先验证前置语言处理后继续使用现有 S2S。本轮只增加独立实验脚本、测试与报告，没有改业务页面、Agent、供应商适配器、运行配置或启动中的服务。之前工作区已有的未提交修改保留，不计入本轮实验改动。

## 结论

**现有 Seeduplex 可以在有限作者样本中理解通过初始化上下文送入的泰文，并返回回答；但“泰语语音 → 外置 ASR → 当前 S2S”完整链路尚未验证通过。**

- 独立 ASR 的 1.0、2.0 小时资源都返回 HTTP 403；安全分类为资源访问未授权。没有建立识别连接、没有上传音频，也没有获得识别结果。不能将其计为泰语识别准确率失败，更不能声称已支持泰语输入。
- 当前公开原生协议中未核实到可直接触发回答的文本用户消息入口。历史写入、指定朗读和用户提问分别测试，不混为一谈。
- 初始化 `dialog_context` → 回读确认泰文 → 固定中文语音触发：两道不同的泰文算术题均得到正确结果，返回中泰文字和非静音语音。答案未放进触发音频或占位回复。
- 同一连接内更新 `dialog_context`：收到更新 ACK，但回读未发现新问题，停止在音频触发之前。
- 同一连接内把泰文问题作为 JSON 数据更新进 `instructions`，再用固定音频触发：两轮只有 **1/2** 正确；第一轮仍表示没有收到泰文问题。不能把这个旁路视为可靠连续对话输入。

因此本轮**不将旁路接入中泰页面**。保留 S2S 值得继续研究，但仍有独立识别权限、正式文本输入契约及持续话轮可靠性三个缺口。不是仅换一个音色或加一个语言参数即可完成。

## 范围和来源

当前模型 `1.2.6.1`，协议 `seeduplex-1.2.6.1`，Vivi 2.0 `zh_female_vv_uranus_bigtts`。使用中泰专用 profile 的内存副本；文件及原中英配置保持不变。本轮只用作者固定问题和 macOS 合成音频，没有真人或学习者数据。

核对[当前 Seeduplex 接口](https://docs.volcengine.com/docs/doubao-voice/end-to-end-real-time-voice-full-duplex-version?lang=zh)、[独立 ASR 接口](https://docs.volcengine.com/docs/doubao-voice/large-model-streaming-automatic-speech-recognition-api-1?lang=en)及[其他 S2S 版本的文本接口](https://docs.volcengine.com/docs/doubao-voice/end-to-endreal-time-speech-large-model-api-access-document?lang=en)。其他版本的 `ChatTextQuery` 不移植为当前 JSON 协议事件。没有发送猜测的 `response.create` 等指令。

静态检查官方 Web、Go 示例，没有执行示例服务。Web 示例名为 `send_text()` 的方法实际调用 `speech_text_buffer.commit`，不能由该方法名认定是用户文本提问。示例下载地址与哈希见[实验说明](../../scripts/thai-support-spike/asr-s2s/README.md)。

## 真实服务结果

共 15 个原生 S2S 连接、4 次 ASR 握手拒绝，分阶段收集；后续格式对照和旁路实验在前一阶段结果后提出，未将它们冒充同一预注册实验。

| 实验 | 结果 | 能说明什么 |
| --- | --- | --- |
| 中文语音正对照：三加五 | 识别正确，回答八，299,230 字节非静音音频 | 当前语音模型和凭证正常可用 |
| 单条中文／泰文用户历史消息 | 3 次新连接，各观察 10 秒，无回答 | 此实验用法没有触发回答；单条消息超出文档完整 QA 指引，不代表所有文本入口均不可用 |
| 完整作者 QA 历史对照 | `conversation.item.added`，无回答 | 历史写入确认不等于发起新问题 |
| 指定文本朗读对照 | 109,104 字节音频；无自主回答文本 | 该接口不能充当用户问题理解的证据；没有听音频，不另行断言实际朗读内容 |
| 历史 + 固定语音触发，`input_text` | 两道题均要求重发问题 | 未成功；初次没有做历史回读，不能归因于泰文理解能力 |
| 历史 + 固定触发，`text` 格式／回读诊断 | 2 道题及 1 次字段诊断均未答出；回读用户、助手文本为空 | 写入 ACK 不证明文字实际进入上下文；格式／服务契约需供应商确认 |
| 初始化 `extension.dialog.dialog_context` + 固定触发 | 2/2 正确，回读精确匹配问题；334,574／322,642 字节音频 | 新会话中的泰文文本理解候选成立，不证明通用泰语质量或多轮稳定性 |
| 同连接动态 `dialog_context` 更新 | ACK 成功，回读不匹配，未继续触发 | 不能把初始化能力推为动态更新能力；第二题未尝试 |
| 同连接 `instructions` 数据更新 + 固定触发 | 1/2 正确；两次触发音频都被正确转写 | 有限上下文旁路不可靠，不能作为完整桥接通过 |
| ASR 2.0／1.0 及原因诊断 | 4 次均 HTTP 403；0 音频包 | 当前凭证未获这两个资源访问权；泰语、自动和混合识别没有准确率样本 |

两道泰文题分别为“三加五等于几”和“九减二等于几”，数字以泰文词表达。固定中文触发语只要求回答先前泰语问题，不含算术信息或答案。初始化占位助手回复为作者构造的“先记下问题”，不是实际模型历史；实验明确记录这个人工上下文。回答内容由 Codex 核对作者文本，**不是人工泰语审校**，不评定泰文拼写、发音、自然度或教学质量。

首次元数据摘要把历史 ACK 名误写为 `conversation.item.created`，真实计数记录的是 `conversation.item.added`。探针已按官方 Go 常量修正；公开汇总根据保留的计数复核该项，不覆盖原始实验元数据、不为摘要字段重新声称执行新连接。初版旁路的 ASR 对照字段比较的是中文触发和泰文问题，不能解释为触发语识别错误；后续按实际音频脚本独立核对。

## 分层验收

- **合成／本地检查**：`npm run verify` 866/866，新增 5 项覆盖识别二进制帧、压缩／截断／错误、Unicode 及桥接通过条件；`npm run replay` 三场景通过。原 FreeTalk 8 个保护文件哈希不变。不是供应商识别或音质验收。
- **真实供应商**：以上连接与 ACK／回读／文本／音频字节来自当前账号真实服务。ASR 被拒绝；没有独立 ASR final，完整桥接通过数为零。
- **浏览器／真人音频**：本轮未执行。没有播放队列、回声、真实插话、结束意图或真人听感验收。

所有生成音频只计字节与非静音状态，没有将到达当成用户听完，也没有将模型回复变为学习掌握证据。当前没有实施产品话轮归属或迟到隔离的新路径。
