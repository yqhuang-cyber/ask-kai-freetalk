# 自动打断确认超时排查

用户反馈：没有主动插话或点击打断，也出现「语音服务未及时确认打断，对话已中断」。截图同时有两条地址被截断的会话接口 404 和一个 favicon 404。

## 已确认的代码路径

网关接受有内容的另一话轮识别文字后，会以 `asr_confirmed` 来源自动停止旧回复的本地播放，并请求供应商取消。该路径不需要用户点击按钮，也不能仅由识别文字证明真人主动插话；普通接话、误识别或回声的来源仍需真实会话及设备观察区分。

`CANCEL_ACK_TIMEOUT` 从实际派发 cancel 起等待 1500ms。只有已绑定旧回复的取消确认才清除此计时器。排队中的取消不消耗该等待时间。

重新读取[官方全双工 API](https://docs.volcengine.com/docs/DoubaoVoice/endtoend-realtime-voice-full-duplex-version?lang=zh)：`response.done` 返回一轮用量，`response.canceled` 是取消请求确认。本文不将前者改解释为取消确认，也不使用其他产品的同名事件替代当前协议。

## 真实供应商排查

所有输入均为固定作者文本合成的语音，没有读取或上传用户录音，没有浏览器麦克风或真人听感检查。只输出事件类型、字段名、数量和时序，未保存原始供应商消息或回复文本。

| 检查 | 观察 | 结论及限制 |
| --- | --- | --- |
| 生产适配器固定 TTS 取消／恢复 | 两次配置确认正常；cancel 确认约 914ms；恢复输出和关闭正常 | 取消接口并非始终不可用；不能证明用户那次返回及时 |
| 主动播报中输入固定合成语音，两次 | 用量统计先到，随后 ASR 有内容，客户端发 cancel；25 秒内无取消确认 | 两次在输入语句后停止上传，存在持续上行方式不完整的实验限制，不单独据此判断实际浏览器行为 |
| 同一主动播报插话，持续上行 | 用量统计约 2093ms；ASR 内容及 cancel 约 2094ms；没有取消确认；约 4954ms 识别结束，约 4996ms 新回复文字，约 5148ms 新音频边界触发当前适配器协议隔离 | 复现了取消未确认、但供应商继续到新回复的事件顺序；真实 Web 的 1500ms 计时器会更早结束会话。这是同类故障复现，不是用户会话逐帧还原 |
| 普通语音问答对照首次 | 探针在首轮没有回复时错误尝试取消，未进入目标场景 | 无效实验，排除，不作为产品结论 |
| 修正后的普通语音问答对照 | 两轮识别和回复输出；第一轮在第二轮有内容识别前已正常结束，未派发 cancel | 该轮没有覆盖活动回复中的取消，不是打断通过，也不否定前面的复现 |

复现提示一个兼容性缺口：服务端可能已切换话轮，而本地仍保留未收到明确输出终止的旧回复；随后自动发出的取消没有获得确认，最终触发本地超时。不能由无归属的用量事件认定具体回复已取消，也不能直接延长等待就宣称修复。用户那次触发识别的具体声音没有观测留存，仍未确认。

## 本轮修改

- `?observe=1` 增加打断 requested／sent／ack／skipped／ignored／timeout，以及未通过归属检查的事件；显示打断来源、旧回复和话轮、实际等待时长、配置是否待确认。
- 实际语音请求观测补上 `response.cancel` body，继续排除鉴权头和音频。
- 清理准备记录改为幂等：准备被消费或过期后再次 DELETE 返回成功，不再制造清理 404；GET 缺失记录仍返回 404，授权检查保持。
- favicon 返回空的 204。

截图地址已截断，无法断言两条会话接口 404 都是准备清理：若是小结查询，服务重启后的本地内存记录丢失也可能返回 404。上述 HTTP 请求没有清除或替代语音 WebSocket 上的取消确认，不能将它们当作已证实的语音故障根因。

**本轮没有修改取消状态机、1500ms 等待时间或确认归属校验；语音兼容性问题仍开放。** 后续修复需区分本地隔离旧输出、供应商明确取消确认和明确新回复归属，并验证迟到确认／音频不会绑定到新回复；回声来源另做设备对照。
