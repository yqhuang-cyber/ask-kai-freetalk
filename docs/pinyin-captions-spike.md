# Kai 拼音字幕：需求与可行性 Spike

日期：2026-10-26。**本页记录历史隔离实验；后续普通页面首版已实现，当前状态见[实施记录](pinyin-captions-implementation.md)。** 原实验状态：**显示层方案可行，语音开关有真实豆包样本支持；本轮仅隔离实验，尚未接入普通 Agent／Web。** 机器可读结果、失败用例和代码 SHA-256 见[实验汇总](eval-results/2026-10-26-pinyin-captions-spike.json)，运行入口见[工具说明](../scripts/pinyin-captions/README.md)。

## 已确认的需求

Kai 的回复含中文时，中文字幕默认附带声调拼音，英文、数字、标点保留原样。拼音只用于字幕显示，不加入语音内容。学习者在本次对话中说“关闭拼音”可以隐藏，也应支持“重新打开拼音”；只影响本场，新会话恢复默认。关闭拼音保留中文字幕，不等于关闭字幕、停止朗读或修改学习者永久画像。

建议默认采用汉字上方的小号拼音，和渐进字幕同批出现。开关切换时重绘当前已显示的字幕及后续字幕，不显示尚未到播放时间的文字；关闭字幕时拼音一起隐藏。学生转写、词卡、小结和观测原文不自动扩大到此次功能范围。新的拼音显示不是学习掌握或发音评估。

## 技术结论

**继续使用现有原生 S2S。拼音是已归属回复文本的派生呈现，不放进语音模型生成链路。** 当前 `Presentation` 已按浏览器 PCM 播放进度逐短语揭示正文；在其 render 边界装饰中文即可。原文、音频、正文计数、播放完成与收尾判定继续使用原始正文，不把新增拼音当成更多“已说出的字”。

推荐本地转换，避免每段字幕再调一个 LLM，亦不要求豆包同时输出“中文＋拼音”。由同一个语音输出生成带拼音正文，可能让拼音进入朗读或改变回答格式；本地派生可以从架构上让注音不进入音频。未知字符或转换失败时保留原文，注音故障不能阻止播放或结束。

候选库 `pinyin-pro@3.29.5` 为 MIT；可返回每个字符的原文／读音／汉字标识，并支持带声调、词语覆盖和补充词典。[官方 pinyin 接口](https://pinyin-pro.cn/use/pinyin.html)、[自定义读音](https://pinyin-pro.cn/use/customPinyin.html)。用 DOM 文本节点创建 `ruby`／`rt`，不把回复文字拼成 innerHTML；注音可置于汉字上方。[MDN ruby](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/ruby)。

拼音标注建议首版采用词典原调，例如 `你好 → nǐ hǎo`，不宣称字幕能还原连续语流的实际变调。轻声保留无调音节。展示拼音与真实豆包发音之间可能存在多音字、姓名、儿化或变调差异；当前没有逐字声学时间戳，也没有做语音强制对齐。词典拼音不能作为“模型实际这样读了”的证据。

## 实验一：转换质量、上下文与成本

16 条作者样本覆盖中英混合、纯英文、数字、标点、换行、轻声、多音字、繁体和 HTML 字面内容。每种配置额外循环转换 1200 次，以下耗时是本机 Node 热转换，不是浏览器加载或端到端语音延迟。

| 配置 | 符合作者 oracle | 加载成本与发现 |
| --- | --- | --- |
| 基础库 | 13／16 | “还书”“还款”与繁体词语出错 |
| 加现代汉语词典 | 13／16 | 这批样本无改善；词典 JSON gzip 约 633KB |
| 加完整词典 | 14／16 | 修正“还款”，仍误标“还书”与繁体词语；词典 JSON gzip 约 3.68MB |
| 基础库＋两条审核词语覆盖 | 15／16 | 修正“还书”“还款”，繁体仍需映射 |
| 审核覆盖＋繁体映射 | 16／16 | 映射 JSON gzip 约 9.4KB；属于样本内修正，不代表开放领域准确率 |

基础完整 UMD 文件约 326KB、gzip 143KB；`dist/index.mjs` 的 33 字节只是重导出入口，不是实际库体积。完整词典本机初始化约 989ms，轻量覆盖＋繁体映射约 33ms；后者热转换 P95 约 0.052ms。不是正式打包结果、低端设备或浏览器性能承诺。补充词典包为 `@pinyin-pro/data@1.3.1`，注册表标注 ISC；正式集成需随实际分发文件保留许可。

**不要按每个刚到达的汉字独立转拼音。** 同一句“银行行长”逐字转换得到 `yín xíng xíng cháng`，带词语上下文时得到 `yín háng háng zhǎng`；“重复”“重庆”也出现同类差异。用现有短语分段器模拟逐字符到达的三个样本，按短语转换与整句一致，但这三个样本不能覆盖所有分段边界。

建议使用完整已收到的上下文生成带原文位置的注音，再只渲染当前允许显示的部分，避免把 previous／current 高亮边界当成读音断词边界。已显示字符不能因异步转换回写到新回复；转换任务需绑定 response_id／会话代次。软超时、12 单位分段、词语跨段、专名和稀有字仍需集成用例。词语覆盖必须经人工审核；这两条样本内修正不能冒充独立测试集。

## 实验二：真实豆包语音开关

注册隔离实验工具 `set_caption_pinyin({enabled:boolean})`，保持真实 S2S 输入与输出。每个作者输入单独建一个真实连接；应用执行器是 synthetic caption renderer，回传模拟应用结果后模型再说话。没有使用麦克风，没有浏览器执行或人耳试听。

| 作者输入类型 | 观察结果 |
| --- | --- |
| 关掉字幕拼音，保留中文 | 一次 enabled=false，结果前无输出 |
| 重新打开拼音 | 一次 enabled=true，结果前无输出 |
| 不要关掉拼音，继续显示 | 无工具调用 |
| 问“关闭拼音”用英文怎么说 | 无工具调用 |
| 英文要求隐藏 pinyin、保留中文 | 一次 enabled=false，结果前无输出 |
| 关闭拼音，再问“银行”的意思 | 一次 enabled=false，随后收到完整文字／音频回复 |

六次真实连接均观察到预期工具结构及开关状态；全部收到文字、音频和关闭回执。作者输入规范化转写精确匹配为 5／6，英文样本不完全一致，但开关动作正确。所有需要动作的样本都在工具结果后才输出。否定／引用样本无工具，正常直接回复，不要求等待不存在的结果。

输出文字未检测到带声调拉丁拼音；这个有限检查不能证明没有任何形式的拼音，也不能替代人耳确认没有额外朗读。这里没有保存或播放输出音频，仅计字节。混合请求只证明有后续回复，尚未做独立语义评分证明问题已充分回答。

工具回执是模拟的，不能声明已经连上真实字幕组件。此供应商 FC 仍没有可靠的原生输入身份；六个独立单输入连接不能证明连续多轮、快速开关、插话或迟到调用的归属已解决。

## 实验三：浏览器离线排版

真实 IAB 中运行独立作者示例，6 项检查通过：默认只为中文注音；关闭后原文不变；后续示例沿用关闭状态；新会话恢复默认；HTML 形状文字保持字面内容、未创建图片；重新开启及桌面布局无水平溢出。

这是单独的离线页面，不是普通 Web，也没有语音播放或实际语音控制。初次检查把九个汉字误计为十个，修正驱动预期后通过，未据此改动 UI。尚未测手机宽度、全量渐进高亮和真实音频时序。

## 接入建议与模块边界

显示和语音控制分开实施，默认注音不依赖课件开关。无需为了显示拼音而打开 Slides 或更改已有语速。

| 模块 | 后续建议改动 |
| --- | --- |
| Web 注音呈现 | 新增独立 caption annotation renderer／读音覆盖表；`web.js` 的 render 调用它，CSS 添加 ruby 样式。保留 Presentation 的正文与播放契约 |
| 当前会话显示设置 | 网关维护 `pinyin_enabled=true` 与 revision，Web 接受同代次版本并确认应用；断线重建／换人恢复新场默认，不写长期画像 |
| 语音意图控制 | 作为“字幕显示设置”独立意图，首版可复用已接受 ASR final 的明确命令路径；或用已验证可行的原生 FC 理解自然表达。不能扫描 Kai 回复文字来决定开关 |
| 模型工具适配（若选择 FC） | 新增单独受限工具家族和能力开关，与 Slides 组合验证；普通 Provider 当前仅显式允许 Slides，不能直接把新函数塞进去或放开任意工具 |
| 上下文与反馈 | 使用已确认设置编译后续上下文，结果未确认不说“已关闭”；只确认一次，混合问题继续回应。保持教学／语速／课件完整快照更新和既有收尾隔离 |

首版若只支持“关闭拼音／打开拼音”等明确指令，建议从**安全检查后、已接受的 `user.final`** 识别，复用口头调速已有输入归属，使用窄范围正反例规则；不在 partial 阶段直接改状态。它更容易处理本轮顺序，也无需新增工具家族。未支持的表达交给对话澄清，不能因含“拼音”二字就切换。

若需要自然中英表达或“关拼音再解释这个词”的更宽理解，原生 FC 已有可行性证据，可继续实验后选择。FC 路径必须保留会话／call／代次校验、幂等、ACK 和迟到隔离；当前缺少输入身份意味着不能自动承诺“最后说出的指令总能最后生效”。顺序到达不等于语音产生顺序，版本校验也不补造供应商因果归属。

共同执行闭环为：接受合法请求 → 提交本场目标设置 → 当前 Web 应用并 ACK → 确认状态 → Kai 简短反馈“好的，接下来只显示中文，不显示拼音”。如果重复关闭，保持状态并说明已关闭；新请求反转、结束或换人时隔离旧确认。显示可立即更新，不需要复刻调速的两次播报。确认语使用真实执行结果，不能只靠 prompt 自称完成。

## 下一步实施顺序

1. 固化简短 PRD：显示范围、默认规则、本场开关、恢复默认、失败反馈和注音声调策略；准备独立多音字留出集。
2. 先接 Web 注音：复用原渐进／播放链路，实测首屏加载、跨词高亮、开关后原文与播放 ACK 不变；转换失败降级原文。
3. 接本场语音开关：先选明确 ASR 指令或进一步验证 FC 自然表达；补快速开关、否定／引用、混合问题、重连换人、与调速／Slides 并用的竞争用例。
4. 执行 verify／replay、普通页面自动化、真实豆包连续多轮及真人听感，分别报告证据；通过后再启用普通页面默认注音。

本轮没有改运行模块、工程 package.json／lockfile、生产提示词或真实学习资料。仅新增隔离工具、作者用例与报告；`npm run check` 通过，未因纯 spike 重跑或沿用旧运行时通过数。实验已经证明值得实施，主要未决项是开放文本读音质量与正式会话控制的竞争处理。
