# Agent 口头调速：需求、设计、实施与移植说明

版本：1.0　日期：2026-10-25

适用读者：产品、Agent 开发、实时语音开发、客户端开发和测试人员。

本文以 Ask Kai 自由对话 POC 的当前工作区实现为基线，说明已完成的能力及其移植方法。独立产品需求见 [口头调速 PRD](prd/spoken-speech-pace-prd-v1.md)，具体任务与验证记录见 [实施任务清单](spoken-speech-pace-tasking.md)。目标项目尚未移植，当前实现也尚未封装成独立组件包。

## 1. 功能概述

学习者在语音对话中直接说“慢一点”“快一点”或“恢复正常”，Agent 就调整本场会话的说话速度，无需退出重连。

一次正常的交互是：

1. 学习者：“慢一点。”
2. Agent 先以原速度回应：“好的，我来把语速放慢一点。”
3. 第一段确认的语音和字幕播放完成后，系统更新语音配置，并等待语音服务确认。
4. Agent 用新速度回应：“已经放慢了，接下来我会说慢一点。”
5. 后续交流沿用新速度，原话题和教学目标继续保留。

这项能力把学习者的明确请求落实为有执行状态的会话设置。产品确认语、模型指令和供应商语音参数需要保持一致；其中任何一个单独变化，都不足以表示调速已经完成。

当前已完成实际 Agent、网关、供应商适配器和页面的改造。工程测试、浏览器合成音频检查，以及真实豆包上的作者合成语音请求均已通过。用户初步体验反馈较好；真人设备、回声和不同口音的系统性听感验收仍未完成。

## 2. 需求与产品取舍

### 2.1 需要解决的问题

语音老师的默认速度不一定适合学习者当下的理解需要。要求学习者退出对话后再修改设置，会打断交流；只让 Agent 口头答应，也无法确认后续语音实际采用了新速度。

学习者需要的是：在当前对话里表达要求，知道系统正在调整，并听到与实际结果一致的反馈。

### 2.2 已确定的规则

| 设计项 | 当前规则 | 原因 |
| --- | --- | --- |
| 入口 | 口头明确请求；开聊前仍可选择默认档位 | 对话中无需寻找控件 |
| 反馈 | 请求确认和执行成功确认分开 | “我来调整”与“已经调整”具有不同证据要求 |
| 生效时间 | 第一段确认播完，再更新配置；第二段确认使用新速度 | 避免播放切换截断确认语，让变化可感知 |
| 作用范围 | 本场会话持续生效 | 一次调速不自动成为长期画像 |
| 相对调整 | “慢／快一点”每次移动一档 | 支持继续微调，避免一次变化过大 |
| 恢复正常 | 回到正常档位 | 正常档独立于本次开聊时选择的默认档 |
| 边界反馈 | 已在边界时说明当前已是可用的最慢／最快档 | 不虚构未发生的变化 |
| 教学关系 | 调速属于会话控制，不新增教学任务或掌握证据 | 操作偏好与学习表现具有不同含义 |
| 失败处理 | 显示明确失败；不说“已经调整” | 保持反馈可信 |

### 2.3 当前范围

支持经过验证的中文和英文明确表达，例如“请说慢一点”“快一点”“恢复正常语速”“slower please”“Could you speak more slowly?”。识别采用保守规则；未命中的表达继续走普通交流，不保证任意自然语言说法都能调速。

否定、引用、词义讨论和相反方向的模糊请求不直接触发调速，例如“不要说慢一点”“他说‘快一点’”“慢一点是什么意思”“慢一点还是快一点”。中间识别文本不执行控制，只有同一会话内已接受、去重后的完整转写才能触发。

当前不包含单句临时语速、自动根据能力推测语速、长期偏好保存、会中下拉框操作或所有同义表达的语义理解。调速也不会自动简化词汇、缩短回答或降低教学难度；这些属于其他策略。

## 3. 技术方案

### 3.1 职责分工

| 层次 | 负责什么 | 当前实现位置 |
| --- | --- | --- |
| 请求识别和状态 | 把明确口头请求变成慢／快／正常意图，计算目标速度 | [speech.js](../packages/agent-core/speech.js) |
| Agent 会话 | 接受有效输入，保留本场设置，协调本轮教学处理 | [teaching.js](../packages/agent-core/teaching.js) |
| 上下文编译 | 将有效语速写入完整指令，移除已被覆盖的初始语速投影 | [context-snapshot.js](../packages/agent-core/context-snapshot.js) |
| 调速事务 | 管理两段确认、播放等待、更新与过期处理 | [speech-pace-coordinator.js](../apps/realtime-gateway/src/speech-pace-coordinator.js) |
| 实时编排 | 串行处理回复、取消、上下文更新、授权和关闭 | [realtime.js](../apps/realtime-gateway/src/realtime.js) |
| 供应商适配 | 发送真实速度参数，绑定供应商回复身份和配置确认 | [seeduplex.js](../packages/provider-doubao/seeduplex.js) |
| 客户端 | 播放语音、呈现字幕、显示状态并报告播放完成 | [speech-playback.js](../apps/realtime-gateway/public/speech-playback.js)、[web.js](../apps/realtime-gateway/public/web.js) |

请求确认和成功确认采用宿主提供的固定文本，通过真实语音服务合成。字幕来源明确为该固定文本；没有将宿主文本冒充供应商返回的转写。中文优先，当前语言策略要求英文支架时追加短英文。

### 3.2 三种速度状态

实现区分三个值，防止“已经请求”被误认为“已经生效”：

| 状态 | 含义 | 何时改变 |
| --- | --- | --- |
| `desired` | 学习者最新请求的目标速度 | 接受明确请求时 |
| `contextSpeed` | 准备交给供应商的上下文快照所使用的速度 | 第一段确认播放完成，释放更新时 |
| `applied` | 当前活动会话中，供应商已确认的有效配置速度 | 匹配的配置更新确认到达时 |

连续收到“再快一点”时，目标从当前 `desired` 继续步进。已发送的快照保持不可变，不能被后来的目标就地改写。等待旧更新和取消完成后，再处理最新请求。

`applied` 是配置状态，不是听感评分，也不证明学习者听到了、听懂了或获得了学习效果。

### 3.3 正常执行顺序

完整转写被接收后，Agent 将其识别为会话控制，并停止本轮新的教学 Planner 工作。网关收住归属此请求的自动回复，复用已有取消流程，避免普通回复与固定确认语竞争输出。

原回复结束或取消完成、且没有其他待确认控制后，系统合成第一段确认。客户端只有在同一回复的音频排空、字幕展示完成后，才报告这一阶段完成。服务器还会核对请求、回复、阶段和音频时长。

随后，网关把新语速与完整教学上下文合并成一个版本化配置更新。收到匹配确认后才更新有效状态，并合成第二段成功确认。第二段也有自己的回复归属和播放回执；结束后继续普通交流。

当前客户端允许明确标记的静音播放完成回执。静音只表示本机播放流程已处理，不表示用户听到了确认。

### 3.4 状态与主要转移

| 阶段 | 下一步条件 |
| --- | --- |
| 等待原回复结束 | 原自动回复结束／取消，并且串行控制通道空闲 |
| 播报请求确认 | 收到有归属的确认音频完成事件 |
| 等待第一段播放 | 客户端报告同一请求／回复的 PCM 排空、字幕完成 |
| 更新配置 | 供应商确认对应的会话配置更新 |
| 播报结果确认 | 使用新配置产生有归属的确认音频 |
| 等待第二段播放 | 客户端报告该段播放完成 |
| 完成 | 保留本场有效速度，恢复普通交流 |
| 取消／失败 | 清除过期反馈；按真实配置状态和错误结果处理 |

原回复及更新等待、语音生成、浏览器播放均设有超时。当前失败策略沿用已有网关行为：显示原因并结束失败会话，不在状态不确定时继续宣称成功。移植时可以另行设计恢复流程，但必须提供等价的归属、隔离和真实状态保证。

### 3.5 上下文与播放时钟

语速数值和指令同步更新。后续 Planner、画像刷新或普通上下文重编译，继续使用本场有效设置，不恢复旧计划中的 pace。原始初始计划仍保留其历史值；有效指令投影会去掉已被覆盖的字段。

本实现直接调整服务端生成语音的速度，保留采样率和浏览器原播放时钟。字幕、播放排空及会话收尾继续依赖同一 PCM 时间基准。已经生成或进入队列的音频不会被追溯变速；本方案通过明确的回复边界控制切换。

## 4. 并发、打断与结果真实性

| 情况 | 当前处理 |
| --- | --- |
| 完整转写前已生成回复 | 按原回复 ID 收住或取消，丢弃过期输出 |
| 第一段确认期间来了新输入 | 取消旧反馈；尚未释放的目标不继续自动执行 |
| 配置已发出，但新输入到达 | 在途更新仍依据真实 ACK 记录；不再播旧请求的成功确认 |
| 连续要求加快／放慢 | 继续计算最新目标，串行处理在途控制，不用旧确认覆盖新请求 |
| 手动打断／退出／断开 | 停止相关播报并隔离迟到输出；结束时清除控制状态 |
| 错误／重复／迟到播放回执 | 不推进其他请求或其他阶段 |
| 已达到速度边界 | 说明限制，不再假称调整了一档 |

每笔事务使用会话、来源话轮、请求和回复身份。第一段确认不能替代配置回执；配置回执不能替代播放回执；播放回执不能替代学习理解证据。

控制确认携带独立来源标记，不进入教学执行观察、学习小结或学习尝试证据。业务身份和学习记录仍走原授权边界；此功能不新增外部 HSKai 集成，也不产生真人安全交付声明。

## 5. 豆包实现中需要单独适配的部分

当前使用仓库已审核的 Seeduplex `1.2.6.1`。以下内容属于当前适配器及已记录实测，不应直接套用到其他供应商：

| 项目 | 当前实现／观察 |
| --- | --- |
| 速度档位 | -40、-20、0、20、40；初始 slow=-20、normal=0 |
| 参数位置 | `session.audio.output.speed` |
| 配置更新 | `session.update`；动态调速使用完整 session 形状，保留模型、音色和音频格式 |
| 配置确认 | `session.updated`，核对会话并绑定唯一在途上下文版本 |
| 固定文本合成 | `speech_text_buffer.commit` |
| 固定语音身份 | 实测有独立 question ID，不回显上行 event ID；通过预留控制通道及有身份的音频开始边界绑定 |
| 音频时长 | 24 kHz、16-bit 单声道 PCM；字节数用于计算时长 |

这里的步长 20 是供应商参数单位，不能写成固定“提高 20%”的产品承诺。其他供应商的 0、1、20 可能有不同含义；移植应使用产品语义档位，再由适配器映射并试听校准。

当前 ACK 归属还依赖已有的单笔在途控制与账号审核过的有序确认策略。不能假定供应商会返回本项目的请求 ID 或版本号。新供应商若提供可靠的请求关联标识，应优先使用；没有关联标识时，需要独立证明串行及迟到隔离策略可行。

### 6.1 实施顺序

| 阶段 | 交付 | 完成情况 |

| 可行性实验 | 同一真实连接内更新速度，对比固定文本 PCM 时长并恢复正常 | 已完成，见 [Spike](speech-pace-spike.md) |
| 请求和会话状态 | 明确请求判别、相对步进、上下限、去重和作用范围 | 已完成 |
| Agent 与指令 | 持有有效状态，跳过本轮教学规划，避免旧画像／计划覆盖 | 已完成 |
| 控制事务 | 两段确认、串行更新、回复归属、取消和超时 | 已完成 |
| 页面和播放 | 状态展示、字幕、PCM 排空、暂停恢复与回执 | 已完成 |
| 分层回归 | 工程、真实供应商、浏览器分别验证 | 已完成当前检查；真人设备专项仍开放 |

### 6.2 证据范围

| 验证层 | 已有结果 | 能证明的范围 |
| --- | --- | --- |
| 工程／合成 | 527 项测试通过，其中本功能新增 12 项；三个 synthetic replay 通过 | 状态、契约、隔离及既有运行回归 |
| 浏览器／合成 | 通用 Chromium 检查和专项三笔事务通过，page errors=0；暂停播放阻止提前更新 | 真实浏览器音频／字幕模块在合成输入和合成供应商下的行为 |
| 真实供应商／作者语音 | 同连接依次“慢／快／恢复正常”，三笔事务完成；速度 -40、-20、0 | 作者语音经过实际 ASR、网关、取消、配置确认和确认音频链路 |
| 真实供应商／固定文本 | 九段同文对照；正常中位数 5392 ms，+20 为 4651 ms，+40 为 3695 ms | 本次采样中参数更新与生成音频时长变化有可观测关联 |
| 真人体验 | 用户初步反馈较好；未做标准化采样 | 尚不能替代不同设备、口音和回声环境验收 |

真实供应商的 CLI 探针使用明确标记的合成静音播放回执，未使用浏览器播音来完成该次探针。固定文本合成在本次观察中没有返回文字输出事件；宿主确认字幕不构成音频逐字内容核对。上述结果应分别陈述，不能合并成“所有真实设备场景已通过”。

本轮没有提交密钥、原始供应商事件、真实学习者转写或录音。验证脚本默认不联网；真实调用必须显式启用，并使用目标环境已审核的配置。

## 7. 移植到其他 Agent 项目的实施计划

### 7.1 可以复用的设计与需要替换的实现

| 可沿用的设计 | 需要按目标项目适配 |
| --- | --- |
| 慢／快／恢复正常的产品语义与作用范围 | 供应商速度参数、范围、档位和真实听感 |
| 目标、待更新、已确认三种状态 | 目标项目的会话容器和上下文版本机制 |
| 请求确认→播放完成→配置确认→结果确认 | 自动回复接管、取消接口和固定文本合成能力 |
| 请求／话轮／回复／阶段归属与过期隔离 | 供应商实际返回的身份和 ACK 关联方式 |
| 控制输出不产生业务成果证据 | 目标项目的业务记录、分析和观测接口 |
| 工程、真实供应商、客户端分层验证 | Web、移动端或其他播放器的完成回执实现 |

`SpeechPaceCoordinator` 当前直接调用 `TeachingSession` 的状态和方法，浏览器模块依赖现有 `Presentation`／`AudioIO`。移植时应把“读取语言策略、释放配置更新、取得有效速度”等依赖替换为目标项目的接口；不能只复制协调器文件就视为完成接入。

建议在目标项目明确以下宿主接口。名称仅用于说明职责，不是已经发布的跨项目 API：

| 接口职责 | 输入／结果要求 |
| --- | --- |
| 接受学习者输入 | 已授权、同会话、去重后的完整文本及来源话轮 |
| 管理速度状态 | 默认档、最新目标、配置快照、有效档及请求来源 |
| 等待可控回复边界 | 能确认原回复已经结束／取消，且没有竞争控制 |
| 播报受控文本 | 文本、请求、阶段、来源话轮；返回有身份的实际音频 |
| 提交配置快照 | 有效指令、产品档位映射后的参数、宿主版本 |
| 确认配置 | 可核验的供应商确认，绑定到唯一实际发送的快照 |
| 确认播放 | 同请求／回复／阶段的音频排空、字幕完成和静音状态 |
| 取消与结束 | 使旧反馈失效，保留在途配置的真实最终状态 |

### 7.2 建议分阶段落地

| 阶段 | 负责角色 | 交付与进入下一阶段的条件 |
| --- | --- | --- |
| M0：能力核对 | 语音／服务端 | 明确动态参数、固定合成、取消、ACK 和身份能力；缺项时先形成等价方案并验证 |
| M1：产品契约 | 产品／Agent | 确认文案、语言、速度档、范围、边界、超时及新输入处理；采用独立 PRD 做验收依据 |
| M2：状态与上下文 | Agent／服务端 | 实现三种速度状态、版本与过期规则；证明旧 Planner／画像不会覆盖新设置 |
| M3：编排与播放 | 服务端／客户端 | 打通两段确认、更新和客户端完成回执；证明暂停、打断和退出行为正确 |
| M4：分层验证 | 测试／开发 | 通过合成竞争测试、实际供应商作者语音测试、实际客户端播放测试，并分别记录 |
| M5：试用与放行 | 产品／测试 | 在目标设备做听感和口音检查；确认延迟可接受、故障反馈清楚，再开放给用户 |

移植不要求把 Ask Kai 的课程、画像、Mock HSKai 或整个 Planner 一起带入。目标 Agent 只需在自己的授权、会话和业务边界中提供等价接口。是否抽取共享包，应在完成一次目标项目接入后再判断。

## 8. 移植验收时的重点

需要证明：学习者说出请求后，真正改变了后续生成语音的参数；成功确认出现在配置确认之后；新输入、退出和迟到事件不会复活旧反馈；已有话题、身份授权和业务记录保持正确。

还要单独检查目标环境的自动打断兼容性、不同速度下的清晰度、确认流程耗时及实际播放器时钟。本项目保留的原有自动打断兼容性问题，不能因一次三请求探针通过就判定在目标环境中已解决。
