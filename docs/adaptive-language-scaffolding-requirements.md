# 自适应英语支架需求

状态：需求草案，尚未实现验收。  
范围：Ask Kai 独立 Web POC 的中文对话语言支架；遵守当前本地 Mock HSKai 与实时语音边界。

## 1. 背景与问题

当前策略已支持画像／明确自述、已知表达、语言偏好和本轮求助，并提供 `required`、`adaptive`、`off` 三种英文支架状态。未知或初学者默认提供英文；画像标记为能理解中文、学生明确表示能听懂中文或有已知表达时，进入 `adaptive`，允许对熟悉内容省略英文。

当前缺少两种能力：一是不能根据多轮实际交流表现逐渐减少支架；二是“新表达”容易被视为需要英文，尚未充分区分学习者已能理解的内容与当前真正困难的词句。显式自述可以作为起点，但不能代替持续适应；单纯中文输出或 ASR 成功也不能证明理解。

## 2. 产品目标

1. 按学习者的中文理解水平和交流偏好提供够用的支持，减少高水平学习者不需要的英译。
2. 在有充分、相关的理解表现后谨慎减少英文；出现明确困难时及时提供局部帮助。
3. 允许同一会话中不同话题、不同句子的支架程度不同。
4. 让学生明确设置的语言偏好始终有效，并让学生容易请求解释或改回自动支持。
5. 将语言支持判断与课程目标、表达尝试和掌握结论分开。

## 3. 不在本需求范围内

- 证明学生已掌握某个词句、提高 HSK 等级或产生正式学习成绩。
- 仅凭中文发言、ASR 识别成功、沉默、跟读、回答“嗯／好”或教师说法，推断学生理解。
- 通过播放开始、音频转发或供应商 ACK 推断学生实际听到或理解了回复。
- 新增逐轮第二个规划模型、要求豆包暂停本轮生成，或改变现有响应归属、打断和迟到事件规则。
- 改变课程／身份数据的授权边界、长期画像写入规则或现有学习记录含义。

## 4. 用户与系统行为要求

### 4.1 支架起点

- 明确要求只用中文或常规双语时，按当前已实现的作用范围执行；本轮请求立即生效，会话设置持续到新的设置，长期偏好仅由授权画像保存。
- `auto` 下综合有效学习画像中的中文理解／听力描述、学习者自述、已知表达和熟悉交流情境选择起点。
- HSK 等级可作为起点参考，不能单独决定实际理解或强制指定支架；相同等级的学习者也可有不同语言偏好和听力表现。
- 画像未知时沿用当前安全默认：对可能影响理解的中文提供简短英文支持。

### 4.2 支架粒度

自动模式按当前内容选择最小够用的支持：

| 观察到的需要 | 期望行为 |
| --- | --- |
| 熟悉、具体、易理解的交流 | 中文自然回应，可省略英文 |
| 可能陌生的单词或短语 | 先用中文上下文、简单释义或例子帮助理解 |
| 局部含义仍可能不清楚 | 对应短语后给简短英文释义 |
| 整句或复杂意思可能造成理解负担 | 中文先说，随后提供意思对应的简短英文 |
| 学生明确表示没听懂 | 修复当前意思；只针对不清楚的部分增加解释，不借机换题或安排练习 |
| 学生询问“中文怎么说”或如何表达 | 给出所需中文说法；除非理解该说法需要帮助或学生要求，否则不机械追加整句英文 |

新表达或新词本身不是必须加英文的充分条件。还应考虑它是否是当前交流重点、上下文是否可理解、表达的词汇／句式／抽象程度及信息负担。无需做逐词拆解；英文不能增加中文之外的新知识或任务。

### 4.3 基于交流表现的渐进调整

- 系统可根据学生对 Kai 最近实际中文内容的相关回应，形成会话内的“可尝试减少支架”信号。
- 有效的正向信号包括：回应中文问题中的具体信息、正确承接限制条件或细节、围绕中文内容作相关补充。信号必须能关联到相关的 Kai 回复。
- 若 Kai 的上一回复已经提供对应英文，后续答对只能说明交流顺畅，不能作为“理解中文”的正向信号。
- 一次看似相关的回答不应导致大幅撤架。需要多次、近期且彼此独立的有效表现后，才尝试减少一级；具体窗口、阈值和冷却期由实现前的评测校准，不在本需求中固定为学习科学结论。
- 减少支架后继续观察。表现不确定时维持当前级别；重复出现无法承接、学生明确求助或上下文难度显著上升时，恢复必要支持。
- 判断只作用于当前会话的支架策略，不写入长期能力画像，不更改 KP 状态或 mastery。
- 换话题可以令系统暂时增加局部支持，但不应抹去其他话题下已观察到的表现。

### 4.4 证据与不确定性

- 将“表达是否相关／准确”“此前 Kai 实际提供的语言”“当前支架设置”“观察来源和话轮”绑定保存，供后续支架决策使用。
- `student_response_received`、`reply_completed`、上下文 ACK 和文本被转发均不等同于理解证据。
- 语义观察不可用、超时、过期、与话轮不匹配或置信不足时，忽略该观察并保持原有支架状态；不得阻塞语音会话。
- 如果本轮回复可能早于后台观察或上下文更新，观察只可影响后续安全边界的输入；不得声称它控制或改写已生成回复。
- 诊断使用固定枚举、计数、版本和匿名话轮引用；不记录不必要的学生原话、原始音频或原始供应商 trace。

### 4.5 控制优先级

优先级从高到低：安全与明确结束／打断 → 当前明确语言要求 → 当前轮理解求助 → 有效会话语言设置／授权偏好 → 当前话语和上下文需要 → 会话内逐步适配状态 → 默认画像起点。

求助只改变当前帮助动作，不永久将学生标成初学者。一次性语言要求在对应回复结束后失效；旧回复完成事件不得清除更新的话轮请求。只中文偏好下，理解求助先简化中文，不擅自附英文。

## 5. 验收场景

| 场景 | 验收要求 |
| --- | --- |
| 未知画像的初学者听到可能超出当前理解的中文 | 保留简短英文支持；中文在前，英译对应中文 |
| 高阶画像学习者谈熟悉话题 | 不因每个新词／新表达机械附整句英文；优先用上下文或简短中文解释 |
| 学生在没有对应英文的前提下，连续准确承接中文中的细节 | 达到经校准的保守条件后，只减少一级；后续仍持续观察 |
| 学生答对的上一句已有完整英文翻译 | 不将这次答对视为理解中文的证据，不据此撤架 |
| 学生只说“嗯”“好”、沉默、重复教师示范或只有 ASR 成功 | 不因此减少支架 |
| 学生说“没听懂”或针对当前含义求助 | 立即解释当前不清楚处；结束此次帮助后回到原会话基线 |
| 学生问“这个意思中文怎么说” | 给所需的中文表达，不自动追加不必要的英文释义或跟读任务 |
| 学生明确只用中文、要求英文或设置常规双语 | 当前要求按正确作用范围优先，确认语也符合当前要求 |
| 换到陌生主题、观察超时或结果不确定 | 只对当前内容增加支持或维持现状，不清空会话中其他有效记录，不阻塞对话 |
| 结束后总结或学习档案写回 | 不把支架变化、回答正确或尝试记录称为掌握、独立能力或等级变化 |

## 6. 评测与发布门槛

- 建立按画像起点、明确偏好、熟悉／陌生内容、是否先给英文、明确求助和话题切换分层的多轮用例；同时保留正例与误撤架负例。
- 逐回复审阅中文是否自然易懂、英文是否必要且准确、求助是否局部修复，以及支架变化是否有可追溯证据。
- 合成回放验证状态归属、作用范围、过期／取消／迟到观察隔离和降级行为；不得把合成结果报告为真实模型合规。
- 真实豆包候选需独立审阅实际输出并保留失败样本；另行检查浏览器中的播放、打断和听感。模型内容、真实供应商连通性和浏览器音频体验分开报告。
- 在理解观察校准完成前，自动撤架保持 shadow／建议状态，不驱动学生级能力画像或任何正式学习结果。

## 7. 与当前实现的关系

当前代码已有 `required`／`adaptive`／`off` 状态、来源受限的偏好和理解自述、已知表达、本轮求助、回复归属，以及上下文安全边界更新。当前规则还会在新表达或理解求助时优先要求英文，并未实现基于多轮理解表现的渐进撤架，也未验证对当前中文难度的可靠语义判断。

实现本需求时应先将上述要求转化为独立固定案例及真实模型检查，再扩展会话内语言状态和策略指令。新的语言观察只能影响后续安全边界；现有 POC 仍是 Doubao 实时全双工与 `next_turn_advisory`，未验证当前回复门控。Mock 画像、规则回归和 synthetic replay 不证明真实学习者已理解。
