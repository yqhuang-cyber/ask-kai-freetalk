## 评分与诊断边界

- 保留作者脚本和实际 ASR 两者。端到端模型接收音频，ASR 是用于诊断和文本评分的观测；识别文本有偏离时，分别评估 ASR 偏离、Agent 与实际可见输入的回应关系和原案例覆盖，不用脚本替换 ASR，也不把连锁失败重复算成独立问题。
- 上下文确认、策略版本和回复开始时间用于定位时序。下一轮已确认不证明本轮应用新决策；首案观察不足以判定是供应商时序、当前架构或运行器行为导致。
- 逐轮评分使用截至本轮的真实前文与独立要求；会话总结使用实际结束前的记录。未来学生输入和参考回复不能补入待测历史，也不能倒推当前轮预期。字符计数只给表面提示，不能替代翻译、教学密度和意图的语义判断。
- 内容失败、采集失败、不可评、上下文失配、待人工复核分别统计，并显示各项有效分母。完整执行不等于内容通过；部分案例不能宣称全量覆盖；总均分不能抵消安全或关键失败。
- 固定音频和完整学生脚本提供可重复的内容实验条件，不能证明自然交互、真人口音、扬声器播放、字幕同步或真实插话体验。Task 10 保留独立验收，不因内容评测完成而自动完成。

## 两种 harness

这里将用户所说的 “honeys” 暂按 **harness** 理解。**评测 harness** 是外围运行、记录、评分和比较工具；**Agent harness** 是被测 Agent 的运行外壳，涉及提示词、画像／上下文、工具、状态和响应控制。当前 `apps/eval-runner/src/agent-harness.js` 属于前者：它驱动生产网关，不是新的 Agent 编排层。

后续 Agent 修改面由完整评测和必要的对照实验决定：每条建议应有受影响案例、实际证据、根因假设、支持／反证、预期收益及回归范围。尚未验证的原因标为假设，不能把所有问题都归为提示词，也不能从单个案例推出全局策略。

真实采集沿用现有 `DOUBAO_API_KEY`。人工评分不需新 Key；可选模型 Judge 按现有 `EVAL_JUDGE_*` 单独配置，不预设豆包语音 Key 可直接用于评分接口。当前不要求 Langfuse 接入。
