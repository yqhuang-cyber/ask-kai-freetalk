# 主题对话作业：最小 Demo 服务蓝图

2026-10-26 · 设计与演示稿，业务主链尚未实施。

本稿将“sales blueprint”按本次角色与流程语境理解为 Service Blueprint（服务蓝图）：横向看作业如何流转，纵向看教师、学生、Kai 与后台如何接力。

## 1. 这次只演示什么

**一位教师确认并发布一份主题作业，一位学生和 Kai 完成一段对话并提交，双方获得针对这次练习的反馈。**

用一个固定案例贯穿：林老师 → 模拟学生 Maya → 餐厅点餐 → “说清想点什么、说明一种口味要求” → 一次练习 → 一次提交 → 两份反馈。

这是现有完整作业方案的缩小切片，供先做 Demo，不替换 [完整 PRD](prd/teacher-assigned-conversation-homework-prd-v0.2.md)、[User Journey](teacher-homework-user-journey.md) 或 [前置规划设计](teacher-homework-planning-design.md)。当前 FreeTalk 不承载作业，入口、初始无目标规划和行为保持现状；外部 HSKai 集成不在本切片范围。

用户已确认先以本蓝图为实现目标。实施顺序为 G0 → G-Demo → 教师 / 学生 / Kai 分角色完善，具体见[最小 Demo tasking](teacher-assistant-minimal-demo-tasking.md)及[技术方案 v0.2](teacher-assistant-technical-design.md)。本蓝图原有故事板与验证记录仍仅代表演示稿，不代表新业务已经实现。

## 2. 四个角色各负责一句话

| 角色 | 责任 | 最小操作 / 产物 |
| --- | --- | --- |
| 教师 | 决定练习方向，确认任务，查看如何跟进 | 选点餐主题 → 确认预置任务 → 发布 → 看报告 |
| 学生 | 理解任务，开口交流，决定何时提交 | 打开任务 → 和 Kai 聊 → 结束 → 提交 → 看反馈 |
| Kai | 围绕已确认任务创造表达机会，必要时帮助 | 扮演服务员，一次一个问题，记录实际提示与学生尝试 |
| 本地演示后台 | 把同一份任务、同一次尝试和两份反馈连起来 | 本地模拟身份 / 授课关系 / 作业；区分提交与分析状态 |

不要求四个独立服务，也不要求多个 Agent。演示中的角色切换仅为查看不同视角，不代表真实账号授权。

## 3. Service Blueprint

| 层次 / 阶段 | ① 布置与发布 | ② 查看与开始 | ③ 主题对话 | ④ 结束与提交 | ⑤ 双端反馈 |
| --- | --- | --- | --- | --- | --- |
| 可见凭据 | 教师任务预览、发布结果 | 本人任务卡 | 对话、字幕、帮助提示 | 提交确认 | 学生反馈、教师报告 |
| 教师动作 | 选主题、对象与截止，确认任务后发布 | 等待学生练习 | 无需在线陪练 | 可看到已提交 | 看表现、证据与下一步建议 |
| 学生动作 | — | 看清要做什么，点击开始 | 点餐、回应、求助；可随时结束 | 结束对话后确认提交 | 看本次练过什么、下一次怎么练 |
| **交互线：双方可操作的触点** | **确认并发布** | **开始练习** | **说话 / 求助 / 结束** | **提交这次练习** | **查看反馈** |
| 前台服务（看得见） | 展示任务草案与发布状态 | 展示任务、AI 身份与真实连接状态 | Kai 扮演服务员，按需提示 | 停止采音，显示提交结果和分析状态 | 同一尝试，两种反馈视图 |
| **可见性线** | 以下为后台支持 | 以下为后台支持 | 以下为后台支持 | 以下为后台支持 | 以下为后台支持 |
| 后台动作（看不见） | 读取预置资源 / 计划；固定发布版本 | 核对本人任务与权限，准备独立作业会话 | 在任务范围内接话；区分提示与学生尝试 | 固定本次尝试；防止重复提交 | 对照同一目标与证据生成反馈 |
| 支撑资源 | 本地模拟名单、点餐模板 | 已发布任务与最少授权资料 | 经确认的情境、语音与字幕基础能力 | 本次会话事实与提交记录 | 同源事实、两种表述、教师查看权限 |

任务发布成功不等于语音已连接；学生提交成功不等于目标已经达成；报告生成成功不等于教师已阅读。

## 4. 最少页面：四个页面，五个演示步骤

| 页面 | 核心内容 | 主操作 |
| --- | --- | --- |
| A 教师作业页 | 主题、对象、具体截止时间、预置计划预览；发布后显示进度 | 确认并发布 / 查看报告 |
| B 学生任务页 | 林老师布置、要做什么、AI 角色、可求助与结束；提交后显示反馈 | 开始练习 / 查看反馈 |
| C 学生对话页 | 本次任务、连接状态、Kai 对话与字幕；结束后显示提交确认 | 结束练习 → 提交这次练习 |
| D 教师报告页 | 已提交状态、本次尝试、帮助与证据、下一步教学建议 | 查看本次报告 |

页面是后续实现的设计建议。本次交互演示稿展示角色接力与内容，不会发布作业、采音或调用模型。

## 5. 逐步演示脚本（约 3～5 分钟）

### 第一步：教师确认一份任务

林老师选择 Maya 和点餐主题，看到预置草案：

> 在模拟餐厅里，用中文说清想点的一种食物，并说明一种口味要求。Kai 扮演服务员，学生可以求助或结束。本次观察点：是否表达点单意图、是否表达口味要求，以及此前获得了什么帮助。

示例截止时间：2026-10-27 23:59（Asia/Shanghai），供演示使用，可在实现时编辑，不创建提醒。

教师点击“确认并发布”。预期结果：教师看到“已发布 · 0/1 提交”，Maya 的独立作业入口出现同一份任务。

讲解句：“老师只需要确定方向并确认任务；首个 Demo 用一份预置计划代替自动备课。”

### 第二步：学生打开任务

Maya 看到：“点餐练习 · 林老师布置。你来做顾客，Kai 来做服务员。试着点一种食物，并告诉 Kai 你的口味要求。可以随时求助或结束。”

点击开始后才进入独立作业会话。真实运行时，准备完成与语音就绪分别显示；没有真实就绪，不能显示正在聆听。故事板统一标注“合成示例，无语音连接”。

讲解句：“学生一眼就知道要做什么，不需要理解后台教学计划。”

### 第三步：完成一小段主题对话

以下均为作者编写的合成脚本，用于展示结构，不是真实学习证据：

| 顺序 | 发言 | 观察意义 |
| --- | --- | --- |
| K1 | Kai：你好，今天想吃点什么？ | 给点餐机会，尚未提供完整答案 |
| S1 | Maya：我想要一碗面。 | 在本示例前文未提供完整句框时表达点单意图 |
| K2 | Kai：好的，口味有什么要求吗？ | 给口味表达机会 |
| S2 | Maya：不要 spicy，怎么说？ | 学生主动求助，不推断为整体能力不足 |
| K3 | Kai：可以说“不要辣”。 | 完整短句提示 |
| S3 | Maya：不要辣。 | 在明确提示后尝试，不记为独立使用 |
| K4 | Kai：一碗面，不要辣，对吗？ | 确认含义 |
| S4 | Maya：对，谢谢。 | 本次确认订单 |

讲解句：“Kai 让学生在情境里使用中文，遇到困难再给一点帮助。反馈必须分清自己说出和提示后尝试。”

### 第四步：结束后明确提交

学生点击结束，先停止采音和播放，再点击“提交这次练习”。页面显示“已提交，反馈整理中”，教师页显示“1/1 已提交，报告整理中”。

学生没有说全也可以提交；退出页面和提交是两个动作。重复点击只产生一次提交。若无法确认写入，显示“提交状态待确认”；分析失败保留已提交状态，单独提供报告重试。

讲解句：“交了作业和表现好不好，是两件事。”

### 第五步：同一事实，反馈给双方

**学生反馈示例**：

> 这次你说出了“我想要一碗面”。表达口味时，你先求助，再借助提示说出了“不要辣”。下次可以试着把两句连起来说：“我想要一碗面，不要辣。”

**教师报告示例**：

| 观察点 | 本次事实 | 示例来源 |
| --- | --- | --- |
| 说清想点什么 | 在本示例的开放提问后说出点单句，前文无完整句框 | K1 → S1 |
| 说明口味要求 | 先求助，完整短句提示后尝试 | S2 → K3 → S3 |
| 作业状态 | 本次练习已提交 | 提交记录，与学习表现分开 |
| 下一步教学 | 下次换一种食物，先不提供完整句框，观察能否连贯表达点单和口味 | 基于上面两项事实的建议 |

首个 Demo 不做 A/B/C/D。完整方案中的等级仍仅教师可见，需后续独立验证量表。此处不写长期掌握结论、不评发音、不写教师已审阅。故事板中的全部反馈标注“合成示例”。

讲解句：“学生获得可执行的练习建议，老师获得能用来安排下一次教学的观察。”

## 6. 哪些先做真，哪些可以先预置

| 项目 | 最小可运行切片的建议 | 本次交付状态 |
| --- | --- | --- |
| 教师 / 学生 / 授课关系 | 本地 Mock，显示模拟身份，边界与鉴权仍要保留 | 设计示例 |
| 主题资源、前置计划 | 一套经人工确认的点餐模板；显式标“预置方案” | 作者预置内容 |
| 发布、本人任务、提交、报告关联 | 在同一条本地业务链真实流转；一份任务、一次尝试、一条提交 | 尚未实现 |
| Kai 主题对话 | 后续复用现有语音基础能力，在独立作业场景接入固定任务 | 仅合成脚本；未连接豆包 |
| 反馈 | 按本次实际事实填充简单模板，保留来源；没有证据则显示无法判断 | 仅与示例脚本配套的示例报告 |
| 自动准备与个性化 | 预留前置规划步骤，后续将预置方案换成 AI 草案 | 延后 |

预置内容可以代替暂未实现的内容生产；真实运行时，不能把预写报告当作任意学生对话的结果。若演示现场改用真实语音，报告必须读取当场事实，或明确保留为独立示例。

## 7. 首轮延后事项

多学生分层、多个主题、自动生成教学包、完整教师工作台、A/B/C/D、复杂剧情、发音评分、重练择优、多次趋势、家长端、外部通知和真实 HSKai 集成均延后。保留单个学生的发布与提交进度，不先做班级统计。

## 8. 这条路打通的验收标准

1. 教师确认的主题、目标、学生任务卡及 Kai 执行说明一致。
2. 学生从独立作业入口进入；原 FreeTalk 没有作业读取、卡片或行为变化。
3. 真实连接失败时显示失败，不用合成对话冒充实时回复。
4. 一次结束和一次明确提交可以到达双方可查询的同一提交；重复点击不重复写入。
5. 报告失败不会变成未提交；没有覆盖到的目标显示未观察到或证据不足。
6. 学生反馈与教师报告引用同一次尝试，提示后尝试不写成独立使用或掌握。
7. 最小故障展示至少包含连接失败、提交待确认、报告失败；无需扩成完整异常管理台。

**本次验证范围**：文档与交互故事板；所有人物、对话、状态和反馈为合成示例。已检查故事板脚本语法、五步前进、后退、直接跳步、返回蓝图及范围切换，检查使用本地模拟页面对象，不是浏览器视觉验收。浏览器视觉预览未完成。未改运行代码 / 业务契约，未运行 synthetic runtime replay、真实 provider 或浏览器音频验收。后续运行 / 契约实现应按仓库要求执行 `npm run verify` 与 `npm run replay`，并分别报告合成、真实供应商和浏览器音频结果。
