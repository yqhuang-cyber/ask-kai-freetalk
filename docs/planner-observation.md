# Planner 与语音模型观测

本机开发页面自动整理每场前 5 轮观测总结，并提供详细时间线，帮助核对初始规划、逐轮规划和语音配置之间的关系。不改变规划预算、生成方式或对话结束规则。

## 对话后的汇总导出

普通页面无需 `?observe=1`。选择学习者、开始对话，结束或断开后到「会话观测总结」点击「汇总并导出观测总结」，下载可直接阅读的 Markdown。历史记录可按当前学习者选择；尚未保存成功的本场会提示刷新，不自动改选历史会话。没有开启详细面板，也会整理新会话；不追溯旧会话。

| 内容 | 汇总方式与边界 |
| --- | --- |
| 豆包 Log ID | 仅取 WebSocket 握手的 `x-tt-logid`，记录来源；缺失写未取得，不使用本地 ID 替代。是连接级标识，不伪造逐轮 ID |
| 供应商身份 | 通过独立观测回调关联豆包 session／response ID，不把它们混入正常业务事件或改变回复归属 |
| instructions | 各回复引用配置版本与哈希，文件末尾附对应完整指令，并逐版标注是否实际发送、是否确认 |
| actual response | 通过归属和安全检查后已转发的文字；输出未结束或中断时保留已收到部分并明确标注，不代表用户已听完 |
| expected response | 自动保留当时配置中的 Planner 任务、难度、支架及预期观察；可选填写理想措辞，不编造标准答案 |
| expected effect | 自动提取中文难度／词汇上限等要求，可选补充效果和备注；实际语义符合度未自动评分 |
| 对本轮输入的后续计划 | 单独列出该输入触发的逐轮提案，不追溯替换回复开始时的预期 |
| 异常 | 取消来源、实际发送／确认／超时，以及会话错误码，保留最后 20 条相关事件 |

计数以服务接受的学生完整表达为准，每场前 5 轮及其关联回复；不足 5 轮也可导出。开场等尚未关联输入的回复最多单列 2 条，不保证一定是开场。超过 5 轮后不再将后续输入／回复加入总结，并显示省略轮数。总结独立于原始事件滚动窗口，旧事件从时间线淘汰后，已整理的前 5 轮仍在。

正常结束和异常断开均在服务结束处理时保存；进程被强制杀死前尚未保存的活动会话不能恢复。授权撤销或安全限制不会新增该场持久化总结。保存失败会明确显示，不能把旧场当成本场导出。

POC 使用 `.local/observation-reports/` 保存，按 owner／learner 的哈希键分桶、接口要求有效的会话授权。每位学习者保留最近 20 场（不是只保留 5 场），每场最多 1 MiB。目录新建权限 0700、文件 0600，文件原子替换；刷新和重启可读，超限淘汰最旧场次。人工补充每字段最多 3000 字，只允许修改当前报告中的回复。存储目录被 Git 忽略，不能提交真实识别文本、回复和指令。

这些是单独的开发观测数据，不写学习成果或掌握记录；原业务学习小结仍使用本地 Mock 内存。新连接的 Log ID 回调失败不改变业务结果。完整语音、认证信息和原始供应商消息均不保存。

实现：`packages/agent-core/observation-summary.js` 做增量关联，`apps/realtime-gateway/src/observation-reports.js` 做授权存储，页面 `observation-reports.js` 做选择、可选补充与导出。接口为 `GET /api/observation-reports`、`GET /api/observation-reports/:id`、`POST /api/observation-reports/:id`（人工补充）、`GET /api/observation-reports/:id/export`。

## 打开与使用

启动更新后的服务，访问 `http://127.0.0.1:4310/?observe=1`，展开页面下方「Planner 与语音模型观测」。普通页面也有开启链接，点击后重新加载。详细面板默认隐藏，普通页面已自动采集前 5 轮总结所需内容。

1. 选择学习者，等待准备完成，查看初始规划。
2. 开始对话，每个已接受的学生表达会出现在同一条时间线上。
3. 展开事件查看 JSON；可筛选初始规划、逐轮规划、学生输入或语音模型交互。
4. 需要交给开发者分析时，手动导出 JSON。文件包含画像、提示词及对话文字；普通元数据诊断仍不包含这些文字。

切换学习者会清空旧的时间线显示，并加载当前学习者的历史总结。每次重新准备产生独立 `trace_id`；开始语音时继续使用该准备对应的观测。刷新不会恢复历史详细事件，但可读取保存的总结。页面「清空显示」只清时间线，不删除总结；回到不带 `observe=1` 的页面会隐藏详细面板，仍会整理新会话。

## 能看到什么

| 阶段 | 事件与内容 | 能证明什么 |
| --- | --- | --- |
| 准备 | `preparation.started`、`preparation.ready/failed` | 当前入口和最终采用的初始计划 |
| 触发 | `planning.triggered`、`planning.attempt` | 初始／逐轮类型、输入、预算、规划模型、尝试序号及修复原因 |
| 模型请求 | `planner.request` | 实际请求方法、地址和 JSON body；含 messages、生成参数，以及 Pi 使用的 tool schema |
| 模型返回 | `planner.http_response`、`planner.response` | HTTP 状态、content 或 tool_calls、结束原因、token 用量；不采集模型思考过程 |
| 校验 | `planning.proposal`、`planning.validated/rejected` | 适配器编译后的提案、校验结果、错误码和安全字段名 |
| 降级／采用 | `planning.fallback`、`planning.committed`、`planning.accepted/cancelled` | 规则计划和具体原因；通过校验后是否仍适用于当前轮。通过校验的旧提案仍可能失效 |
| 语音配置 | `voice.context.prepared/requested/waiting` | 编译后的完整 instructions、配置版本与哈希，以及是否正在等待回复结束或控制确认 |
| 实际发送 | `voice.request.sent` | 当前豆包适配器成功交给 WebSocket 的 session.create / session.update / response.cancel body；不包含鉴权头或音频帧 |
| 打断 | `voice.cancel.requested/sent/ack/skipped/ignored/timeout` | 自动识别或手动打断的来源、归属、实际发送和确认时长；超时前是否仍在等配置确认 |
| 确认 | `voice.ready`、`voice.context.confirmed` | 连接就绪；或适配器接受了匹配的配置更新确认。初始就绪与配置更新确认分开 |
| 回复 | `voice.reply.started`、`voice.reply.forwarded` | 回复开始时观察到的已确认版本、哈希、是否还有配置待确认；安全和归属检查后已转发的文字及完成／取消状态 |

全部事件共享一个服务端单调时钟；准备阶段就是时间原点。`trace_id` 关联整个准备和会话；`planning_id` 区分每次规划，`attempt` 区分修复重试；逐轮事件还包含 `turn_id`、输入版本。配置通过版本和哈希关联到回复。普通页面为总结开启采集，但不展示详细事件；既有模型传输元数据观察接口继续独立使用。程序化调用仍须传递准备观测开关才有总结。

## 排查 Alex 的中文难度

先在最终初始计划中检查 `strategy.speaking_difficulty` 和 `speaking_constraints`。随后在 `voice.request.sent` 的 `body.session.instructions` 搜索「说话要求」，确认普通主动用词范围为 HSK1。

逐轮调整时，依次查看请求、返回、校验／降级、`voice.context.requested`、实际发送和配置确认。再找到对应回复，比较 `applied_context_version/hash` 和当前配置，并查看 `pending_context`。这样可以区分规划未产出要求、结果被拒绝、仍未发送、尚未确认，以及要求已经发送但输出仍超出预期。

当前全双工允许豆包先生成、Planner 在后台规划。因此 `voice.reply.started.generation_basis` 保留 `unknown`：这个事件只记录收到回复开始通知时的已确认配置，不能证明生成开始时间，也不能证明每句话使用了最新计划或遵守了全部要求。文字已转发也不代表浏览器已播完；结束处理会补记未完成回复已转发的部分文字，完全没收到文字时明确标注。

## 详细事件的保留与边界

原始事件仅在本机服务内存和当前页面内存保留，不自动写普通日志、业务记录或磁盘；独立会话总结按上面的范围持久化。服务端每条观测最多 128 KiB，整个观测最多 160 条、2 MiB；页面同样最多 160 条、2 MiB。超大事件明确标记省略；超出容量淘汰旧事件；发送受 WebSocket 背压限制，序号缺口在页面显示。详细事件 JSON 导出只包含页面当前保留的事件，不保证长会话完整。

服务端取消、过期、撤销或结束会清理对应内存。已接收的页面内容保留到刷新、重新准备、切换学习者或手动清空。失败或超时后的迟到模型返回不再进入该次规划观测。观测回调失败不改变业务结果。

请求捕获限于规划请求 body 和语音会话配置 body；不捕获认证头、Cookie、票据、原始音频或原始供应商消息流。敏感字段和常见凭证形式另做屏蔽。请求中的授权画像与对话文本会进入观测，开启详细面板后可展示和导出，不能将其提交到仓库。

此开关与 `?diagnostics=1` 的体验采集分开。后者保留旧有采集语义，会抑制自动收束；普通排查使用 `?observe=1`，无需开启它。
