## 已实现的执行顺序

1. `speech.js` 保守识别中／英文明确请求。`TeachingSession` 只接受有效 final，持有目标、待更新配置与已确认速度，不跑本轮教学 Planner。语速请求不改变原教学目标。
2. 网关收住归属此请求的自动回复，复用现有 cancel／ACK 顺序；回复在 final 之前已经产生时也按原回复 ID 停止和隔离。
3. `SpeechPaceCoordinator` 请求固定文本合成：“好的，我来把语速放慢一点。”字幕明确来自宿主确认文本。确认语跟随本轮语言策略，必要时加短英文。
4. 等待这段音频完成，且浏览器报告相同 request ID／reply ID／阶段的字幕完成和 PCM 排空，再释放速度更新。
5. 通过唯一待确认的教学上下文更新一起发送完整 instructions 和速度，等待同 session 的 `session.updated`。上下文快照不可变，已发送的旧版本不会被新请求覆盖。
6. 配置确认后，才合成：“已经放慢了，接下来我会说慢一点。”这段使用新速度；等待自身播放完成后回到正常交流。请求阶段不会提前说“已经”。

固定文本合成的实际回包带独立 question ID，不回显上行 event ID；适配器只在原自动回复已经结束／取消后预留控制语音通道，并在有身份的 audio.started 绑定真实 reply ID。已知 ASR turn 不得抢占此通道。迟到／重复输出不能重新开启旧回复。控制语音的输出单独携带 request／phase 来源，不进入教学执行、学习小结或尝试证据。

新输入或手动打断会取消旧确认；已经在途的配置仍按真实 ACK 更新实际状态，旧请求不得据此再播成功确认。连续快／慢请求从当前目标继续步进，等待旧配置／取消完成后应用最新目标。普通画像刷新保留本场有效速度，语音 instructions 中去掉已被覆盖的初始 pace 投影。会话结束清除控制状态，不写长期画像。

## 验证结果

- **工程／合成：** `npm run verify` 527／527，通过；`npm run replay` 三个 synthetic 场景通过。新增 12 项覆盖请求判别、版本与参数、无教学证据、Planner／画像刷新、播放顺序、连续请求、迟到回复、错误回执和更新超时。完整回归发现的诊断 reason 白名单缺项已补齐。
- **浏览器／合成音频：** `npm run test:browser` 通过、page errors=0。`node scripts/spoken-speech-pace-browser-check.js` 使用生产 Seeduplex 适配器、真实 Chromium AudioContext／字幕模块、合成 peer 与设备，完成慢／快／正常三笔事务，证明暂停播放时不会提前更新、恢复后继续，page errors=0。没有把合成就绪展示成真实供应商连接。
- **真实供应商／作者语音：** `node --env-file-if-exists=.env scripts/spoken-speech-pace-probe.js --live` 通过生产网关上传本机作者合成的“请说慢一点／请说快一点／请恢复正常语速”。同一连接三笔事务均有 ASR、请求确认音频、配置 ACK 和结果确认音频，速度依次 -40、-20、0。CLI 的播放回执明确标为 synthetic muted，不冒充浏览器或真人播放证据。最初探针的静音补帧越界已修复，完整结果来自修复后运行。
- **正向速度：** 独立参数探针同连接发送九段相同作者文本，正常中位数 5392 ms；+20 为 4651 ms，+40 为 3695 ms，调回正常为 5188 ms；固定合成未返回文本事件，不声明听音内容核对完成。
- **未验收：** 真人麦克风／扬声器／耳机听感、回声和不同口音的识别质量。原有普通自动打断兼容性问题仍按既有边界保留，本次有界三请求通过不证明所有打断顺序都可靠。

不需要提供真实学生资料。Mock 身份和授权仅服务本地 POC；没有外部 HSKai 接入或真人安全交付声明。独立参数可行性见 [Spike](speech-pace-spike.md)。
