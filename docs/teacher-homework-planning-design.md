# 教师助教作业场景：前置规划与教学包需求

日期：2026-10-26（Asia/Shanghai） · v0.2 需求补充，尚未实施。

依据用户最新确认：**教师决定主题与教学方向；AI Planner 前置分析练习内容和目标；该能力是独立的新场景，不影响 FreeTalk。**

配套：[需求分析](teacher-assistant-requirements-analysis.md) · [User Journey](teacher-homework-user-journey.md) · [PRD v0.2](prd/teacher-assigned-conversation-homework-prd-v0.2.md)。

技术落地见[技术方案](teacher-assistant-technical-design.md)及[实施计划 / tasking](teacher-assistant-tasking.md)，均为待实施设计。

### 1.2 可借鉴与尚未证明的部分

可借鉴的是生成与消费分开、共享资源与私人资料分开、基于证据的目标选择、同源页面与语音上下文、版本固定及失效隔离。

原仓库实际工程示例为运动和音乐，本次没有运行点餐生成。其历史实施记录报告固定包下真实 M3 初始化 0/8、逐轮 0/8 采用模型，均走规则降级；这说明机制存在，但当时的真实模型可靠性未通过。此为原记录，不是本次新测结果。

原包也没有证明完整词句教学、专项发音或通用目标达成评分。用户期待的更完整作业教学包，需要在新场景中补充对应能力与验收。

## 2. 修正后的产品职责

| 决定 | 责任 |
| --- | --- |
| 练什么主题、服务什么课堂意图、给谁练、何时完成 | 教师做教学方向判断；可附当堂内容、观察和必须练的表达 |
| 主题里有哪些适合的情境、练习内容与表达机会 | AI 在教师范围内准备主题资源 |
| 每位学生具体练什么、为何合适、需要怎样的支持 | 前置作业 Planner 综合已授权画像、相关学习证据和教师要求形成草案 |
| 是否采用、修改、发布 | 教师批量预览，重点检查差异与风险项；无需逐人从零写教案 |
| 本轮怎么接、问什么、给多少帮助 | 新场景的逐轮 Planner 在已确认计划内调整 |
| 发生了什么、下一步怎么办 | 会后分析生成有来源的反馈 / 教师暂评；教师决定后续教学 |

这是职责分层，不要求多个 Agent 或多次串行模型调用。具体模块、授权服务与运行边界见[技术方案](teacher-assistant-technical-design.md)。

## 3. 前置规划的三个产物

### TeacherBrief：教师的方向与约束

最少为主题、学生和截止；可附课堂所学、希望巩固的沟通行为、指定表达、禁止 / 不希望重复的内容及材料。教师不必预先逐项写出目标、脚本或量表。

主题由教师决定。AI 可以报告方向与资料之间的冲突、提出修改建议，但不能自行改成另一个主题并发布。教师写的个人观察进入私人规划输入，不能混入共享资源。

### TopicPack：可复用的主题资源

包含主题边界、子话题、角色和情境、候选表达机会、允许能力关联、可用开场及经准入的材料引用。优先读取符合本次范围的可用版本；没有合适资源时，在教师端后台生成与检查。

无 learner 身份、画像、历史、表现或成绩。教师私有材料只能在获准的作业 / 教师范围复用，不因去掉学生姓名就自动成为全局公共包。

词句示例、菜单、提示阶梯或剧情节点可以作为新需求的扩展字段，必须分别注明来源与内容准入状态。复用原受限包时只消费其已准入字段，不能自动补成“全部审核通过”的完整教材。

### HomeworkPlan：按学生形成的作业教学包

本稿将每位学生的作业教学包称为 HomeworkPlan；PRD 内 TaskPlan 指同一私人计划，不增加两份相互竞争的目标来源。它包含：

- 与教师方向一致的需要假设及最小依据，保留未知与覆盖限制。
- 具体、可观察的核心目标和选做目标；不是只返回“点餐”或能力标签。
- 关键沟通节点与表达机会，例如先点单、回应确认、处理替代选择；允许自然调整顺序。
- 与本次目标相关、经准入的材料 / 词句引用及按需提示选项。
- 难度、支持与纠错重点；哪些已稳定基础应避免完整重教。
- 每项目标的观察标准、预期证据种类、评估能力是否可用，以及教师专属量表引用。
- 学生任务卡、Kai 执行说明和报告分析都要引用的计划版本与来源。

作业层可有 1～3 项核心目标，逐轮只激活一项主要任务。这是对原“一个主要 GoalInstance”的新增扩展，不能假设原 schema 和生命周期可以直接承载。

“需要假设”与“观察标准”是计划，不是学生结果。生成器不得自行创设正式 KP、硬先修、发音能力或已验证评分规则。

## 4. 完整流程与等待位置

1. 教师选主题、对象、截止，可补充课堂意图与要求。
2. 系统读取可复用的已准入主题资源；必要时在教师端后台生成、校验并准备可消费的版本。
3. 前置作业 Planner 分别读取各学生获准资料，形成私人 HomeworkPlan；共用需要允许共用目标。
4. 页面显示整体摘要、每人的任务差异、依据和需处理项；教师可批量采用，只编辑需要变化的部分。
5. 教师发布后固定 brief、资源、个人计划和评价标准版本。资源发布资格检查与作业发布是两项逻辑检查，UI 不要求教师重复点击两次发布；教师也不会因此获得全局目录管理权限。
6. 学生从独立“老师的作业”入口选择任务。开始时只核对计划、授权、资源、资料时效，并准备会话执行方式，不重新生成教学包或任意另选目标。
7. 新场景逐轮按计划组织主题对话，学生可求助、暂停或结束。有效证据进入本次任务账本。
8. 学生提交后，分析按固定计划逐项对照实际发生的内容，生成学生反馈与教师报告。学生看不到 A/B/C/D。

前置生成有独立预算、进度和取消；不占学生的开聊 / 逐轮预算。教师不应通过刷新页面重复付费生成；学生端缓存未命中只读取已发布资源。

## 5. 失败、变化与资源缺口

| 情况 | 产品处理 |
| --- | --- |
| 资源生成或内容检查失败 | 保留教师草稿及原因，可重试 / 修改；不显示作业已可练习 |
| 部分学生计划失败 | 按人显示状态；默认不完整发布，教师可明确改选可发布的学生，不能静默漏发 |
| 教师修改主题、要求或学生名单时旧任务返回 | 结果绑定原草稿 / 学生 / 输入版本，不覆盖当前；只重做依赖变化的部分 |
| 没有可靠“薄弱点”证据 | 可在教师主题内提出有来源的探索 / 新情境应用目标，不虚构能力缺陷 |
| 先修或授权缺失、指定目标不受支持 | 标资源 / 能力缺口，建议缩小任务或补充经确认的资源；不得改用无关目标填充成功 |
| 词句、精确数量或句式目标不在现有目录 | 新增能力资源与评估需单独准入；不能只复用“喜好 / 原因”标签就声称完整支持点餐或“再也不” |
| 学生开始前学习资料变化 | 重新验证新快照与原计划的一致性；偏好调整可影响执行，目标冲突则提示需教师重新规划，不静默改正式标准 |
| 已发布资源 / 作业被撤回或权限失效 | 失效准备并阻止继续依赖该资源；在已知变更后隔离迟到规划及写回 |
| 任务完成得快或学生想改变练习 | 可自然收尾 / 使用已发布选做机会；更换核心任务需新计划版本和教师确认 |

## 6. FreeTalk 不受影响：硬要求

本需求是独立的“教师助教作业主题对话”场景。建议采用独立页面 / 路由与明确场景标识（名称待实现时确定），不复用 `mode: free` 承载作业。

| 边界 | 必须保持 |
| --- | --- |
| 入口与页面 | 原 FreeTalk 入口、页面流程与控制不加作业步骤、卡片或提醒；待办只在新场景入口展示 |
| 初始规划 | FreeTalk 继续按现有契约初始无正式目标；不因有作业而加载目标、TopicPack 或 HomeworkPlan |
| 逐轮行为 | FreeTalk 不催作业、不自动识别并切成作业、不借作业扩展持续练习权限 |
| 数据与依赖 | FreeTalk 不调用教师 / 作业 / 包服务；这些服务未配置、离线或失败不影响其准备、对话与小结 |
| 提示词与校验 | 教师目标、主题边界与新多目标契约只在新场景编译；FreeTalk 默认提示词、校验和预算不因本需求改变 |
| 状态与证据 | 任务 / 计划 / 报告按场景、学生、作业、尝试隔离；FreeTalk 内容不追认成作业或流入教师报告 |
| 复用基础能力 | 可复用现有语音适配、网关基础设施、采音、播放、字幕、拼音、调速及授权资料端口；共享代码仍须按场景约束并回归 |
| 切换 | 学生显式离开当前场景再进入另一入口；收束采音、取消在途工作及清理输出后创建新会话，不就地改 free 语义 |

教师主题是新作业场景的内容范围；学生保留拒绝、结束和退出权。暂停目标保留作业主题；想完全换题时可离开作业，原 FreeTalk 的自由选题规则独立保持。

验收至少包含：相同 FreeTalk 输入与配置的新旧契约对照；新服务关闭 / 故障时 FreeTalk 可用；未选新入口时作业 / 主题读取及生成调用数为零；FreeTalk 提示词无作业内容；换人、换场景及迟到结果不串状态；既有语音、字幕与小结回归通过。

## 7. 产品验证重点

前置规划要验证主题相关性、资料依据、目标适合性、任务具体性、支持与材料可用性、机会可观察性及教师修改负担。只换姓名 / 等级标签不应改变教学依据；改变真实需要应有合理响应。

作业执行要验证计划里的机会是否实际出现，报告要对照这些实际机会解释表现。三个阶段分别评估，包生成成功、计划通过字段校验均不证明学生完成或教学质量通过。

本次仅做源码 / 文档只读核对和本地需求文档更新。未运行原仓库模型、语音或浏览器测试；未改本仓库运行代码，也未改变原 FreeTalk 的功能与验收状态。
