# Free Talk 中泰语音输入：能力与接入分析

2026-10-29。用户明确 learner 主要会使用中文与泰语语音。本轮仅查代码、官方文档与已有实验记录，没有修改产品代码、配置或模型，没有新采集用户语音。

后续已按用户提供的截图与音色表补充[Vivi 2.0 多语种参数分析](free-talk-thai-vivi2-language-analysis.md)：当前已使用 Vivi 2.0；该音色表的新多语种参数用于独立 TTS，明确排除 S2S，不能由此认为当前麦克风泰语输入已经可用。

## 结论

泰语可以作为目标产品的语音输入，但**当前已接的豆包实时全双工链路不能视为已可靠支持泰语输入**。不能从能生成泰文和音频，推导出它能听懂泰语。profile 的泰语母语字段和中泰回复提示也不等于输入语种配置。

官方模型列表当前仍将端到端实时语音列为支持中文、英文；没有据此确认当前账户、模型 `1.2.6.1` 的泰语识别保证。[官方模型列表](https://docs.volcengine.com/docs/doubao-voice/model-list?lang=zh)。本次直接抓取该页只取得页面外壳，支持范围使用该官方页面的搜索索引正文交叉核对；没有将第三方转载作为依据。

## 本地链路核对

- 当前语音协议为 `seeduplex-1.2.6.1`，输入为单声道 16 kHz PCM，音频同时承担模型识别与原生语音对话输入。已审核 profile 的输入对象只配置音频格式，没有已启用的泰语识别语言选项。
- `capture-worklet.js` 与 `AudioIO` 发送麦克风 PCM，不按中文/泰语筛选声音。`SeeduplexProvider.text()` 及事件契约接受 Unicode 字符串；`hasSpeechText()` 使用 Unicode 字母/数字判断，泰文字母不会因为不是汉字而被当作空文本丢掉。
- 因而代码中没有发现专门过滤泰语的规则。更主要的限制落在 **M5 供应商语音识别能力/支持范围**；还没有用户此次实际会话的采集证据，不能将每一次未响应都断言为同一原因，短句、收音、噪声和原生判停仍可能影响表现。
- 2026-10-28 的作者泰语语音探索样本，ASR final 为四个汉字、零泰文字元，未匹配原文，等义也未核对；即使随后有中泰回复，仍不能算听懂泰语。记录见[原 Spike](free-talk-thai-support-spike.md)和[安全汇总](eval-results/2026-10-28-free-talk-thai-spike.json)。这是旧的单样本探索，不是今日真实使用复现或总体成功率。

## 独立 ASR 的可能路径

火山的独立大模型语音识别文档列有泰语 `th-TH`。但其参数表明确：指定 `audio.language` 和 `enable_auto_lang` 的多语种自动识别能力限于 `bigmodel_nostream` 流式输入模式；不能把这组参数直接移植到当前 Seeduplex 原生会话。双向流式/优化版与流式输入的支持范围需要分别确认，语言检测出 `speech_th` 也不等于该模式能输出泰语识别结果。[独立 ASR API](https://docs.volcengine.com/docs/doubao-voice/large-model-streaming-automatic-speech-recognition-api-1?lang=zh)、[模式功能对比](https://docs.volcengine.com/docs/doubao-voice/product-overview-22?lang=zh)。

文档说明流式输入可在结束包后返回结果；它不是同样的逐字双向实时体验。自动选出语种也不能直接证明一句话里中文、泰语交替混说的准确性。固定泰语模式同样不能保证同时识别中文。

若不能确认供应商原生全双工版本的泰语输入能力，较可控的候选为：**支持中文/泰语的独立 ASR → Agent 处理可靠转写 → 中泰回复与语音合成**。这是需要独立验证的 Free Talk 中泰链路，不能当成一行配置修复。继续复用当前 S2S 生成回复，也要先证明文本输入如何触发一轮回复；上下文写入 ACK 不能冒充生成已受控。单纯并行加 ASR 并改字幕，原 S2S 仍可能依据听错的音频先回答，不足以解决问题。

## 建议下一步 Spike

1. 分别覆盖纯中文、纯泰语、轮间自由切换、句内中泰混说。识别准确度、最终语义与说话结束到可用结果的延迟分开测。
2. 先核实当前账户的独立泰语 ASR 权限、可用模式和格式，再用作者固定音频及授权真人样本验证。不得从 TTS 的泰语能力推断 ASR。
3. 输入转写正确后，再测求助、换题、结束、继续、调速、拼音设置等中文/泰语意图。当前许多宿主控制规则以中英文为基础，正确泰文转写并不自动让所有泰语控制命令可用。
4. 接入时由中泰专用 M5 适配、M2 话轮编排管理录音切段、输入归属、单一回复来源、插话取消和迟到结果；M3 保持中文学习目的及中泰回复规则。原中英与教师助教继续走原链路。

本轮没有实现上述候选，也没有确认任何新服务已开通；先确认输入能力与延迟，再决定改造范围。
