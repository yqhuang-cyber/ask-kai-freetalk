# 口头结束：先总结，再自动关闭

> 来源：原 Ask Kai 仓库 [3e4422e](https://github.com/yqhuang-cyber/ask-kai/commit/3e4422e5ec85f45317a0a687fe949530c196c8ce)。下文保留原设计及原仓库历史实施记录，其中的真实调用、测试数量和三入口范围不代表本独立 FreeTalk POC 的新增验收。本仓库保留已有豆包退出信号、结束语及语言修复；当前适配范围与实际验证见[增强移植分析](freetalk-enhancement-port.md)。


2026-10-16。状态：收尾编排、规则小结、服务端记录与浏览器播放确认已实现；真实语音仅有限样本，完整设备及受控生成仍待验收。最初设计于 2026-10-15。用户要求：“就聊到这儿吧”等明确结束意图应主动结束，并在结束前总结这次对话里的知识点。适用于三个入口；保持独立 Mock HSKai、豆包实时全双工、attempted-only 和既有授权边界。

用户进一步明确：小结必须包含本次对话的目标、过程中实际涉及的知识点（包括词汇、表达方式等），并更新到服务端的本次对话记录。这次会话小结的写回属于已明确要求的流程，不再以旧“保存表达尝试”勾选框作为前置条件；学习能力／掌握状态不随小结自动更新。

## 设计前的问题（2026-10-15）

| 环节 | 当前代码行为 | 缺口 |
| --- | --- | --- |
| 意图与教学 | `natural-teaching.js` 识别 CLOSE，`TeachingSession.accept()` 设置 stage=closing 并暂停目标 | 教学状态没有驱动会话关闭 |
| 回复规则 | `NATURAL_TEACHING_INSTRUCTIONS` 明确禁止口头知识点复盘，要求告别后保留麦克风 | 与最新要求冲突，需版本化更新；同步检查 context compiler、Planner 和 fallback 的告别规则 |
| 网关 | `realtime.js` 在客户端 session.end、供应商关闭或异常时 finish | 没有“本次收尾回复播完 → 自动 finish”的控制流程 |
| 总结 | `TeachingSession.finalize()` 在结束时才生成最终总结并关闭学习采集 | 不能直接提前调用作为播报预览，否则后续事件和撤销无法正确处理 |
| 动态路径 | 跳过 `LearningSummary.recordFinal()`；动态卡片投影固定 recap 空数组 | 缺少实际交流回顾；只复制初始化目标不能补上本次知识点 |
| 播放 | Presentation 已区分收到、播放和字幕完成；网关有 playback.report 接收入口 | Web 未发送消费回执；供应商 response.done 不代表设备播完 |

相关既有缺口见 [free 工程审查 FC-09／10](free-conversation-engineering-review.md)。现有结束意图测试证明控制选择，不证明自动挂断。

## 用户体验与状态

正常口头结束：`active → preparing_close → presenting_close → awaiting_playback → finalizing_record → closed`。服务端维护独立 ClosingCoordinator，教学 stage 只供教学展示，不承担网络生命周期。finalizing_record 是有界的服务端记录更新，不继续占用麦克风，也不无限延长通话。

1. 仅对已接受、校验通过的 final 或经校验的明确语义结束提案启动收尾。partial 不执行挂断；翻译、引语、否定不能触发。补测“就聊到这儿吧”“那今天先到这里吧”等自然说法，不简单扩大关键词匹配。
2. 为收尾创建 closing_id，绑定 session_id、source_turn_id、source_event_id、输入版本和 summary_revision。立即取消后台旧规划，停止旧目标推进。重复告别保持幂等。
3. 从本会话实际记录生成有来源的小结快照。页面显示“正在总结，播完后结束”，保留立即结束入口；Kai 回顾重点后告别，不再提问或布置练习。口头默认选最有价值的 1～3 点，完整内容放卡片；按语言偏好提供必要英文，不逐项朗读拼音。
4. 收尾输出必须绑定本次 closing_id 和实际 response_id。仅匹配的回复完成后等待浏览器播放回执，不能取“下一个 response.done”或上一轮已完成回复作为收尾。
5. 浏览器报告本次音频排空且必要字幕展示结束，服务端校验归属、完成边界和状态仍有效，冻结最终小结并通过授权业务端口更新本次对话记录。浏览器先停止采音；服务端在写回收到回执或有界失败后执行一次正常 finish。浏览器释放播放资源与 WebSocket，保留本轮总结卡及实际保存状态。

明确“马上结束／不用总结”、点击结束按钮或离开页面优先立即清理，不强制听完。口头正常收尾期间保持全双工，允许打断；学生明确“等等，我还想问……”时撤销旧 closing_id、停止旧收尾音频，恢复交流但不自动恢复旧教学目标。单纯噪声或 ASR candidate 不撤销结束意图；确认插话时先停止旧播放，待有效 final 判断继续、重复结束或立即退出。

每阶段都设有界超时。超时或服务失败保留可用文字小结并结束，显示“语音小结未完成”，不记成正常播完，也不无限等待学生再说一句。具体时限通过合成边界测试和真实播报时长校准，不把任意固定延时当播放证据。

## 总结数据：同一来源供口头与卡片使用

新增非终结的 `summarySnapshot()`／SummaryBuilder；它不设置 closed、不清空状态、不保存学习记录。最终 finalize 复用快照的来源和版本，补齐实际结束结果。收尾播报自身不再被收集为本次新增教学知识，避免自我引用。

| 总结内容 | 允许来源 | 表述边界 |
| --- | --- | --- |
| 本次对话目标 | 同一已接受会话计划、目标实例及有来源的目标变更 | 展示初始目标／交流目的、会中调整和实际进展；目标本身不是成果。free 无教学目标时写明“自然交流”，不补造目标 |
| 聊了什么 | 本会话有效学生 final 与已完成、未取消的实际回复 | 话题／交流内容，不当作正式 KP 或学习成绩 |
| 词汇、表达方式与相关用法 | 本次实际讨论的词句、讲解／示范及其事件区间，必要时由可信资源核对语言解释 | 按词汇／表达／句式或用法分类，可附本次实际例句及获核对的释义。称“刚才说到／示范了”；未确认播放不能称“你听过／学会了” |
| 学生尝试 | 当前受支持的 PlanningObservations 或既有尝试规则 | 只称“尝试表达”；不推断正确、独立、掌握或发音 |
| 需要再练 | 实际困难／求助及来源；正式观察缺口单列 | 不因没说到、计划未完成或统计为零虚构弱项 |

每条保留 source_refs（session／turn／event，教师内容另有 response），只引用快照截止前的有效记录。候选由模型提取时，宿主核对引用、对应文本、说话者、取消状态及数量／长度；引用存在只证明出处，不能代替语言正确性或教学语义校准。资料、课程候选、初始计划和模型自述不能单独成为“这次学过”的依据。无知识点时允许只做交流回顾。

动态路径要把“记录交流内容”和“生成正式尝试”拆成独立操作：接上 recap 采集，不直接恢复 legacy recordFinal 的尝试规则，防止 free 的 unassessed 技能意外增加 attempted。扩展当前有限表达目录之外的摘要要有独立契约及校准；先支持有来源的重点，不能标为完整知识清单。会内有界记录／滚动摘要需覆盖较早内容，不能只靠 Planner 最近 12 条消息声称总结整场。

新增预览消息与总结版本，不能复用只接受一次最终包的 SummaryState.accept。卡片和口头使用同一 snapshot；用户继续后预览失效，重新收尾生成新 revision。撤权和安全限制继续清空相关学习展示。

### 目标和知识点的结构

小结的三部分共用同一个版本化数据对象：

- `objective`：conversation_purpose、initial_goal、goal_history、closing_goal、goal_progress 及 plan／resource／事件引用。goal_history 记录真实调整、暂停、停止；明确区分学生主动暂停与系统为收尾而暂停。CLOSE 触发前先捕获目标状态，避免收尾把目标一律改成 paused 后误写“学生放弃练习”。完成度没有足够证据时保持 unverified。
- `knowledge_points`：本次实际涉及的词汇、表达方式、句式或用法。每项有 type、text、简要 meaning_or_usage、可选实际 example、occurrence（discussed／teacher_demonstrated／student_attempted）及 source_refs；释义或例句不能依据主题凭空补齐。库外的自然交流知识项可有本会话局部 ID，kp_id 允许为空，不为保存而伪造正式课程 KP。数量裁剪及覆盖不足必须标记。
- `conversation_recap`：实际交流话题与过程摘要，补足没有正式教学目标或知识点的会话。目标和知识点两栏在页面始终有明确状态：可以是无预设教学目标、无可核验知识项或记录不足，不能用空白让用户猜测。

口头回顾要交代本次目标／交流目的，再选关键知识点，随后告别；完整卡片与服务端保存全部经校验的有界条目及来源。三处允许不同展示长度，但不能各自生成相互矛盾的小结。

## 服务端本次对话记录

当前 `learning-record-v1/v2` 只允许 session／plan／resource／observations／outcome 等固定字段，Mock append 按 owner＋learner＋session 去重且拒绝不同正文覆盖。它既没有完整小结字段，也没有独立会话详情读回接口。不能直接向旧 append 塞入小结或把知识项伪装成 attempted。

新增独立的 ConversationRecordPort／版本化对话记录契约，落在本地 Mock HSKai 的授权业务边界，保留旧尝试接口兼容。拟定职责如下；具体路由在实施时定义，不冒充已存在的接口：

1. 会话创建时服务端将签发的 session_id 绑定 owner／learner／入口与已接受目标版本。保存和读取均从授权身份确定 owner／learner，不能信任浏览器或模型传入的身份，也不能向任意 session_id 写记录。
2. 最终更新携带 session_id、schema_version、summary_revision／hash、objective、knowledge_points、conversation_recap、已有可验证 observations 引用，以及 ended_at／outcome／end_reason／summary_delivery。summary_delivery 区分语音完成、被跳过和未完成；无音频完整播放不能伪装成已播完。服务端存储时间和归属由服务端生成。
3. 正常收尾自动写回本次记录，与本次卡片使用同一最终 revision；立即退出也生成可用的最小小结并按真实结果写回，摘要不足或异常则记录 partial。退出不强迫播放，网络失败不伪装记录完整；撤权后停止写入，安全限制按既有隔离路径处理。
4. 同一记录按 owner＋learner＋session 唯一；同 revision、同 hash 重试返回同一回执，旧 revision 不覆盖新版本，同 revision 不同正文报冲突。预览不作为最终记录；学生继续后废弃旧 closing_id，旧请求／回执不得覆盖后续小结。普通流程只提交最终版本，失败重试复用相同正文和幂等键。
5. 返回绑定 session_id、summary_revision／hash 的 accepted／pending／failed 状态与服务端 record_revision。仅 accepted 可显示“本次对话已保存”；超时保留“保存状态未确认”，明确拒绝或失败显示“未保存”。重试先核对服务端已有版本，有限重试不重复新增历史。
6. 提供授权的会话详情读回及历史摘要投影；以读回的目标、词汇／表达、小结版本验证服务端确实更新。历史应称“会话记录／涉及的内容”，零 observations 不能显示“已保存表达尝试”。用于下一会话时按既有三类资料与来源边界读取，不直接变成已掌握知识。

本次用户要求已授权会话小结的自动保存。身份、scope 与授权有效期检查继续保留；缺少服务端写权限时展示未保存，不绕过授权。旧勾选框不再控制会话小结；如保留额外学习观察写回，应单独说明其用途并避免与会话记录重复记账。保存字段不含原始音频、完整逐字稿、密钥或私有模型推理；读取／删除／导出范围需覆盖新增记录。

当前 POC 后端为本地 mock，既有记录仅进程内存。本项要求首先保证同一服务端会话可写入、读回并在历史中关联；如沿用内存必须在 UI 和回执标明重启重置，不能称持久保存。磁盘持久化另需明确实现和重启恢复测试；此次设计不宣称已接入外部 HSKai 或生产数据库。

## 豆包执行：先验证收尾这一段的控制能力

当前 next_turn_advisory 允许豆包在 final 和后台决策之前自动生成。仅在 CLOSE 后 updateContext，即使收到 ACK，也不能保证该次语音采用新小结；等待浏览器播放同样不能补上生成控制。因此“改提示词＋遇到 done 挂断”不能作为完整验收方案。

建议保留普通交流全双工，单独验证收尾阶段的受控执行：让已核验的供应商能力在播报前取得宿主校验的小结，再输出一次总结与告别。优先沿用已有 Function Calling 实验做定向验证：工具只能提出收尾／读取本会话摘要，服务端验证结束意图与来源后返回小结；工具调用本身没有关闭权限。还需实测普通口头结束是否可靠触发、先输出后调用、取消、迟到及工具失败等情形。已有 probe 的成功样本不证明该流程已可用。

这是一项待验证的执行方案，不在设计中假设每轮强制调用可用，不据 PRD 或内部契约发明 wire 事件。若当前 provider 无法可靠执行该段，自动关闭和文字卡可独立完成工程验证，口头总结必须标为尚未保证；不能宣称完整需求通过，也不默认切换独立 ASR／TTS。正文生成方案确定后再核验实际协议与账号能力。

## 内部契约与竞态

以下是拟新增的 Web／网关内部消息，均不是供应商 wire 事件：

- `session.closing`：closing_id、source_turn_id、summary_revision、phase，让 Web 进入收尾展示。
- `teaching.summary.preview`：同会话版本化 snapshot，只作本次预览。
- 收尾输出归属：必须显式绑定 closing_id、response_id、source_turn_id，不能按文本“再见”猜测完成。
- 播放完成回执：扩展独立收尾回执或 playback.report，带 closing_id、response_id、summary_revision 与实际播放状态。服务端只接收已转发且完整结束的当前收尾回复；重复、提前、外会话、已取消和旧版本回执不触发关闭。

浏览器按音频输出时钟与 Presentation 完成状态发回执，不只监听网络 done 或音频片段之间暂时的 audio.drained。回执是客户端播放状态报告，不能证明学生听到／理解，也不升级学习证据。无音频、播放暂停、静音等要记录各自结果，不能伪装音频播放成功。

服务端 finish 保持幂等，退出后清理收尾 timer、规划和取消／更新等待，隔离所有旧输出。会话小结按上述最新要求自动写回；区分对话运输关闭与服务端记录完成，在授权仍有效时有界完成已冻结最终记录的写回，撤权立即取消。收尾撤销、失败或断开不允许迟到预览冒充新的最终版本，不能另建绕过身份／scope 的写回路径。
