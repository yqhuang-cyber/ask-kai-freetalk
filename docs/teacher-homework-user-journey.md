# AskKai 主题对话作业：User Journey

日期：2026-10-26（Asia/Shanghai） · v0.2 · 状态：设计示例，尚未实施。

配套：[需求分析](teacher-assistant-requirements-analysis.md) · [PRD v0.2](prd/teacher-assigned-conversation-homework-prd-v0.2.md) · [前置规划与教学包](teacher-homework-planning-design.md)。人物、任务、对话及报告均为作者编写的合成示例，不是真实运行结果。

本旅程仅描述独立“教师助教作业主题对话”新场景。原 FreeTalk 的入口、页面、初始无目标规划及交流流程保持现状，不加载或催促作业。

各旅程节点对应的模块与交付顺序见[技术方案](teacher-assistant-technical-design.md)及[tasking 的 Journey 追踪](teacher-assistant-tasking.md#5-user-journey-到切片的追踪)，尚未实施。

当前优先交付[最小 Demo 五步旅程](teacher-assistant-minimal-demo-tasking.md)：一位教师确认预置计划、发布给一位学生，学生与 Kai 对话并明确提交，双方看本次事实反馈。本文的 AI 前置准备、四人分层及完整教师审阅是后续角色完善范围，不能记为 Demo 已具备。

## 1. 端到端旅程

**教师确定主题与课后方向 → AI 准备主题资源 → 前置 Planner 形成每人的内容 / 目标 / 支持 / 观察计划 → 教师批量预览发布 → 学生从独立作业入口选任务 → Kai 按计划进行主题对话 → 学生提交 → 按同一计划分析 → 双端反馈 → 教师安排下一次教学。**

发布前教师做方向判断、采用或修改 AI 计划；完成后结合证据决定怎样跟进。AI 承担内容 / 目标的具体设计工作，教师不必逐人手写教案。学生在练习中保留选择、求助、暂停及结束权。

## 2. 教师 Journey

| 阶段 | 教师想完成的事 | 页面 / 操作 | 系统与 Kai 的职责 | 成功信号 / 需避免的摩擦 |
| --- | --- | --- | --- | --- |
| 课后安排 | 把课堂内容延伸到口语使用 | 在“我的学生”选中全部或部分学生，创建对话作业 | 显示已授权名单及相关学习摘要 | 名单清楚，不需要重新输入每人的基础资料 |
| 描述意图 | 说明这次练什么 | 输入主题、剧情或目标表达；补充课堂所学和期望 | 区分内容、情境、表达目标及限制 | 支持自然语言草稿，不强迫先写复杂教案 |
| AI 前置准备 | 把主题变成可练习内容 | 查看资源准备、按人规划及校验进度，可取消或修改方向 | 复用 / 生成准入主题资源，再按授权资料形成私人计划；生成失败保留草稿 | 不要求教师先逐项写目标；不把等待转嫁给学生开聊 |
| 预览计划 | 任务对这些学生是否合适？ | 看共同方向、个人内容 / 目标 / 支持差异及风险；批量采用，按需修改 | 展示具体表达机会、材料、观察标准及依据，标先修 / 评估未知 | 只处理需要变化的部分，等级不替代教学判断 |
| 预览发布 | 确认学生会看到什么、Kai 会做什么 | 设置截止、核心 / 选做、支持策略；预览后发布 | 校验对象、必填项、目标可执行性；固定版本 | 一次操作分配给四人，每人只看到自己的要求 |
| 等待练习 | 了解是否有人需要帮助 | 在作业详情看未开始、进行中、待提交、已提交、迟交及报告状态 | 显示产品内待办；独立显示技术异常 | 未提交与未达标不混为一谈 |
| 查看结果 | 快速识别需要自己介入的人 | 看班级概览，再展开个人目标证据卡 | 生成报告、AI 暂评及覆盖限制，标出 Kai 执行缺口 | 不必为了理解一个等级而重听所有对话 |
| 审阅反馈 | 修正误判、补充教学意见 | 调整教师专属等级、写评语、标记已审阅 | 保留修订理由与版本；向学生发送获准的事实反馈 / 评语 | 学生数据中无等级；不因老师尚未审阅而阻塞基础反馈 |
| 准备下节课 | 把结果变为教学行动 | 查看共同练习建议、个人建议，创建下一份草稿 | 建议引用实际目标证据及覆盖人数 | 能区分共性问题、个别困难及证据不足 |

### 教师的关键判断

发布时判断“这个任务是否值得练”；读报告时判断“这份证据能否支持我的下一步安排”。因此教师页面应优先呈现目标和证据，而不是堆叠聊天日志。

## 3. 学生 Journey

| 阶段 | 学生的疑问 | 页面 / Kai 的体验 | 系统职责 | 成功信号 / 需避免的摩擦 |
| --- | --- | --- | --- | --- |
| 进入作业场景 | 老师安排了什么？ | 从独立“老师的作业”入口看到任务卡、主题、要求和明确截止 | 只读当前 learner 的任务；不自动开麦；原 FreeTalk 页面不变 | 进入新场景才能看待办，原自由聊天仍按原流程使用 |
| 选择作业 | 老师希望我做到什么？ | 用短句展示本人的目标、场景、预计时长和反馈说明 | 绑定本人的目标版本；明确老师可查看作业表现 | 看懂任务，不需要理解后台术语 |
| 准备开始 | 我需要先准备什么？ | 看已准备的菜单 / 角色背景、调整语速和拼音，再点开始 | 只校验已发布计划及授权 / 时效，准备执行；不生成包或重新改选核心目标 | 准备完成不冒充语音连接成功，也不在此才开始写教学包 |
| 进入角色 | 我该怎么开口？ | Kai 简短说明角色并给自然入口，如“你好，想吃点什么？” | 使用已确认计划；开场本身不算学生成果 | 学生很快获得自己说话的机会 |
| 进行练习 | 卡住了怎么办？ | 可说慢一点、没听懂、给点提示；Kai 接住内容，按需支持 | 记录实际提示及表达机会，隔离旧轮次事件 | 求助不会被惩罚成低分，亦不伪装成独立完成 |
| 应对变化 | 我还能怎样表达？ | 根据任务遇到确认、替代选择或误会；无固定逐句脚本 | 只使用本人的核心要求；选做难点可跳过 | 变化服务于目标，不为了“凑轮次”延长对话 |
| 收尾 | 我已经做完了吗？ | Kai 概括实际练习内容，提供“结束并提交”“暂存练习”“继续练习” | 区分结束、保存和明确提交；立即结束随时可用 | 无需取得 A 或完成全部目标才允许提交 |
| 看反馈 | 我做到了什么，下次练什么？ | 先显示本次小结；分析后补充具体表现和一两个建议 | 无 A/B/C/D、分数、排名；证据不足明确说明 | 反馈具体、有来源、不会只有泛泛鼓励 |
| 再练 / 反馈更正 | 我想试一次，或这条反馈不准确 | 可重练、选一次练习提交、提出反馈疑问 | 新尝试不覆盖旧记录；最新明确提交成为当前结果 | 不自动取最高等级，也不自动发新作业 |

## 4. Kai 在旅程中的工作 Journey

| 时点 | 需要知道什么 | 可以决定什么 | 需要交回教师或系统决定什么 |
| --- | --- | --- | --- |
| 教师布置阶段的 AI 准备 | 教师主题、方向、允许资源；私人规划还读取各学生授权资料 | 准备主题情境与候选机会，形成每人的目标 / 内容 / 支持 / 观察草案 | 教师采用 / 修改后发布；不得自行换主题或把私人资料放进共享包 |
| 学生启动 | 已发布作业、本人计划、支持策略、相关资料时效 | 在计划内选择适合的开场与材料切入 | 不生成包、改核心目标或引用另一学生的任务 |
| 对话 | 学生刚说的内容、有效前文、已发生的提示、尚未获得机会的目标 | 回应、澄清、追问、给局部帮助、建议收尾 | 不能把学生拒绝或技术中断当能力失败 |
| 收尾 | 实际练过什么、哪些证据仍不完整 | 给保守小结，提示提交或继续的选项 | 不能口头宣布教师专属等级或谎称已提交成功 |
| 会后 | 固定任务版本、有效证据和覆盖限制 | 生成反馈草稿、教师专属暂评与后续建议 | 系统验证来源；教师审阅评级及决定后续教学 |

## 5. 主场景：一位教师给四位学生布置点餐练习

### 5.1 教师发布

演示教师“林老师”完成课堂教学后，选择 Alex、Maya、Leo、Nina，输入：

> 练习在餐厅点餐。请根据各自的中文表达能力，完成点单并回应店员。课堂已经练过的内容不要全部重教。

系统先复用或后台准备“点餐”的准入主题资源，包括角色、候选情境、表达机会与材料；再结合四人的授权资料形成私人作业计划。需求分析里的四种任务仅是合理候选示例，实际不能按姓名 / HSK 固定映射。

预览同时显示各人的具体目标、关键机会、提示策略、观察标准与依据。林老师批量采用，只修改不合适或缺先修的部分。每人建议保留 1～3 项核心要求，复杂协商另设选做挑战。生成器若只能提供受限情境 / 开场，菜单、例句和相关新目标须完成相应准入，不能假装已有完整教学包。

林老师设置演示截止为 **2026 年 10 月 27 日 23:59，Asia/Shanghai**。这里刻意用完整时间示例，不能把用户口头说的“十月二十七号之前”直接解释为包含 27 日全天。真实创建时应显示可编辑的具体日期、时间和时区。

发布预览同时展示学生任务卡和 Kai 执行说明，并固定 brief、资源包、个人计划和评价量表版本。林老师点“发布给 4 位学生”后，分别生成四条分配记录；学生开聊时不再临时生成包。资源校验与发布由系统处理，不要求教师额外操作全局主题管理台。

### 5.2 Maya 选择并练习

Maya 从独立作业入口看到的任务卡（原 FreeTalk 页面不增加该卡片）：

> 点餐练习 · 林老师布置。试着说明你的口味及原因；如果想点的菜没有了，换一道并确认订单。你可以随时求助或结束。提交后，你会获得具体反馈，老师可以查看本次表现。

以下仅展示若干关键片段，不是完整脚本，也不是实际证据：

| 对话片段 | 教学机会 | 会后应如何理解 |
| --- | --- | --- |
| Kai：“你好，今天想吃点什么？”Maya：“我想要一份面，不要太辣，因为我不太能吃辣。” | 表达偏好和原因 | 存在符合目标的学生表达候选，需核对实际前文和来源 |
| Kai：“这份面卖完了，你想换成米饭还是饺子？”Maya：“我换……怎么说？” | 应对替代选择，学生主动求助 | 说明此处需要帮助，不推断她整体水平不足 |
| Kai：“可以先说‘那我换成……’。”Maya：“那我换成饺子。请问有不辣的吗？” | 提示下继续完成沟通 | 记录提示后输出；不标成独立使用 |
| Kai：“可以，给你一份不辣的饺子，对吗？”Maya：“对，谢谢。” | 确认订单 | 只证明本次对话节点的表现，不等于已掌握点餐能力 |

真实运行时，如果无法确认提示与学生说话的先后，支持程度标为未知，不照抄本示例的因果解释。

### 5.3 学生明确提交

Maya 选择“结束并提交”。系统先结束采音并收束会话，再确认提交记录；重复点击不生成两次提交。页面显示“已提交，反馈分析中”。若网络断开无法确认，显示“提交状态待确认”，恢复后查询同一条记录。

分析失败不会撤销已成功的提交；学生可稍后重试报告生成。没有完成所有目标也可提交，报告据实反映本次练习情况。

### 5.4 学生反馈

在证据校验通过后，Maya 获得：

> 你练习了点餐、说明口味和更换菜品。你把“不太能吃辣”的原因说清楚了。更换菜品时，你借助了一句提示，然后继续问了口味。下次可以试着先自己说“那我换成……”，再加上你的要求。

这份学生反馈没有等级。若某条观察不可靠，删去该结论或写明还不能判断；不会为了使报告完整而编造错误。

### 5.5 教师报告

林老师看到同一尝试的目标表、实际帮助、证据卡和教师专属 AI 暂评。只有独立判断和目标语义都经过验证，且覆盖充分时，才可按量表给出例如 B 的暂评；否则显示“待复核”，不能凭上面的示例直接评分。

教师建议可以是：“下一次先安排一个新的售罄情境，暂不先给完整句框，观察是否能自行提出替代品。”教师可接受建议、写自己的评语，或创建下一份草稿。

班级概览按每人的分层目标汇总，A/B/C/D 不用来比较四人的整体中文能力。

## 6. 另外两类任务的 Journey 差异

| 项目 | 昆虫主题 | 目标句式 / 固定剧情 |
| --- | --- | --- |
| 教师输入重点 | 聊昆虫的什么：描述、比较、经历、观点？哪些内容已教？ | 是练“再也不……”这个表达，还是某个指定故事？ |
| 建议的语言任务 | 描述一只虫子、讲一次经历，或说明喜欢 / 害怕的原因 | 给出符合语义的使用情境；剧情可设一个改变决定的事件 |
| 对话方式 | 跟随学生选择的虫子与内容追问 | 保留角色与关键事件，允许自由措辞 |
| 评价重点 | 中文表达和沟通；科学知识是否计入须提前说明 | 表达是否适合语境；只提到字符串不算完成 |
| 特殊边界 | 使用教师确认的内容材料，学生不必披露真实隐私经历 | 可讲虚构故事；不要求学生作真实承诺，也不强行引导负面经历 |

## 7. 关键分支 Journey

| 分支 | 学生体验 | 教师看到的结果 | 系统保证 |
| --- | --- | --- | --- |
| 有多份待办 | 在作业入口按截止时间展示，自己选择 | 未选任务保持原状态 | 待办不进入原 FreeTalk 页面或提示词；不串任务 |
| 学生拒绝或想换题 | 可暂停目标并保留主题；也可结束作业、显式进入原 FreeTalk | 本次中止 / 待提交，已发生事实单独保留 | 拒绝不自动判 D；离开后不在 FreeTalk 追作业 |
| 教师端生成 / 按人规划失败 | 学生不会看到可启动的无效任务 | 草稿中按人显示失败；教师重试 / 修改，或明确改选可发布对象 | 不静默漏发或降级成其他主题；学生端不触发补包 |
| 开始前资料变化 | 支持偏好可更新；目标冲突时说明需重新准备 / 教师调整 | 原计划与冲突项可辨认 | 不偷偷改正式目标；原 FreeTalk 不受此任务阻塞 |
| 新业务服务离线 | 作业入口显示不可用；原 FreeTalk 可继续按原流程使用 | 对应服务异常 | FreeTalk 对新服务零依赖 |
| 网络中断 | 停止采集，显示恢复或重试；提交状态可查询 | 技术中断及覆盖不足 | 新会话不伪装延续原 provider 会话；不虚构后半场 |
| Kai 没给练习机会 | 学生可以提交已完成部分 | 对应目标“未获得有效机会”，需要检查 AI 执行 | 不把缺少机会归为学生不会 |
| 目标明显过难 | 可以求助、结束、反馈“不适合我” | 目标适配疑问及证据 | Kai 可降低支持难度，不能偷偷换掉正式标准 |
| 到截止时间仍在练习 | 提示截止已过，可继续；按提交时刻标迟交 | 迟交与表现分别显示 | 截止不强制切断麦克风，不因迟交降等级 |
| 教师修改已发布任务 | 开始前看版本变化；已开始沿用固定计划 | 报告明确旧 / 新版本及分配对象 | 修改标准不追溯重评旧尝试 |
| 教师撤回任务或权限失效 | 立即停止此任务的采集及新提交，显示可理解原因 | 撤回 / 权限变更状态 | 阻止迟到分析写回；安全处置沿用既有规则 |
| 再练后想提交另一场 | 明确选择本次提交，旧尝试仍可辨认 | 当前提交与历史分别展示 | 不取最高分，不拼接不同场次伪造一次独立表现 |
| 报告不准确 | 提交简短反馈疑问 | 教师看到待核对项，可修订 | 学生不能读到教师等级字段；修订不静默覆盖 |

## 8. 页面信息结构

| 页面 | 核心问题 | 必要内容 |
| --- | --- | --- |
| 教师首页 | 我现在需要处理什么？ | 当前任务、提交进度、待审阅报告、技术异常 |
| 我的学生 | 我能给谁布置？ | 授权班组与学习摘要；POC 明示模拟关系 |
| 新建 / 编辑作业 | 主题是什么，AI 准备得是否合适？ | 教师方向与对象、前置准备进度、按人内容 / 目标 / 支持摘要、差异项、截止及批量预览发布 |
| 教师作业详情 | 谁做了，哪些地方需要跟进？ | 状态分布、各人的任务目标、报告与等级、共性建议 |
| 教师个人报告 | 这次表现如何，凭什么判断？ | 目标证据、支持范围、覆盖限制、AI 暂评、教师修订与建议 |
| 学生独立作业入口 | 我要选哪一项作业？ | 我的待办、历史反馈；原 FreeTalk 入口 / 页面独立保持现状 |
| 学生任务与对话 | 这次要求是什么，我能怎么练？ | 本人目标、角色背景、开始与语音控制、求助、结束和提交 |
| 学生反馈 | 做到了什么，接下来练什么？ | 本次表现事实、少量建议、教师评语、再练与反馈疑问入口 |

## 9. 走查时需要验证的问题

1. 教师能否只用一句意图和少量修改就完成一份可执行的作业？
2. 学生能否在开口前说清本次要做的事情？
3. 对话是否跟随回答，同时给到核心目标足够的表达机会？
4. 在帮助过多、断线、拒绝和未覆盖时，报告是否仍然诚实、清楚？
5. 教师能否从报告确定一个具体的下一步教学动作？
6. 学生反馈是否有帮助，且所有入口都不暴露教师专属等级？
7. 教师是否只给主题与少量要求即可获得完整的可执行草案，而非仍需逐人补写教案？
8. 学生开聊时是否只消费已发布计划，且关闭新服务后原 FreeTalk 的页面、规划和对话仍保持原样？
