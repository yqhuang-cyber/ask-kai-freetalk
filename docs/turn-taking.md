2026-10-14 后续设计：[学习者话轮与 AI 提前开口控制](turn-taking-control-design.md)，优先核验供应商判停参数与等待指令，网关话轮许可与声学活动方案保留为条件性后续；尚未实施，不改变本文所述现有行为。

## 已修复的代码路径

| 情况 | 当前处理 |
| --- | --- |
| 仅 ASR started／标点／单独“嗯、啊、呃”等犹豫声 | 不直接发取消。附件说明 started 是“识别首字”，不能当作真实 VAD 起点 |
| 学生新话轮出现有内容的识别文字 | 确认候选绑定的旧回复，立即本地停播、清字幕并隔离旧输出；一字目标／数字／“停”仍可确认 |
| 同一话轮的迟到 ASR 或迟到候选确认 | 不将旧候选重新绑定到正在播放的新回复 |
| Kai 输出早于已知学生话轮的 final | 暂存该回复的文字／音频，等待这个话轮的最终识别 |
| final 刚到，学生接着表达 | final 后暂留 350ms 候选观察窗口；期间新的有效话轮会丢弃／取消旧回复 |
| 点击“打断 Kai” | 浏览器立即清队列；网关立即隔离／丢弃等待输出。无需等待文本确认 |
| 上下文 update 尚未 ACK 时打断 | 本地立即停，专用适配器排队 cancel；update ACK 后才派发，不因控制重叠直接报错 |
| 重复打断 | 同一未确认回复只派发一次，不重新计时 |
| 排队期间旧回复完成或出现新回复 | 跳过旧 cancel，保持新回复；不伪造供应商 ACK |

使用专用 Seeduplex 适配器时，上述规则自动启用，无需新密钥或客户端 SDK。已审核的通用 speech-start 映射保留其现有语义，不擅自把其事件改解释为 ASR 候选。

`kai-turn-v1` 指令会随初始教学提示及后续上下文更新保留：学生短暂停顿／找词时等待，不代答或催促。指令不是供应商时序保证。

## 控制归属与等待边界

供应商 `response.cancel` 是无目标 ID 的简单请求，因此每个排队取消必须捕获旧回复。派发前若该回复已经完成或被替换，跳过请求；否则可能误取消新回复。控制队列最多 32 项；原有 session/event/turn/reply 归属校验和重复 wire event ID 隔离继续生效。

取消 ACK 的 1500ms 超时从实际 wire 派发开始，排队不消耗这个时间。上下文更新 ACK 的默认等待是 8000ms，给真实豆包的 `session.updated` 留出时间；测试仍可传入更短的 `contextTimeoutMs`。缺失／不匹配 ACK、断连和错误继续安全结束，不默默当成功。跳过旧取消只表示本地停止已完成，不能当成实际 cancel ACK。口头结束一旦开始，后续计划不再抢 `session.update`。收束本身会送一次带词汇和表达的更新；若当时已有更新在等确认，就等这次确认后再送收束。确认超时不再把整段对话报成上下文失败，而是保存并关闭。

输出等待绑定 question 对应的 turn，仅用于已观测到的学生话轮；无学生 ASR 的开场输出不强加等待。350ms 是首个待校准的呈现缓冲，并非“学生必须停顿 350ms”，也不是完整静音判停策略。等待 final 最多 5s；最多暂存 256 个包／262144 字节，超出或缺少 final 时结束并丢弃缓冲。final 后的窗口不计入等待 final 的超时。打断、替换、安全限制和结束都会清理缓冲及计时器。

只在会话内存中短暂保留待呈现文本／音频，不写文件、不上传诊断，不持久化学习者原始数据。麦克风仍按原节奏持续上传；不做“老师说话时关麦”、不填充假音频、不以本地音量检测替代真实 VAD。回复长度和播放同步字幕由 Task 04／06 继续处理。

## 供应商依据与未解决边界

附件 PDF 的 ASR 事件表说明 started 是识别首字，completed 是模型判定说话结束；cancel／updated ACK 按原专用适配器审核政策绑定。

本次已读[全双工接入必读](https://docs.volcengine.com/docs/DoubaoVoice/access-mustread?lang=zh)。[旧端到端 API](https://docs.volcengine.com/docs/DoubaoVoice/End-to-endreal-timespeechlargemodelAPIaccessdocument?lang=zh)和 RTC 方案描述过 `end_smooth_window_ms`／`enable_custom_vad`，但附件的当前全双工字段表没有给出该型号的判停效果说明。本项不把其他协议的参数默认为当前模型已经支持，保留原有审核配置。供应商自主说话策略仍需实际账号核验；呈现等待不能强制模型重新生成已经提前生成的回答。

非空识别文字仍可能来自扬声器回声或错误识别，文本确认不等于确认真人来源。单独犹豫声的过滤是保守的本地规则，真实重复词、弱声和不同口音需校准；不以“与老师文本相同”直接判回声，以免误伤初学者跟读。设备 AEC 请求和实际设置继续记录，耳机／扬声器必须分别测。模型先输出、后 ASR 文字的真实事件顺序也需测试，不能由合成数据推断。

## 诊断与本地验收

`/?diagnostics=1` 中新增候选／确认、呈现等待／释放／丢弃、取消实际派发／跳过／重复事件。`session.config` 记录 `grace_ms` 和 `turn_wait_ms`。报告只导出白名单数值／布尔／枚举及匿名引用；`cancel.ack.ack_ms` 是实际派发到 ACK，`cancel.sent.elapsed_ms` 是本地请求到派发等待。两者均不是实际人声到停播的延迟。

| 场景 | 操作与观察 |
| --- | --- |
| E02 短停顿 | “我喜欢……足球”；观察是否在继续表达前开口，以及 held／discarded／released |
| E03 思考 | 留较长思考停顿再继续；观察等待自然性和供应商 final 时机，勿以窗口值当验收结果 |
| E04 噪声／犹豫声 | 背景噪声、短“嗯”，再清楚说“等一下”；观察候选是否误确认、明确插话是否停播 |
| E05 回声 | 扬声器播放时自己不说话，再与耳机对比；任何自我打断仍记为缺陷 |
| E06 真插话 | Kai 说话中说“停”／“等一下”；检查旧声音清理、持续采音和正常续聊 |
| E07 取消竞态 | 连点打断、更新边界时插话；检查 sent／skipped／ignored，新回复不被旧确认清除 |

真实体验、设备源头延迟和供应商自主打断不能由自动测试证明。Task 10 将依据真实报告调整窗口或经核验的供应商配置。
