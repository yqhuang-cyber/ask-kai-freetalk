## 1. 交付目标与顺序

三个入口共用动态初始化；Mission／主题有基于学生情况的整体目标，自由聊天初始目标为空；每个有效完整话轮根据实际上下文规划下一步，再由可核验执行路径生成回复；执行与学习观察进入下一轮，并在获准后形成跨会话记录。

现有普通 Web 验收保留，但不能直接证明新规划路径合格。原收尾 Task05／06 编号继续有效；以下使用独立 DP 编号，不冒称旧任务已覆盖。

主要依赖：DP-00 → DP-01 → DP-02 → DP-03 → DP-04；DP-05 可在接口契约明确后提前核验语音路径；DP-06 依赖 DP-04 与 DP-05；DP-07 依赖 DP-06；DP-08 依赖 DP-03／06／07；DP-09 可逐步建设，最终 DP-10 完成真实验收。某项工程实现不等于整体动态规划验收。

每项提交需写清输入契约版本、实际验证、未验证项与回滚路径。运行代码／接口契约改动执行仓库要求的 `npm run verify` 与 `npm run replay`，再做受影响浏览器或真实检查；实际结果见本轮验证报告，不能自动把原设计验收项标为完成。

## 2. 逐项需要冻结的决策

| 决策点 | 设计默认 | 首次实施需确认的证据 |
| --- | --- | --- |
| 规划模型 | 统一 PlannerPort；初始化与逐轮不同契约，可同模型 | 结构化输出、延迟、取消、费用与可用权限；实时 Key 不默认复用 |
| 业务数据 | 本地 Mock 聚合三类上下文，真实后端只预留端口 | profile／KP／history schema、资源和来源版本 |
| 每轮模式 | 正常语义输入先 Planner、后受控生成；直接控制动作允许规则 | final 输入与执行归属、规则与语义评测 |
| 语音路线 | 先独立能力验证；未证实实时门控时使用可控组合设计 | 正确 Seeduplex 产品文档、账号真实控制事件／生成顺序；组合 ASR/TTS 权限 |
| 学习事实 | 来源绑定的限定情境观察；不引入自动永久掌握 | KP 语义规则、提示来源、部分播放处理与校准 |
| 计划预算 | 详细设计第 17 节为试点初值 | 目标设备 P50/P95、额外等待、取消与总成本 |
| 框架 | 无 Pi 迁移前置；可通过 PlannerPort 引入 | 确实需要工具循环／状态管理时单独评估，不扩大本轮范围 |

现有 Seeduplex 即时生成路径和本轮外部 Planner 控制目标存在真实时序差异，DP-05 是技术验证工作而非文档形式检查。若供应商能力或必要服务权限不足，DP-06 保留阻塞原因与可实施选项，不能以输出缓冲替代。

| 案例 | 入口／条件 | 检查点 |

| DP-C24 | 准备时更换入口、开始前版本变化 | 同学生／资源／revision 核对，旧结果不覆盖 |
| DP-C25 | Planner 超时、格式错误、资源不可用 | 有界处理、单独降级标记、不回固定课冒充动态 |
| DP-C26 | 生成失败、音频失败、部分播放 | 计划与实际结果分开；总结保留未知／partial |
| DP-C27 | 跨学生访问、撤权、迟到计划／写回 | 拒绝、不泄漏、不提交 |

确定性门槛必须全部通过；语义判定需独立校准，有合理多解和不可评标记。真实设备／模型结论与合成测试分开，不从合成标签推断成功率。

## 4. 验收报告模板

每个候选报告至少包含：

1. 当前 Agent commit、输入契约、Planner／生成器／语音版本、prompt／resource／policy／rubric／fixture 版本。
2. 初始化：读取了哪一版三类数据、何时接受整体计划、实际计划与同源页面／首轮结果。
3. 逐轮：当前输入、上一动作真实执行、TurnPlan／引用、接受或失效原因、受控生成调用顺序及实际回复。
4. 观察与总结：实际表达和提示来源、是否可评、记录候选及写回回执；未知与缺口。
5. 规划质量、执行遵循、原十维内容评分、实时体验、成本和降级分别汇总；列出完整分母与关键失败。
6. 测试种类和实际执行范围；未完成项、风险与回滚说明。任何未受控的自主回复不计入受控执行通过。

新主路径只有在 DP-05／06 和实际案例通过后，才能在 README“当前实现”中替换旧时序。全量旧评测可能主要为 free，不能独自证明 Mission／topic 的动态目标正确；必须补齐上述跨入口与成对样本。

## 5. 上线方式与范围控制

拟议开关分为 legacy / shadow / controlled，实施前定义清楚作用范围。legacy 是旧固定目标／自主生成，保留作对照；shadow 只在获准的离线或观测流程中产出计划，不改变用户回复；controlled 是新规划执行路径。用户页面不展示框架、plan hash 或技术选路。

影子规划需要模型调用授权与成本预算；本次设计交付没有启动这些调用。运行开关、外部服务凭据、mock fixture 加载及新候选工作流将在实施任务中单独添加。失败后不静默把 controlled 标成成功，不自动恢复已撤销目标或已取消执行。

最终提交边界是运行代码、mock 接口契约、受影响测试与事实状态文档。真实 HSKai 后台部署、生产数据库、专业发音评估、复杂长期掌握模型和完整 Pi 迁移另列，不作为这份 POC 的隐含工作。
