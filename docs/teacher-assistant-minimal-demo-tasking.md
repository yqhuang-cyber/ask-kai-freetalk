# 教师助教：最小可运行 Demo 实施计划 v0.1

日期：2026-10-26（Asia/Shanghai）。状态：G0 已通过，MD-01～MD-07 最小功能已实现；MD-08 工程及真实豆包浏览器链路通过，真人设备走查待验。

依据：[最小 Demo 服务蓝图](teacher-homework-minimal-service-blueprint.md)、用户“先完成最小 Demo、架构完整可扩展、再完善教师 / 学生 / Kai”的要求。关联：[技术方案 v0.2](teacher-assistant-technical-design.md)、[完整任务清单 v0.2](teacher-assistant-tasking.md)、[完整 PRD](prd/teacher-assigned-conversation-homework-prd-v0.2.md)。

## 1. 新的交付顺序

**G0 最小架构与隔离基线 → G-Demo 一条完整闭环 → 教师 / 学生 / Kai 三个视角逐步完善 → 完整能力与质量验收。**

不要求先完成原 G1 / G2。原 G1 包含 AI 教学包和四人个性化，超出这次最小 Demo；原 G2 只到对话，尚缺提交和双端报告。G-Demo 从原 G1～G3 抽取必要实现，并把一条真实语音与浏览器检查前移。

最小 Demo 的结束点：林老师确认一份预置点餐任务并发布给 Maya；Maya 进入独立作业场景，与 Kai 练习、结束并明确提交；学生反馈和教师报告读取同一次尝试的真实可用事实。新应用 / 服务未启动或失败时，原 FreeTalk 仍按原流程运行。

这里的“真实”分别说明：业务身份 / 授课关系为本地 Mock；发布、提交、报告关联在本地服务实际执行；可运行语音 Demo 使用已配置的真实 provider，不能用合成剧本冒充。演示操作者仍是模拟 learner，不宣称真实学生、正式教学效果或真人教师已审阅。

| 教师体验 | 确认主题 / 对象 / 截止、预览、发布、查看提交与报告 | 自然语言备课、计划修改、审阅、班级分析 |
| 学生体验 | 本人任务、开聊、求助 / 结束、明确提交、看反馈 | 多任务、重练历史、个性化支持、反馈疑问 |
| Kai | 根据已发布计划扮演服务员、自然回应、按需帮助、尊重结束 | 动态机会选择、逐轮 Planner、多目标调度和更多剧情 |
| 反馈 | 受限的有来源事实 + 模板建议；未知保持未知 | 通用语义分析、长期建议、教师专属暂评 |
| 页面 | 教师作业页 A、学生任务 / 反馈页 B、学生对话页 C、教师报告页 D | 扩展同一应用页面，不改 FreeTalk 首页 |
| 非目标 | 不做 AI 自动备课、多学生分层、通用抽取、A/B/C/D、发音诊断、教师完整工作台 | 对应完整 TA backlog，分阶段启用 |

Demo 不依赖外部 HSKai、云队列或新的语音服务。预置的是教学内容和计划；实际对话、提交与报告不能采用预写成功结果。学生没有按剧本说，反馈就必须反映实际观察或无法判断。

## 3. 架构从第一版保留什么

| 必须先落实的边界 | Demo 做到的程度 | 不要求提前实现的内容 |
| --- | --- | --- |
| 场景隔离 | 独立入口 / scenario / cookie / WS ticket；FreeTalk 零新增作业依赖 | 全局场景路由平台 |
| 身份与授权 | teacher / learner actor、显式授课关系、本人任务读取；模拟切换不作为权限判断 | 生产账号、机构 / 多教师协作 |
| 发布计划 | TopicPack / HomeworkPlan 同一正式 schema、来源 / hash / 版本、发布不可变 | AI 生成 / 校验后台控制台 |
| 会话与尝试 | Attempt / Session / Plan 归属清楚、取消与迟到隔离 | 跨断线无损恢复、多场最佳片段合并 |
| 提交 | 独立 Submission、幂等键、服务端回执；结束不等于提交 | 择次提交、多次趋势 / 复杂迟交管理 |
| 报告 | 固定 source fence，Report 与 Submission / Attempt / Plan 关联，双端白名单投影 | 自动评级、审阅 / 申诉完整工作流 |
| 持久化与后台 | 同一业务 repository / migration；发布、提交 / report job 事务；最小报告任务可重试 | 全类型生成 Worker、通用任务编排 / 分布式部署 |
| 数据边界 | 有界最小证据、无默认原音 / 整场逐字稿归档、基本授权撤销 / 清理及迟到写入拒绝 | 全部运营治理界面、批量导出与复杂保留策略 |

SQLite 业务服务及应用组合沿完整方案，表只按切片迁移创建必要部分；不先建所有未来表。列表与关系用通用 ID / 集合建模，当前部署能力限制为一个接收人；业务代码不写 `if learner == Maya`。后续增加学生、主题、计划来源是能力扩展，不重定义发布 / 提交 / 报告的含义。

### 3.1 可替换能力的最小端口

以下是职责接口，不要求建设通用插件框架：

- `PlanSource.prepare(brief, learnerContext)`：Demo 的 PresetPlanSource 返回经过确认、来源为 authored_fixture 的标准计划；后续 AI 备课适配器返回相同计划契约。预置实现不得标为 llm_generated。
- `PublishedPlanReader.read(identity, learnerAssignmentId)`：runtime 只消费已发布计划，与计划如何生产无关。
- `HomeworkConversationController`：同一 controller / transport 接口承载固定任务；后续注入动态 TurnPlanner，不新增 free 兼容模式。
- `EvidenceRecorder`：记录有效轮次、输出 / 帮助范围、覆盖未知及必要引用；后续异步语义抽取消费同一证据契约。
- `ReportAnalyzer.analyze(plan, evidenceSnapshot)`：Demo 的有限规则 / 模板实现返回标准事实、建议与 unknown；后续模型分析器仍提供可校验来源。
- `HomeworkPort` / repository：权威授权、发布、提交及结果存取的边界不随 UI 或模型变化。

Demo 阶段不实现 AI 生成和通用分析后，系统仍保留清晰的计划来源与分析器能力状态。后续替换这些适配器需要独立验证，不能只换名称就提升结论强度。

## 4. G0：保留，但收窄为 Demo 的前置门

3. 验证新应用 SQLite 在实际支持运行时可用，保证默认 FreeTalk 不导入它；不为 Demo 抬高旧应用要求。
4. 固定点餐预置包 / 计划及少量表达反例，明确规则支持范围、未知和 grade=null；完整 12 案 / 三主题及评级 holdout 后移。

### MD-01：独立入口与必要业务主干

- 新增 Teacher Assistant 应用 / 配置 / 启动命令和本地 Mock 授权服务；采用完整方案目录与端口边界。
- 只实现一位模拟教师、一个有效接收人、角色 / 授课关系、基本 actor 验证及必要 repository；演示角色选择不能授予任意对象权限。
- 实现必要的版本、CAS / 幂等、auth / deletion epoch、迁移和重启读取；不建设完整任务调度 / 分析管理平台。
- **完成：**新应用独立可启动；teacher 不伪装成 learner；跨角色 / learner 请求拒绝；新服务关闭不阻塞 FreeTalk；基础记录重启后仍在。

### MD-02：预置内容与教师确认发布

- 创建一份来源明确的点餐 TopicPack 和个人 HomeworkPlan，包含两项目标、Kai 服务员角色、允许支持及观察标准。PresetPlanSource 与未来 AI 实现使用同一输出契约。
- 页面 A 显示主题、学生、具体截止 / 时区、预置计划来源、预览、确认发布及 0/1 提交状态。
- 发布事务固定包 / 计划版本；仅发布给当前授权对象，不把教师按钮作为内容评估能力认证。
- **完成：**发布结果经真实本地服务写入；学生任务卡、Kai 执行和报告均引用同一 plan hash。修改新版不改历史；重复发布可查询同一结果。

### MD-03：实时基础链路的最小复用

- 为新 controller、WS path / protocol、作业 lifecycle 和实际事件观察提供必要注入点；新场景授权保持有效。
- 默认参数仍走原 TeachingSession / 路径 / 保存规则；不改 FreeTalk mode、prompt、旧目标和页面。
- **完成：**旧路径差分及 verify / replay、受影响音频 / 收尾 / 调速 / 拼音检查通过；跨实例 / 错协议票据拒绝；共享扩展单独可审阅。

### MD-04：Kai 按固定作业练习

- 独立 HomeworkConversationController 编译固定计划：Kai 是服务员，创造点单 / 口味表达机会，跟随学生实际回答，可帮助、被打断和结束。
- Demo 不要求外部逐轮 AI Planner；使用明确标记的固定任务 / 控制策略，不依关键词自动宣布任务完成。后续 TurnPlanner 通过同一接口增加动态规划。
- 在归属 / 安全 / 输出门之后记录本次有效学生表达、实际输出 / 帮助、取消及覆盖情况；支持因果不足就 unknown，不判独立。
- **完成：**真实对话范围与任务一致，学生偏离脚本不串任务 / 造结果；结束停止采音 / 播放；记录不足能明确表达，不写长期掌握。

### MD-05：学生任务与对话页

- 页面 B 展示本人任务、教师、要求、预置来源和开始按钮；页面 C 展示连接、对话、字幕、必要控件与结束。
- 仅消费已发布计划；准备 / 真实就绪分开，收到真实就绪后才采音。复用现有音频 / 字幕 / 控制基础组件，不整体复制旧 web.js。
- **完成：**一条普通浏览器到正式新 gateway / provider 的对话可运行；失败显示真实状态；切人 / 退出清理票据、在途工作和旧字幕。合成预览单独标注，不能替代真实 voice 检查。

### MD-06：结束后明确提交

- 结束先停采集 / 播放，保存有界 evidence fence；学生再确认“提交这次练习”。页面可先显示 pending，只有服务回执 / 查询确认后才为已提交。
- submission 与最小 report job / outbox 同事务提交；只实现报告一类后台任务的领取、幂等结果、失败 / 显式重试及重启状态，不先建设通用生成任务引擎。
- **完成：**重复提交不重复写；丢响应可查；退出页面 / 告别不自动提交；报告失败仍为已提交；作业或授权已失效时阻止新写入。

### MD-07：根据实际事实生成两份反馈

- 最小 ReportAnalyzer 使用有限、经核对的点餐表达观察规则及模板，输出来源、涉及内容、可核实的表现、unknown 和一条相关建议；不能只有关键词命中。
- 至少覆盖肯定点单、合法口味要求、求助 / 示范后尝试的保守描述，以及引语、否定点单、转述、未知改述、未完整输出和识别不确定的反例。无法支持的表达返回未评估，不当成不会。
- 页面 B 显示学生反馈；页面 D 显示同一尝试的目标事实、帮助范围、证据和下一步教学建议。两者由服务端独立投影，均无等级；教师审阅工作流后移。
- **完成：**改动现场对话后，报告也跟着实际证据变化；没有说口味时不出现“已完成口味要求”；提示先后未知时不写独立 / 明确因果；连接失败无有效事实时不编造成功报告。

### MD-08：闭环与失败场景验收

- 按蓝图五步走完：教师预览 / 发布 → 学生打开 / 开始 → 与 Kai 对话 → 结束 / 明确提交 → 双端查看同一提交的反馈。
- 必测连接失败、提交状态待确认、报告失败 / 重试；另覆盖无权读取、重复提交、取消后的迟到结果、基本重启读取与新服务不可用时 FreeTalk 不变。
- **工程门 G-Demo-E：**真实本地业务 + 合成 provider 的 E2E / 浏览器组件和 verify / replay / 隔离检查通过，标为工程预览。
- **可运行门 G-Demo-L：**普通新入口实际连接 provider，浏览器完成采音 / 播放 / 字幕 / 结束与报告关联检查，并记录真人设备听感 / 操作走查。缺少这些证据就保留对应未验收，不把合成或 CLI 回执称为真人语音 Demo。
- Demo 试用说明明确身份 Mock、计划预置、规则覆盖有限、无自动评级。G-Demo 完成以这条闭环实际可操作为准，不以页面截图或预写脚本为准。
