# 自由对话入口：工程链路审查与 TODO

本仓库只保留自由对话这一条入口。学习页读取三类授权学习者资料，初始没有教学目标，不读取课程或主题包。学生明确要求持续练习时，才从通用技能目录选择一项。语音仍是豆包实时全双工，逐轮规划最多 2 秒。以下是这条链路还要完善的事项。不默认引入独立语音识别或合成，也不在这里决定更换规划模型。

## 现有链路

1. Web 选择 free → `/api/conversation-preparations` → 按授权身份读取个人画像、学习画像、近期学习记录；不读取课程或 Topic Pack。
2. 初始化 Planner → Validator → 会话 plan。初始 primary_goal 为 null，候选和 KP 为空；模型不可用时标记规则降级。free 仍使用 conversation-plan-v1，不包含主题入口的 teaching_decision。
3. `/api/sessions` 消费准备结果 → 重新核对身份、资料 revision、入口与有效期 → 一次性实时票据 → Doubao Adapter。真实 provider ready 后浏览器才开启麦克风。
4. user.final → 即时控制／语言策略 → 三类资料＋当前输入＋最近有限上下文进入 Planner；从宿主接受 final 起最多 2 秒，含有界修复／验证／提交，预留 200ms。
5. 明确练习可使用宿主通用 Skill catalog；resource 始终为 null，课程引用为空。通用技能当前均 unassessed；ObservationPort 仅 shadow，不写成能力事实。
6. 计划经校验后在安全回复边界更新后续输入上下文，并等待 ACK。当前是 next_turn_advisory，不能证明当轮语音先经过外部 Planner。
7. 结束 → 来源受限的总结；勾选保存才经签名端口 append，并返回本地 mock 回执。记录只存进程内存，不包含原始逐字稿／音频，不升级掌握。

已有基础可复用：准备一次性消费、身份／revision 校验、free 零课程调用、局部求助到期、明确取消／暂停、迟到提案隔离、2 秒预算、保存去重与来源约束。工程测试通过不等于语义与真实语音体验通过。

## 建议顺序

1. **先修控制与契约缺陷：FC-01、02、03、04。** 可不依赖新模型推进。FC-04 涉及另一份 learner-data 工作，应先约定接口，不直接覆盖其改动。
2. **完善 free 的决策和意图边界：FC-05、06。** 先明确三类资料如何影响交流支持，再实现模型可替换的决策接口；不套用 Topic Pack，也不强制 free 进入教学。
3. **接上反馈、记忆、总结与第二次会话：FC-07、08、09。** 先做到有依据地适应，保留零成果合法路径；真实掌握保持未评估。
4. **贯穿补评测，最后做真实执行／体验验收：FC-10、11。** 样本与工程 harness 可先完成；模型可靠性待候选确定，豆包门控与真人设备分别验收。既有普通 Web 验收保留，补当前改造受影响范围。

与全 Agent 清单对齐：FC-05／06 对应 AC-M3-01／02；FC-07／08 对应 AC-M3-03／04／06；FC-04／09 对应 AC-M3-05、AC-M4-03；FC-10 对应 AC-M1／M2 的执行回执与 AC-M5-01／02；FC-11 对应独立 AE 计划。本文件是 free 入口的细化，不替代其他入口或另一个工作区的任务。
