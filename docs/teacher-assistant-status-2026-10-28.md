# 教师助教：需求与实施状态核对

核对日期：2026-10-28。最初核查基线：`0d2d392`，分支 `codex/report-analysis`。依据：[完整 TA 计划](teacher-assistant-tasking.md)、[作业 PRD](prd/teacher-assigned-conversation-homework-prd-v0.2.md)和[报告任务](conversation-report-deep-analysis-tasking.md)。最初核查只更新文档；用户随后要求实施 GE-01～04，当前工作区已接入下述目标执行子集，见[实现与边界](teacher-goal-execution-implementation.md)。

当前已有单教师、单学生的「备课 → 发布 → 主题对话 → 明确提交 → 后台深入分析 → 双端报告」闭环。它不是完整教师助教需求全部完成，也没有完成自然对话发音效果和教学质量验收。外部 HSKai 集成不在当前 standalone POC 范围内。

## 1. 核查时发现的两个缺口及后续实现

以下两节描述 `0d2d392` 的问题；当前工作区已补中文输出契约和逐轮模型规划，不应继续把这些描述读成当前代码仍未接入。

### 初始计划：有目标字段，缺少明确的中文输出要求

`ai-plan-source.js` 生成目标的 label、task、criterion 和交流机会；`planning-contract.js` 校验文本、结构和引用。目前没有要求每个口语目标明确写出：学生应当用什么语言、表达什么信息、可接受哪些回答、允许什么帮助，以及什么事实足以说明本次练到了。预置点餐计划更只有目标标签和观察规则。因此不能把“有教学目标”视为“已有可执行的中文输出标准”。

点餐可以明确为：学生亲口用中文表达一种食物选择，再表达一种口味要求；例如“我要一碗面条”“不要辣”。接受合理变体和上下文中的简短回答，不强迫背固定句型。英文求助可以得到支持，但只用英文点餐不满足该中文输出要求。文字转写是表达观察的来源；是否确为本人说话、发音如何，仍依赖音频核对与评测，不能由文字证明。

### 逐轮计划：固定计划已注入，目标进展闭环尚未接入

`controller.js` 当前主要在 RESPOND 和学生明确要求结束的 CLOSE 之间选择；`planning=null`，小结目标进展固定为 unverified。它会持续带入已发布计划，但没有调用 TA-11 所要求的逐轮 planner，也没有将已观察到的表达转为可追溯的目标进展。因此可能自然聊下去，却不知道何时已经练到本次要求。

当前提示词还一并禁止“目标达标”。应拆开两个边界：允许依据具体回答确认“今天这两项都练到了”；不能据此宣布已经掌握、独立完成、获得等级，或声称发音合格。达到本次练习要求后可说：

> 你刚才用中文点了面条，也说了不要辣，这两项都练到了。想再换一种食物试试，还是结束这次练习？

这不自动结束、不自动提交，学生仍可提前选择结束。逐轮计划应明确下一步创造什么听说机会、期待什么中文信息、困难时如何支持；不要求每轮都产生新目标或机械复读。字幕、英文或示范参与时，不能将相关回答直接解释成纯听力或独立能力。
