# 会话中调整 Kai 语速：可行性 Spike

后续状态（2026-10-25）：[口头调速已实施并验证](spoken-speech-pace-tasking.md)。下文保留实施前的可行性结论和六段原始统计；探针现已扩展为九段，包含 +20／+40 的加快验证。

2026-10-24。结论：**供应商层面可行，不必断开重连。现有 Web 尚未接入会中调速。** 同一真实豆包连接中，更新 `session.audio.output.speed` 后，再合成相同固定文本，PCM 时长随档位改变，恢复正常档后时长也恢复。这是独立协议实验，没有修改网关、Planner、页面或学习者资料。

## 当前代码的限制

- `apps/realtime-gateway/public/web.js` 的 `controls(active)` 在会话中禁用语速选择；当前选项仅 slow／normal。
- `packages/provider-doubao/seeduplex.js` 仅在创建时把档位映射为 -20／0。`updateContext()` 当前只发送会话 ID 和 instructions，不发送 speed。
- `packages/agent-core/teaching.js` 在构造时固定语速指令；更新供应商数值而不更新指令，会造成两处设置冲突。
- 网关未接受会中 `speech.pace` 消息；现有 `tests/speech-pace.test.js` 明确验证此消息使连接关闭。因此不能只解锁下拉框。
- `session.updated` 当前归属唯一待确认的教学上下文。另发一个语速更新可能误确认教学版本，必须共用串行控制机制。

## 官方协议依据

本次重新读取[官方 Seeduplex 协议](https://docs.volcengine.com/docs/DoubaoVoice/endtoend-realtime-voice-full-duplex-version?lang=zh)：创建／更新会话的配置包含 `audio.output.speed`，范围 [-50,100]、默认 0；`session.updated` 表示会话配置更新成功。文档没有明确承诺正在生成／排队播放的半句话何时切换速度，因此不能把配置 ACK 等同于当前回复已经采用新语速。

本次实测发送的是**完整 session 配置**，保留模型、音色、输入／输出格式和 instructions，设置同一 session ID，只改变 speed。不据此声称只发 `{audio:{output:{speed}}}` 的局部更新已经验证。

## 真实供应商结果

使用本机已配置且通过现有校验的 Seeduplex `1.2.6.1` 账号，创建一个独立会话。禁用音频输入后，按下面顺序串行操作：

1. 发送 `session.update`，等待同 session 的 `session.updated`。
2. 用 `speech_text_buffer.commit` 合成同一段 33 字符作者文本。
3. 从有回复归属的 `response.output_audio.started` 到同回复的 `response.output_audio.done` 累计 PCM 字节数，以 24 kHz／16-bit 单声道换算音频时长。
4. 再切换下一档；最后正常关闭并收到 `session.closed`。

| 顺序 | speed | PCM 时长 | 更新 ACK 耗时 |
| --- | ---: | ---: | ---: |
| 正常 | 0 | 5397 ms | 131 ms |
| 慢速 | -20 | 6465 ms | 133 ms |
| 恢复正常 | 0 | 5172 ms | 129 ms |
| 更慢（仅实验） | -40 | 8994 ms | 122 ms |
| 恢复正常 | 0 | 5161 ms | 415 ms |
| 再次慢速 | -20 | 6469 ms | 125 ms |

正常三次的中位数为 5172 ms。-20 两次音频时长约为正常的 1.25 倍；-40 约为 1.74 倍。恢复正常的结果相近，支持这是同一连接内可逆的调速效果。这里测量的是生成音频的时长，不是网络耗时，也不是浏览器播放速度。

所有六次更新均得到确认并收到完整音频；输出格式保持不变，音频不落盘。本次固定文本合成没有返回文字输出事件，所以没有转写核对或听音确认，不把内容一致性标为已验证。它也不能替代自然对话生成链路的独立验证。

探索过程另有两次未完成尝试：沙箱网络限制使初次连接失败；首次放开网络后成功连接及更新，但探针额外等待固定文本合成未返回的文字完成事件而超时。修正为依赖有归属的音频完成事件后，上表六次测量完成；前两次不计入有效样本。

## 接入建议

建议先沿用 slow／normal 两档，在安全回复边界生效，明确显示“等待切换／配置已确认”。-40 只用于放大实验差异，不新增为产品档位。

1. **统一会话设置。** 维护 `requested`、`pending`、`applied` 档位及版本。语速数值、`speechPaceInstructions()` 和有效计划中的语速投影一起更新；后续 Planner／偏好刷新不能恢复旧语速。仅影响本场会话，不自动写长期画像。
2. **复用现有控制队列。** 把语速和教学 instructions 合并为同一个有版本的配置快照。保持最多一个待确认更新，继续串行处理 cancel。活动回复或控制未确认时排队；连续点击合并为最新选择，已经发送的快照保持不可变。
3. **确认与异常。** 只有同会话、同一待确认操作的 ACK 才提交 applied。保留现有超时／失败关闭规则，页面如实显示失败；不能仅修改本地标签后继续宣称供应商已应用。断开后清除待切换状态，迟到结果不能更新新会话。
4. **生效边界。** 产品默认承诺“后续回复采用新语速”。已经生成或进入浏览器队列的音频保留原时长。若需要立即生效，应复用已有打断和播放清理流程，再更新；不另开取消通道。
5. **口头控制。** 对已接受且归属有效的学生 final 识别“接下来慢一点／恢复正常”，转为同一档位设置入口；明确范围、否定、引用／词义询问和撤销。全双工可能已经开始回复，不能承诺这句确认语就以新速度说。先做页面切换可独立验证协议与状态，再接自然语言入口。

不采用浏览器 playbackRate 或修改采样率：现有字幕、播放时长和收尾回执依赖原始音频时钟，服务端调速更符合当前结构。

## 复现与验证边界

```sh
node scripts/speech-pace-probe.js
node --env-file-if-exists=.env scripts/speech-pace-probe.js --live
```

真实运行需要现有 `DOUBAO_REALTIME_PROFILE`／本地默认配置及其指定的环境密钥，继续执行既有配置审核。当前扩展版探针最多 150 秒、九段作者固定文本，每段输出最多 30 秒音频；没有麦克风上传、真实学生文本、原始事件保存或音频保存，输出仅含统计和布尔状态。`passed` 只表示实验有效、慢档时长均大于正常中位数的 1.1 倍且快档小于正常的 0.95 倍，不是产品听感验收。
