## 检查与阻断规则

`kai-content-v3` 保留原有十维和权重，同时叠加 P0 检查。普通 `eval:content` 的表面指标仍是通用报告；本轮回归使用 `eval:p0`，不以通用均分代替逐项通过。

| 检查 | 方法 |
| --- | --- |
| 中英交替顺序 | 每个完整 Kai 回复调用已有 `measureReply` |
| 共享回复预算 | 两种语言共用已有 36 汉字、24 英文词、48 合并单位、180 总字符、最多两句对预算 |
| 问题表面数量 | 对应翻译的问号算一次；多个主要任务仍需语义审核 |
| 翻译对应 | `translation_alignment` |
| 单一知识点与示范 | `single_teaching_point` |
| 至多一个主要问题／任务 | `one_question_or_task` |
| 自然关联 | `natural_relevance` |
| 尊重拒绝、换题、结束 | `respect_choice` |
| 按理解与偏好减少英文支架，尝试后自然交流 | `adaptive_scaffold` |
| 澄清上限与等待 | `clarification_limit` |
| 学习结论真实 | `honest_learning_claims` |

语义检查 `0=明确违反，1=不确定需审核，2=满足`；只有清单预声明不适用的项可以为 `null`，不能临时跳过失败项。十维中的 intent、correctness、instructions、level、expression、continuity、progress 为 0 也阻断，为 1 进入待审核；保留原有 critical failure、安全和真实人工接手证据门槛。完整性只允许 personalization 预声明 N/A。

任一明确失败或缺少规定案例，使 `blocked=true`。不确定项使 `needs_review=true`。CLI 对失败、待审核或覆盖不完整返回非零。检查整段多轮记录，最后一轮正确不能掩盖前面违规，也不以高平均分抵消失败。不引入未校准的总分阈值。

表面检查是词法代理：复杂标点、缩写或混合句可能误报。应审核完整观察并补充回归后修正规则，不能把计数当成翻译、知识点或意图已核验。安全帮助仍优先于普通回复风格；本轮内容清单不替代完整安全评测。

## 本地运行

```bash
npm run verify:p0
npm run test:browser
```

`verify:p0` 包含语法／合同检查、全部 Node 测试、三个合成回放和 P0 合成对照。Node 22／24 CI 执行同一命令，浏览器 CI 独立执行原生设备检查。合成对照也可单独运行：

```bash
npm run eval:p0:demo
```

16 个正向样例与 10 个负向对照是明确标记的作者数据。顺序、长度、多问题反例即使十维给满分也被阻断；错误翻译、多知识点、无视拒绝、重复澄清、重复跟读、夸大掌握和虚构发音结论用明确的作者审核标签验证门槛。后者验证标签处理与阻断逻辑，**不证明自动 Judge 已识别语义错误**。报告始终标记未进行真实模型质量或实时体验验收。

## 评测真实观察

准备 [内容输入模板](p0-content-input.template.json) 和 [人工评分模板](p0-judgements.template.json) 的本地副本。模板默认缺少真实回复、candidate revision 和脱敏审核信息，必须补齐才能运行；不能把合成范例改名成真实观察。

1. 在相应入口执行清单场景，记录从学生输入开始的完整学生／Kai 句对，多轮案例保留全部相关回合。只使用已获准的脱敏观察；取消、缺失、截断的回复不冒充完整回复，相关行为另由工程／真人时序检查。
2. 填写实际模型、prompt、lesson 版本、40 位候选提交 SHA，以及脱敏观察 artifact 的 SHA-256 和 reviewer。此 hash 引用独立的已审核源记录，不是要求模板对自身做自引用 hash。版本与审核元数据是操作者声明，应核对源记录。
3. 保留 16 个固定案例 ID。人工评分填写十维与八个逐项检查，不适用项按清单填 null；或使用显式配置的可选 Judge。脱敏授权、来源、版本、案例形状会在 Judge 调用前验证。

```bash
npm run eval:p0 -- .local/p0-recorded.json .local/p0-human-judgements.json
# 可选：仅显式调用已配置的 Judge；不会自动调用豆包或采集对话
npm run eval:p0 -- .local/p0-recorded.json --live-judge
```

Judge 沿用 `EVAL_JUDGE_BASE_URL / MODEL / API_KEY / VERSION`，采用独立 P0 structured output；普通十维接口不变。人工评分不需要 Judge API Key。模型不能批准人工复核，不确定项必须重新审核；来源为 synthetic 的观察始终不产生 recorded 内容通过结论。

内容评测不自动取得对话：Web 诊断导出只有元数据，不含逐字稿／音频，不能直接代替内容输入。评测报告只有版本、固定案例 ID、分数、状态与覆盖信息；不复制逐字稿、自由文本或 N/A 说明。输入仅本地按授权保管，不提交真实数据、密钥或源记录到仓库，不自动上传 Langfuse。`recorded_content_checks_passed` 仅表示提供的记录通过这些检查，`real_experience_accepted` 仍为 false；Task 10 和发布审核继续独立进行。
