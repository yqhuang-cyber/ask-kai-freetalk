## 1. 分步实施

意图单独定义为 **控制课件进度**（拟议内部标识 `courseware_progress_control`）。识别范围包含回看和提前查看，处理分为执行／暂缓／澄清；首版只执行当前或更早且已展示页的回看。下一页／后续指定页仍须理解并自然回应“稍后会学到那里”，正常路径不调用工具、不排队、不改页；任何大于当前页的目标均禁止，即使它曾展示过。识别由原生 S2S 完成，可执行回看才以 navigate_slides 进入宿主；没有 FC 不代表暂缓意图漏识别。单说没听懂不自动切页，不增加 MiniMax 意图模型或 ASR 后规则执行。详见[技术方案 §2.3](voice-slides-control-design.md#23-意图识别在哪里触发)。

## 3. 真实样本与指标

首轮使用固定作者测试材料，不使用真实学习者录音／转录。至少覆盖 12 个明确有效回看请求、6 个不应切页的表达，以及连续两次 previous／recent 指代绑定／手动交错／打断／失联各一条完整时序。不切页样本至少包含下一页、明确后续页、含糊后面内容、单说没听懂、继续和目标不明；越界／最后一页与回退后请求曾展示的更大页另加覆盖。回看统计工具触发率；提前查看独立统计请求理解、暂缓话术及无副作用，不能把预期无调用计成漏调用。历史来源注明真实组件回执或 synthetic 作者预置，两者分开统计；覆盖不足单列。

记录时间点：输入结束、ASR final、FC 到达、命令派发、浏览器回执、工具结果发出、首段确认音频到达与实际播放。报告各段耗时、成功／失败／未知／拒绝比例，样本量足够时再报分位数，区分供应商时延与页面执行时延。

本机体验初始目标：命令派发至浏览器回执通常不超过 500ms；2 秒未确认进入核对，总预算暂定 5 秒。真实语音端到端延迟先测基线再定门槛，不把这些预算写成豆包 SLA。

必须为零的正确性缺陷：回执前宣称成功、重复应用同一动作、执行到其他会话、失联后盲目累计回退、主动推进禁令被绕过、单说没听懂便误切页、将翻页计为学习掌握。工具漏调用、误调用或明显破坏对话节奏也阻止本轮启用，修复后重跑受影响用例。

## 4. 工具目录与报告约定

新增实验脚本、作者用例定义及专属浏览器检查统一放在 `scripts/voice-slides-control/`，目录内附 README。共享运行模块放实际 packages／apps 模块，不为实验另复制一份 Agent。

原始供应商 trace、密钥、录音／音频和真实学习者内容不提交；临时调试保持本地忽略目录。可提交去敏的合成用例、必要作者脚本、汇总指标及结论，不能把真实原始 trace 重命名成“测试夹具”入库。

运行／合同改动后必须执行 `npm run verify` 与 `npm run replay`；浏览器用专项检查并回归普通聊天、口头调速和收尾。真实供应商实验和人工设备检查独立记录，不能由前两项通过代替。

最终报告采用三栏：synthetic／合同、真实 provider、浏览器与设备；逐项列实际通过、失败、未覆盖及所用代码版本。完成后更新 README／实施计划，将本设计的“待实现”改为真实状态，不提前写已支持。
