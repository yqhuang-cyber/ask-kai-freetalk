## 原流程哪里容易失效

这是代码路径分析，不把它写成某次真人会话已经复现的唯一根因。

1. 收到明确结束后旧流程停麦、mute，并可能取消已经开始的告别；更新指令后只能等待供应商再次自动生成。`session.update` 是更新上下文，不是可靠的新回复触发器，没有新的自动回复时只能超时关闭。
2. 旧流程在网关收到 `response.done` 后进入保存／关闭。该事件说明服务端输出完成，不能证明浏览器已播放完；前端临时 drain 延时也不是绑定收尾回复的播放回执。
3. 小结内容、口头收束和原学习尝试写回使用的结构不同；原学习记录不是可授权读回的完整会话小结。
4. 新小结采集会改变上下文版本，必须同步发送 `teaching.state`，否则采集端可能一直等待旧版本。

## 最小依赖移植

| 改动 | 作用 | 保留的边界 |
| --- | --- | --- |
| ClosingCoordinator | 准备、播报、等待播放、保存、结束；继续发言可撤销，立即退出跳过播放 | 只接受本会话当前收尾编号、回复编号、小结版本及完成边界；重复、旧版本、外来回执无效 |
| ClosingPlayback | 用浏览器音频时钟、队列排空及字幕完成状态发送回执 | 暂停不报播完；回执不证明人耳听到、理解或掌握 |
| SessionRecap | 同一有来源快照供指令、页面和服务端会话记录使用 | free 初始正式目标为空；交流、示范与 attempted 分开；收尾自身不新增知识，取消／未完成回复不提供示范来源 |
| 授权会话记录 | 在现有签名 PlanningPort 内增加登记、保存、读回；owner／learner／session 隔离，版本与 hash 幂等 | 内存 mock，重启清空；失败／未确认不显示成功；撤权、安全和隐私删除沿用既有边界 |
| 收尾提示与版本同步 | 回顾实际内容后告别，不再加问题或练习；采集引起版本变化时同步教学状态 | 不启用 Function Calling 或 controlled，不承诺本轮生成必先取得最新小结 |
| Planner 机制文档 | 说明初始化、逐轮输入输出、四位合成学习者、降级与缺口 | 示例不是实测模型结果；说明本仓库保留的可选 Pi 路径 |

本仓库已有的豆包 `20000002` 退出信号与明确告别 fallback 保留，但改为绑定有效且已转发的回复后等待播放，不再取消已结束的告别、要求供应商重说。归属有效但暂存在 output gate 的退出信号只等待相应输出；新输入后旧回执和退出信号不能关闭继续中的会话。词义、疑问、否定和外来回复不触发退出；诊断采集仍使用脚本模式。

默认等待回复 12 秒，已开始回复最多 45 秒，浏览器播放最多 35 秒；超时记 `incomplete`，不算正常播完。上下文确认保持本仓库已有 8 秒，不退回原仓库的 1.5 秒。结束按钮立即停止播放／采音，正常口头收尾保持全双工至最终保存阶段。

## Planner 运行机制与其他差异

- 初始化：授权读取个人画像、学习画像、最多 10 条近期记录；Free 不取课程／Topic Pack，初始目标、候选目标、知识点为空。默认 15 秒总预算，失败有标记地降级。
- 逐轮：接受归属有效的 `user.final` 后，当前意图和控制先由宿主处理，再用最近 12 条实际师生消息、计划、资料及前次执行状态规划；最多 2 秒，预留提交窗口。新输入、打断、更正、结束会使旧工作失效。
- Planner 输出 action／task 等建议，豆包生成实际正文与语音。普通回复与 Planner 并行，新建议仅在安全边界更新完整 instructions；ACK 不等于已开始的回复执行了该计划。明确结束走收尾，不再启动普通逐轮模型请求。
- 新 SessionRecap 进入语音指令，尚未作为独立滚动摘要进入外部 Planner 输入；不能因此声称外部 Planner 已记住整场对话。
