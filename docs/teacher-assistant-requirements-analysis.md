# AskKai 教师助教：需求分析

日期：2026-10-26（Asia/Shanghai） · 状态：需求讨论稿 v0.2，尚未实施。

配套文档：[师生 User Journey](teacher-homework-user-journey.md) · [主题对话作业 PRD v0.2](prd/teacher-assigned-conversation-homework-prd-v0.2.md) · [前置规划与教学包、原仓库核对](teacher-homework-planning-design.md)。

本版落实用户最新澄清：主题方向由教师判断，内容与目标由 AI Planner 前置分析形成；新建独立教师助教场景，不影响现有 FreeTalk。

## 1. 对需求的理解

AskKai 希望成为教师的课后口语助教：教师给出主题和教学方向，AI Planner 先把方向转成主题资源及适合各学生的内容、目标和支持计划，教师预览发布后由 Kai 组织主题对话，再把有来源的表现反馈给师生，帮助教师决定下一次怎么教。

这一方向包含两个层次：

| 层次 | 要解决的问题 | 成功时的结果 |
| --- | --- | --- |
| 产品目标：教师助教 | 一位教师如何在课后继续支持不同学生，并知道练习产生了什么结果？ | 教师能安排练习、了解每人的表现，并据此调整教学；学生知道下一步怎么练 |
| 首个场景：主题对话作业 | 如何把一节课后的要求，变成 Kai 能承载、学生愿意参与、教师能判断效果的任务？ | 布置 → 选择 → 对话 → 提交 → 分析 → 师生反馈 → 下一次教学 |

教师端页面承担“表达教学方向、预览 AI 计划、发布和查看结果”的职责。前置 Planner 准备教学包与按人计划，实时 Kai 依计划练习，会后分析按同一计划解释结果。教师无需逐人从零写教案，可批量采用并只修改需要变化的部分。

## 2. 已确认、建议与待澄清

### 2.1 用户已确认

- 增加 teacher 角色，以现有四位 learner 为首个演示班组。
- 教师课后可以给所有学生或指定学生布置有截止时间的口语练习。
- 练习可以围绕生活场景、固定剧情、内容主题或指定语言表达展开。
- Kai 知道学生有哪些待完成的对话作业，提示学生选择；学生选择后开始练习。
- 教师决定练习主题及教学方向，可补充当堂内容与指定要求；AI Planner 前置分析内容、目标和支持策略，教师采用 / 修改后发布。
- 这是独立“教师助教作业主题对话”新场景，根据作业计划开展主题对话，不能影响现有 FreeTalk。
- 对话结束后分析实际涉及的内容、表现较好的地方、易错处和后续听说建议。
- 学生与教师分别获得适合自己的反馈。
- **学生只看反馈；A/B/C/D 仅供教师查看。**这是用户在需求讨论中明确选择的权限规则。
- 当前阶段产出需求分析、User Journey 与 PRD。

### 2.2 本稿的设计建议

- 一份作业可以有共同主题和按学生确认的差异化目标。
- 先复用 / 生成不含学生资料的主题资源包，再结合授权资料形成每人的作业教学包；生成与校验发生在教师布置阶段。
- 目标、通过条件、允许的支持和评价规则在发布时固定；Kai 可调整教法。
- 每份作业建议 1～3 项核心目标，可另有选做挑战；每轮聚焦一项主要表达任务。
- 学生结束对话后可以提交本次练习，也可以暂存或再练；提交成功与目标达成分别展示。
- 教师先看到 AI 暂评及依据，可修订并注明理由；学生只接收具体反馈及教师评语。
- 首版允许重练，默认以学生最近一次明确提交为当前结果，保留历史尝试。
- 逾期允许练习和提交，保留迟交标记；教师可以调整截止时间。
- 首期先做一位模拟教师、四位模拟成年 learner、本地 Mock 业务数据。

以上是可调整的产品建议，不等于已经实现或已经通过教学评测。

### 2.3 仍需后续确认

| 问题 | 当前处理 | 影响 |
| --- | --- | --- |
| “再也不”是目标句式，还是某个固定剧情的名称？ | 暂作目标句式示例；固定剧情单独建模 | 教师表单和内容模板；不影响主流程 |
| 实际班级是否同级、是否有未成年人？ | POC 沿用四位成年 Mock；同时支持同级共同目标与异级分层目标 | 内容、反馈语言、授权方式 |
| 教师是否需要主动提醒、邮件或其他渠道？ | 首版只在产品内展示待办和截止状态 | 后续渠道与运营范围 |
| 是否需要课程正式成绩或机构统一量表？ | 当前仅定位为本次口语作业的教学参考 | 量表校准和后续成绩系统接入 |
| 每次练习的建议时长、周期和反馈语言？ | 按任务配置；时长为建议，学生可提前结束；语言沿用授权偏好 | 试点体验与内容设计 |

## 3. 需求背后的三个工作缺口

以下是基于用户描述的产品假设，需要用教师访谈和试点核实，不能当作已经测得的用户研究结果。

### 教师：布置了口语练习，却难以持续看到每人的表达过程

教师需要的结果包括：谁提交了、哪些目标有表现证据、哪些地方需要自己跟进、下次课堂适合一起复习什么。仅有聊天次数、时长或一份泛泛的总结，难以支持这些决定。

系统应帮助教师减少重复设计与逐人检查的工作：教师保留主题方向和发布决定权，AI 承担具体内容、目标与支持方式的前置规划，教师可检查和修改。若教师仍须逐人手写计划，或逐段听完全部对话，助教价值就没有充分体现。

### 学生：知道主题，却不一定知道该说到什么程度

“练习点餐”对不同学习者的含义不同。学生需要看到可理解的任务，例如“点一道菜、说清数量，并回应一次店员确认”，进入对话后还需要有回应、有支持、有退出选择。

反馈应指出自己实际做到了什么，以及下次可以具体尝试什么。学生侧不显示 A/B/C/D，不把一次作业变成公开比较。

### Kai：需要同时理解教师意图、学生选择和实际表现

Kai 要知道哪些是本次必须争取创造的练习机会、哪些只是可选挑战，何时给提示、何时让学生自己表达，以及什么情况下证据还不足。目标命中词、Kai 自己说过目标句、学生点了提交，都不能自动证明目标已达成。

## 4. “助教”的职责与决定权

| 教学环节 | 教师 | Kai / 系统 | 学生 |
| --- | --- | --- | --- |
| 设计 | 决定主题、教学方向、对象及截止，可补充课堂观察；批量预览采用 / 修改 | 前置准备主题资源、按人内容 / 目标 / 支持 / 观察计划，并解释依据与未知 | 查看自己的任务说明 |
| 执行 | 可在后续报告中检查任务是否合理 | 创造表达机会，跟随回答调整追问和支持 | 选择作业、求助、打断、暂停、结束或提交 |
| 评价 | 审阅暂评，修订等级与评语 | 按固定规则分析本次证据，标出未知和执行缺口 | 查看具体反馈，提出“这条反馈不准确” |
| 后续 | 决定课堂复习、个别辅导、下一次作业 | 给出带依据的建议和草稿 | 自愿继续练习 |

首版的闭环终点是教师能够采取下一步教学行动。教师可以把建议带入下一节课，或基于报告创建新的作业草稿；新任务仍需教师发布。

## 5. 作业设计的四个维度

| 维度 | 回答的问题 | 示例 |
| --- | --- | --- |
| 内容主题 | 聊什么？ | 昆虫、周末、饮食 |
| 情境 / 剧情 | 在怎样的场合、以什么角色沟通？ | Kai 扮演店员；想点的菜售罄，需要换一道 |
| 语言目标 | 希望学生完成什么表达？ | 说数量、说明偏好、解释改变、使用“再也不……” |
| 观察标准 | 怎样判断本次表现？ | 是否传达意思、使用了多少支持、是否回应了确认或变化 |

一份作业可以组合这些维度。例如“讲一次被虫子吓到的经历，表达以后不想再做的事”把昆虫主题与一个表达目标结合；初学者可以只练“我不喜欢……”，是否采用更复杂句式由教师确认。

固定剧情应规定角色、背景和必须出现的沟通节点，同时允许学生自己选择措辞和行动。若把每一句都写死，评价到的主要是复述能力，难以判断真实应对。

### 从教师主题到可执行教学包

用户提供的原仓库已有“后台生成 TopicPack → 发布 → 初始化结合学生资料形成具体任务”的机制。本次核对了源码，确认它可供新场景借鉴；本 FreeTalk 分出时未移植主题链路。原包目前只准入受限情境 / 开场及可信能力关联，不能直接视为完整例句教材或通用评分能力，详见[核对与新需求](teacher-homework-planning-design.md)。

新需求将产物分为三层：TeacherBrief 保存教师方向与限制；TopicPack 保存无学生资料的可复用主题资源；私人 HomeworkPlan 保存各学生的具体任务、目标、表达机会、支持和观察标准。最后一项由前置 Planner 形成，经教师采用后成为对话与分析的共同依据。

例如教师只给“点餐”，AI 需要先准备可用情境和候选表达机会，再按学生需要选择 / 组织具体任务，给出提示方式及观察点。教师主要检查是否符合课堂意图、是否有明显不适配；无需补写完整教案。若某个句式或能力缺少已准入资源，应标明缺口，不临时捏造正式知识点。

学生开始时只检查已发布资源与计划是否有效，不再触发生成包或自由改选目标；逐轮调整留在计划范围内。这样可以前置等待，也能让教师知道学生实际要练什么。

## 6. 分层的单位是表达任务

以下均为设计示例，不是官方 HSK 等级标准，也不是四人已经具备或已经完成这些能力的结论。现有画像只用来提出建议，教师要检查先修、当堂所学和目标合理性。

| Learner | 同为“点餐”的建议任务 | 支持方向 | 教师需要确认 |
| --- | --- | --- | --- |
| Alex / HSK1 背景 | 点一道菜和一种饮品，说清数量，回应店员一次确认 | 简单菜单、具体问题；必要时给局部选择或句框 | 菜名和量词是否已教；无需重教已稳定的喜好表达 |
| Maya / HSK3 背景 | 说明口味及原因，在一道菜售罄后选择替代品 | 先独立表达，卡住时提示信息组织 | 是否已接触相关口味词；不把长句停顿当基础缺失 |
| Leo / HSK5 背景 | 比较两种方案，说明预算或同伴偏好，协商修改订单 | 少示范；追问具体理由和条件 | 是否需要练习论据和精确表达，而非只增加词汇难度 |
| Nina / HSK7 背景 | 在误会或服务不符时礼貌澄清，限定要求并提出替代方案 | 平等对话；反馈语气、措辞及应对 | 是否有足够真实的挑战；高级学生也可做简单生活任务 |

如果四人的教学需要相同，允许共用目标。等级不会强迫系统生成四份不同任务。差异化目标下的 A/B/C/D 只相对于各自任务解释，不能用于跨级排名。

## 7. 三个必须分别管理的结果

| 结果 | 它证明什么 | 它不能证明什么 |
| --- | --- | --- |
| 提交状态 | 学生提交了某次练习，或尚未提交 | 学生做到了全部目标 |
| 本次目标表现 | 在本次情境、支持条件与证据范围内怎样表现 | 换场景仍稳定使用、长期掌握或整体等级提高 |
| 长期学习记录 | 多次经授权观察形成的学习事实与候选建议 | 一次暂评就可以自动覆盖长期能力标签 |

“未开始”“逾期”“报告失败”“证据不足”均不能自动记为 D。D 只能描述在公平、有效的表达机会下，本次核心任务仍有明显困难。

## 8. 报告的价值在于支持下一步行动

### 给学生：具体、可理解、可继续做

推荐内容顺序：本次练了什么 → 你已经做到的具体事情 → 一个最值得再练的点 → 下次可试的表达或活动。可补充本次接触的词句，表述为“本次练过 / 接触过”，不直接写“新学会 / 已掌握”。

例如：“你说清楚了想要的菜和数量。店员问能不能换一道菜时，你需要一句提示。下次可以试着先说‘那我换成……’。”示例为作者编写，不是真实学生报告。

### 给教师：快速判断与可追溯证据

教师先看完成分布、各目标表现、AI 暂评和需要跟进的人，再按需展开少量经授权的证据。报告还要指出 Kai 是否给出了足够机会、是否过度示范、是否出现技术中断，帮助教师判断应调整学生任务还是调整 AI 教学。

班级建议应写成“4 人中 2 人在替代选择节点需要提示，另 1 人未获得有效机会”，保留分母和未知；不把所有缺失都归因为学生薄弱。

## 9. 对 A/B/C/D 的产品判断

A/B/C/D 是教师理解本次表现的摘要。它需要与目标、实际支持和证据覆盖一起出现，不能单独代替报告。

建议先采用可解释的描述量表：独立完成、局部提示下完成、较多帮助下部分或全部完成、有效尝试后仍需重新练习。证据不足时不评级。详细判定顺序见 PRD；首版不以精确百分数包装未经校准的判断。

教师可修改暂评，保留原暂评、修订理由和版本。学生看不到等级，也看不到可直接反推出等级的隐藏数字或内部评语。学生应获得与实际表现一致的事实反馈。

发音建议要区分“建议的练习活动”与“已发现的发音问题”。可以建议跟读目标表达；具体声调、声母、韵母或语流诊断需要经验证的音频评测证据，不能从转写推断。

## 10. 与当前 FreeTalk 的关系

当前仓库只有自由聊天入口，初始无正式教学目标。已有四位成年 Mock 学习者、画像与偏好、实时语音、逐轮规划及有来源的小结，为这次扩展提供基础。

用户已明确要求增加独立“教师助教作业主题对话”场景：新入口 / 页面展示待办和任务提示，原 FreeTalk 页面不增加作业卡片、提醒或切换逻辑。FreeTalk 保持初始无目标、按现有规则自由交流；不读取作业、主题资源或个人作业计划，不自动切成作业。

新场景可以复用语音、采音、播放、字幕、拼音、调速和授权资料等基础能力，作业计划、提示词、状态、证据及报告分别隔离。新业务服务关闭 / 失败时不能影响 FreeTalk；显式切换场景需要结束旧会话再开始新会话，FreeTalk 内容不能追认为作业。现有 FreeTalk 无需为了新需求修改默认提示词、校验或规划预算。

已有小结和前五轮开发观测并不足以直接产出整场作业成绩。新需求要补齐作业管理、教师权限、目标版本、全任务证据覆盖、异步分析、复核及双端报告。历史计划中的主题能力不等于本 FreeTalk 仓库已经有可用的教师作业链路。

## 11. 建议的首版验证路径

| 阶段 | 要验证的产品问题 | 产出 |
| --- | --- | --- |
| 需求与纸面走查 | 教师是否能表达教学意图，学生是否看懂任务？ | 当前三份文档与示例作业；收集修改意见 |
| 本地前置规划原型 | 只给主题能否准备资源和按人计划，教师能否低负担采用？ | 一位模拟教师、四位模拟学生，资源与私人计划分开；所有示例明确标合成 |
| 独立场景流程 | 布置、选择、提交、报告是否闭环，FreeTalk 是否保持原样？ | 新作业入口；关闭新服务仍可用原 FreeTalk；无新数据 / 提示词依赖 |
| 真实语音纵向切片 | Kai 是否真正创造目标机会、跟随学生回答？ | 一个点餐任务的真实 provider 与浏览器音频分开验证 |
| 教学试点 | 教师是否省时、反馈是否可信、能否指导下一节课？ | 教师独立审阅、量表校准、反例与误判记录 |

先把点餐做成完整切片，再验证昆虫主题及一个句式 / 剧情任务，避免系统只对单一脚本有效。目标推荐、对话承载和会后评价要分别评估。

## 12. 主要风险与研究问题

- 教师要求可能只有主题，没有可观察目标：提供可修改的任务草案，并说明建议依据。
- Kai 可能自己说得很多，学生几乎没有输出：报告机会覆盖及实际学生输出，不用聊天时长替代效果。
- 支持程度不明，却评价为独立完成：保留未知，进入教师复核，不自动提升证据。
- 反馈可能被误听或一次错误带偏：提供更正入口，保留转写不确定性和教师修订链。
- 分层过度增加教师负担：优先共同任务，仅对确有需要的学生覆盖目标；观察教师修改率。
- 前置规划只输出标签、教师仍要补写内容：教学包必须给出可执行任务、表达机会、支持及观察标准，验证批量采用负担。
- 共享主题包泄露学生资料，或私有材料被跨教师复用：共享资源与私人计划分开，复用按授权范围。
- 新场景改变 FreeTalk：独立入口、零作业服务调用、提示词 / 状态隔离及新服务故障对照为硬验收。
- 教师若看不懂暂评依据，就会重新检查整场：验证证据卡是否足以支持判断。
- 高等级任务得到 A，不代表与低等级 A 相同能力：报告始终并列任务要求和等级参照。
- 实时规划目前只能对后续输入提出建议：验证语音实际执行，不能把计划被接受当作任务已执行。

## 13. 建议衡量的结果

首要观察教师“从布置到形成下一步教学决定”所花的时间是否下降，以及决定是否有有效依据。配套记录目标草案采纳 / 修改情况、作业启动与明确提交比例、目标机会覆盖、独立可评证据比例、教师修订暂评比例、学生反馈可理解性及下一次练习的针对性。

这些指标需要先建立基线，再设试点目标。作业次数、对话时长、A 等比例增长均不能单独证明学习效果提高。
