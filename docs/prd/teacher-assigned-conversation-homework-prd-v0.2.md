v0.2 根据用户澄清修正职责：教师决定主题与教学方向；AI Planner 在发布前生成 / 复用主题资源，分析各学生的内容、目标及支持策略；教师预览采用后发布。此为独立“教师助教作业主题对话”场景，**不得影响现有 FreeTalk**。学生仅看反馈、A/B/C/D 仅教师可见的规则继续有效。

2026-10-27 需求增补：用户确认**自然对话的发音分析是深入报告 feature 的 P0 必交付**，与情境理解 / 口语语义并列，包含必要学生音频、归属与文本对齐、实际声学评测、证据回听 / 建议及专业验收。执行见[深入报告 Tasking v1.1](../conversation-report-deep-analysis-tasking.md)。此前“首版无发音”仅描述最小 Demo 历史边界，不再把该新 feature 的发音安排为可选后续。尚未实现新采音 / 发音能力；没有可靠证据的个案仍不诊断。

## 1. 产品定义与目标

AskKai 作为教师的课后口语助教，承接教师决定的主题与教学方向，由 AI Planner 前置准备主题资源、练习内容和按学生形成的目标 / 支持计划，经教师预览发布后组织实时中文主题对话，并将可追溯的表现转化为学生反馈和教师报告，支持下一次教学安排。

首个完整场景是一位教师向现有四位 learner 布置课后主题对话作业。教师可以只给主题、对象和截止时间，可选补充课堂观察、指定表达与限制；AI 负责把方向变成可执行计划，教师可批量采用、按需修改，无需逐人手写教案。对话过程根据学生实际回应调整，评价以发布时固定的要求与实际证据为依据。

| 目标 | 产品行为 | 判断方式 |
| --- | --- | --- |
| 教师更容易安排有针对性的练习 | AI 将教师方向转成主题资源和按人计划，教师批量预览发布 | 创建及编辑时间、草案修改、目标合理性与资源可用性 |
| 学生能把课堂内容用于对话 | 任务清楚，Kai 创造表达机会并按需支持 | 目标机会覆盖、学生实际输出、对话语义评审 |
| 师生知道下一步怎么做 | 学生看具体反馈，教师看证据、暂评和教学建议 | 教师行动可用性、反馈理解与修订记录 |
| 结果诚实且可复核 | 完成、表现、长期掌握分别处理 | 来源校验、未知处理和反例评测 |

**用户已确认：A/B/C/D 仅供教师查看，学生只看具体反馈。**该规则覆盖页面、接口、通知、导出及语音，不能只在页面上隐藏。

### 1.1 独立场景与 FreeTalk 不变要求

新场景使用独立入口 / 页面及场景标识，不以 `mode: free` 携带作业。原 FreeTalk 页面、初始无目标契约、逐轮自愿练习、提示词、控制与小结保持现状；不增加作业卡片、提醒、读取或自动场景切换。待办及 Kai 的任务选择提示只属于新场景。

可复用语音、网关基础设施、采音 / 播放、字幕、拼音、调速和授权资料端口；新增业务、计划、提示词及报告按场景隔离。作业或主题服务关闭、未配置、故障时，FreeTalk 不受依赖影响。FreeTalk 对话不能事后自动追认为作业证据。

## 2. 范围与优先级

### 2.1 首版 P0 建议

- 一位本地模拟教师与现有四位成年 Mock learner，建立明确的模拟授课关系。
- 教师选全部或部分学生，创建、预览、发布、撤回作业；设置明确截止时间。
- 教师给主题与方向，可附角色 / 剧情、指定表达和材料；支持最少输入。
- 发布前 AI 生成 / 复用经准入的主题资源，并按授权资料形成每人的内容、目标、支持及观察计划。
- 教师批量预览、重点检查差异和未决项，采用 / 修改后发布，不要求逐人手写目标。
- 学生在独立作业入口查看自己的待办，自主选择任务，启动作业会话；原 FreeTalk 入口保持现状。
- Kai 读取固定任务计划，组织实时对话并记录有效机会、实际帮助及学生表达证据。
- 学生结束、暂存、提交及重练；状态与结果分开。
- 异步生成学生反馈和教师报告；教师专属 AI 暂评、修订与评语。
- 作业详情提供班级概览和个人报告，支持形成下一步教学建议或作业草稿。
- 本地 Mock 业务持久化及删除 / 权限隔离；示例数据和真实语音来源分别标注。

深入报告增补的 P0：学生文本与必要语音记录、上下文语义模型、自然对话发音 / 声调 / 语流评测及有来源的双端反馈。该 feature 的文本与发音均通过独立验收才完成；不以 A/B/C/D 自动等级为前置。

### 2.2 后续 P1 / P2

| 阶段 | 范围 |
| --- | --- |
| P1 | 更多主题模板、教师常用任务复用、固定剧情模板、班组管理、批量审阅、更细的教学量表与周期趋势 |
| P2 | 跨多次任务的复习建议、多教师协作、正式 HSKai 账号 / 课程 / 学习记录系统集成 |

首版使用受限的任务材料和结构化剧情节点，支持教师自定义内容；大型可视化剧情编辑器和自动生成完整课程不在首版范围。外部消息提醒、家长端、正式考试评级及机构排名另行立项。

## 3. 用户、权限与责任

| 角色 | 允许 | 约束 |
| --- | --- | --- |
| Teacher | 管理自己授课关系内的作业，查看对应报告及等级，修订、评语、创建后续草稿 | 不能凭同一 owner 身份查看任意学生；跨教师共享需后续显式授权 |
| Learner | 看本人任务、练习、提交、反馈、教师评语；提出反馈疑问 | 不能读取其他学生或教师专属等级 / 评语字段 |
| Kai / 分析器 | 在授权上下文内执行对话和提出分析候选 | 不能自行发布作业、改核心标准、直接升级长期掌握 |
| 本地 Mock 管理 | 演示角色切换、配置模拟授课关系 | 清楚标注演示；不证明真实身份、授权或真人已审阅 |

教师操作权限必须由服务端的教师身份、授课关系和作业范围共同校验。POC 切换角色只用于演示，不能作为真实生产鉴权方案。

## 4. 核心对象与关系

以下是产品对象及建议职责，不是已经发布的接口契约。

| 对象 | 关键内容 | 关系 / 不变量 |
| --- | --- | --- |
| TeachingRelationship | 教师、学生、班组、授权状态、来源与版本 | 教师读写的必要边界；既有 owner 相同不等于已授课授权 |
| TeacherBrief | 教师主题、课堂意图、指定要求、对象、截止及约束 | 教师做方向判断；私人课堂观察不能进入共享主题包 |
| TopicPack | 主题边界、子话题、场景、候选表达机会、可信能力关联及已准入材料 | 可复用、带版本和范围；无学生身份 / 画像 / 表现；生成与发布不同状态 |
| PlanningJob | brief / 资料 / 资源版本、按人进度、生成 / 规划 / 校验结果、取消和失败 | 后台有界、幂等；旧草稿任务不能覆盖新输入，不占学生开聊预算 |
| Assignment | 标题、教学意图、主题、情境、材料、核心 / 选做目标、截止、提交策略、教师 | 每次发布形成不可变内容版本；撤回与权限单独生效 |
| LearnerAssignment | 学生、作业版本、确认后的个人目标、支持策略、可用状态 | 一份班级作业展开为按人隔离的分配；只展示本人内容 |
| TaskPlan（HomeworkPlan） | 按学生形成的需要假设、目标、具体表达任务、场景机会、准入材料、支持、观察 / 评价标准及来源 | AI 在发布前形成，教师采用后固定；两个名称指同一私人作业计划 |
| Attempt | 学生、任务、尝试编号、会话集合、开始 / 结束、来源、技术状态 | 断线重试使用新会话 ID；恢复为同一尝试时须保留分段和间断 |
| EvidenceObservation | 目标、来源会话 / 轮次 / 事件、学生表达事实、已发生帮助、覆盖与置信状态 | 不接受外任务、外学生、重复或已失效权限下的新证据 |
| Submission | 明确提交的尝试、提交时间、幂等标识、迟交状态 | 提交成功不依赖分析成功或目标达成 |
| Report | 尝试与提交版本、目标结果、证据覆盖、学生反馈、教师专属评估、生成版本 | 原始 AI 结果与教师修订分开；学生视图无等级 |
| TeacherReview | 审阅者、原暂评、修订结果、理由、学生可见评语、版本 | 审阅与学生评语发布分别确认；模拟 ACK 不代表真人已读 |

共同主题和每人的正式目标都可版本化。建议每人有 1～3 项核心目标，可有 0～1 项选做挑战；选做未做不影响核心任务评级。逐轮只聚焦一个主要表达任务。原主题实现一次选择一个主要 GoalInstance，多目标作业是新扩展，须独立设计版本，不能修改 FreeTalk 契约或假设原 schema 已支持。

## 5. 教师创建与发布

### 5.1 最少输入

教师选择学生、给出主题与截止时间，就可发起 AI 前置准备；可补充课堂所学、观察、指定表达、情境及限制，不要求先写目标。Planner 生成后，教师预览、采用 / 修改并发布。每项正式目标由 Planner 在允许资源内形成，至少包含：

- 面向学生的“要做什么”，使用可观察的表达任务。
- 可接受的表达含义与变体，明确是否必须使用指定句式。
- 核心或选做、相关先修与教师确认状态。
- Kai 应创造的机会及允许的支持方式。
- 目标判断标准、证据要求和关联量表版本。

“点餐”可以作为足够的教师主题输入；系统在发布前补齐可执行目标。只有“多说中文”“聊五分钟”而没有主题或方向时，保存草稿并提示补充方向。教师也可明确任务只作参与式练习；AI 仍形成具体交流任务，结果只生成描述反馈，不强行产生 A/B/C/D。

### 5.2 前置 Planner 与教学包

流程为：教师 brief → 读取或后台生成主题资源并准入 → 综合教师要求与每人的授权资料形成 TaskPlan → 校验目标 / 先修 / 材料 / 来源 / 评估能力 → 教师预览发布。生成主题资源和按人规划是不同职责，不要求拆成多个 Agent 或独立服务。

TopicPack 可跨学生复用，不含 learner 资料。每位学生的 TaskPlan 才读取已授权个人画像、学习摘要、相关近期记录、本次课堂说明及教师要求。私人观察和私有材料不自动进入公共资源；不同作业可共享主题，但不能共享学生上下文。

每份 TaskPlan 至少包括需要假设及依据、核心 / 选做目标、具体表达任务、关键沟通机会、已准入材料 / 示例引用、提示选项、难度与纠错重点、逐目标观察标准、评估能力状态、学生任务卡和 Kai 执行摘要。缺资料时可安排探索性应用，不虚构薄弱点；等级与姓名不决定固定目标。

目标只能关联允许的能力 / 课程资源。词句、菜单、指定句式及新的数量目标若超出现有资源，标明新增资源 / 准入缺口；不能让模型自创正式 KP、先修或可靠评分规则。需要练习可用与评分可用分别标注，观察能力未验证时只给描述反馈。

页面先展示共同方向，再突出个人差异、依据和未决项。教师可以批量采用有效计划，不必逐人点确认；修改主题 / 要求只重做相关部分。目标推荐和正式评分分别验证，生成计划的自我解释不是评分正确性的唯一依据。

前置任务显示排队、资源准备、按人规划、校验、可预览、失败或取消，并有独立时间与费用预算。生成成功不等于作业已发布。重复刷新不重复生成；取消、草稿修改或学生移出后的迟到结果不能覆盖当前。部分学生失败时默认保留草稿，教师可明确改选可发布对象，不能静默漏发。

学生开始 / 逐轮 / 缓存未命中时不生成包；只消费已发布版本。新资料与原计划冲突时提示教师重新规划，不以开聊初始化悄悄改目标。已授权的偏好变化可调整执行方式，正式目标和标准保持版本一致。具体产物与原仓库证据见[前置规划需求](../teacher-homework-planning-design.md)。

### 5.3 发布校验与预览

预览同时提供学生任务卡和教师执行摘要。教师可批量采用收件学生、正式目标、截止时间与时区、核心 / 选做、材料、评价方式和支持策略，仅按需编辑差异项。缺少授权、目标不可执行、先修明显冲突或材料不适用时，阻止受影响分配发布并定位问题。资源可练但评估能力不可用时，只能以明确的描述反馈模式发布，不宣称自动评级可用。

发布固定 brief、TopicPack、个人 TaskPlan、资料依据和量表的关联版本。资源发布资格与作业发布分别校验，但教师只需一次明确的作业发布操作；不因此获得全局主题管理权限。

截止显示具体日期、时间和时区。用户说“10 月 27 日之前”存在语义歧义，表单不能静默决定是 27 日零点还是 27 日晚间。演示可显式选“2026-10-27 23:59，Asia/Shanghai”，但不视作用户已经确认的真实截止要求。

### 5.4 发布后变更

- 内容 / 标准修改生成新版本，预览受影响对象。首版只对尚未开始的分配显式迁移；已开始的尝试继续绑定原版本。
- 学生开始前若版本已变，旧准备失效并重新确认任务卡；旧准备不能带入新会话。
- 截止延期使用单独的时间策略版本，不改教学标准；重新计算迟交标记并记录原时间与变更。
- 撤回停止新启动和新提交，结束受影响的活动任务采集；已提交历史按留存 / 授权策略保留为撤回历史。
- 授权撤销比发布版本优先，阻止新读取、采集、提交及迟到分析写回。

## 6. 学生发现、选择与开始

新增独立的“老师的作业”场景入口；其中任务卡包含教师、主题、本人目标、明确截止、状态和建议时长，Kai 可在此提示选择待办。不修改原 FreeTalk 页面，不在其入口或对话中增加作业提示。

有多个任务时按截止时间排序，允许自行选择。进入作业前已有发布计划，启动仅校验资料 / 授权 / 资源时效及准备执行方式。学生显式离开当前场景、再进入另一入口时，先收束原会话并清理在途工作，之后创建独立新会话。FreeTalk 不新增自动识别作业、切场景或追认作业的行为。

开始前提示“老师可以查看本次作业表现”，提供语速、语言支架和拼音等既有控制。准备完成和真实语音就绪分别显示，只有真实就绪后才申请麦克风。

准备 / 开始时校验同一学生、分配版本、资料版本、有效期和权限。重连、切换 learner 或任务均不得复用另一任务的票据、计划、字幕或证据。

## 7. Kai 执行教师确认的 AI 作业计划

### 7.1 固定目标与动态教法

| 固定内容 | Kai 可动态调整 |
| --- | --- |
| 学生、作业及版本、核心目标、正式评价标准 | 开场和相关追问顺序 |
| 教师确认的材料与剧情关键节点 | 根据学生回答组织自然的情节变化 |
| 核心与选做边界、内容与安全限制 | 提供局部提示、选择、示范或必要澄清 |
| 允许的支持策略与语言偏好边界 | 在授权范围内降低交流负担、减少重复教学 |

多项目标可以分阶段创造机会。主题范围、核心目标及逐轮动作分别管理；暂停练习保留作业主题，不自动换目标继续考。Kai 不同时连问多项要求，也不为覆盖目标忽略学生当前表达。学生的结束、拒绝、打断、安全与隐私要求优先；核心目标不能成为强迫继续的理由。想换整个话题时可退出此任务，再由学生显式进入原 FreeTalk。

教师计划超出当前学生可承受范围时，Kai 可提供帮助并记录任务适配问题。降低对话难度不意味着偷偷改变正式标准；必要时标记待教师调整。

### 7.2 剧情与主题要求

情境以角色、背景、可用材料、关键沟通节点和可选变化组成。固定剧情不要求固定逐句答案。点餐售罄、对数量的确认等变化必须服务于教师目标。

昆虫等内容主题按语言目标评价；除非教师预先声明并给出材料，不评价学科知识准确性。指定“再也不……”时，需要语境和含义符合目标，单纯提及、引述或 Kai 说出该词不算学生完成。

### 7.3 实时链路约束

当前系统保持实时全双工，逐轮规划默认是后续输入建议。新作业计划在建连前装配，逐轮调整继续经过校验和安全边界提交；不得声称每句语音已被 Planner 预先控制。

计划被接受、指令更新确认、文字被转发、页面显示、音频播放、学生理解是不同事实。每项报告结论只使用其实际可证明的层次；不从内部对象推断新的供应商事件或保证。

## 8. 结束、提交、重练与时间

### 8.1 四组独立状态

| 维度 | 建议状态 | 说明 |
| --- | --- | --- |
| 作业可用性 | 草稿 / 已发布 / 已撤回 / 已归档 | 截止时间另存，不让“逾期”自动代表不可使用 |
| 学生提交进度 | 未开始 / 练习中 / 待提交 / 已提交 | 已提交后再练不清除当前提交；状态展示附“有新练习未提交” |
| 尝试运行结果 | 正常结束 / 学生中止 / 技术中断 / 权限终止 | 独立于成绩；保留分段及实际结束原因 |
| 分析与复核 | 排队 / 分析中 / 可用 / 证据不足 / 失败；未审阅 / 已审阅 | “证据不足”是有效分析结果，和处理失败分别显示 |

迟交是按明确提交时间与当前截止策略计算的独立标记。学生作业级的“已提交”来源于有效提交记录，不能由 Kai 的一句话或报告任务替代。

### 8.2 提交规则

建议学生通过“结束并提交”明确提交当前尝试；立即结束、断线、关闭页面均不自动提交。已正常结束的尝试可以稍后从历史中选择提交。提交不要求全部目标达成，不要求等待 AI 评级。

提交具备幂等标识；重复点击、网络重试只得到同一记录。提交成功后异步分析，分析失败可重试，不让学生重复完成整场对话。提交状态未知时先查询记录，不能直接声称已提交或丢失。

### 8.3 重练与跨场次

每次再练创建新尝试。学生最近一次明确提交成为当前结果，保留旧提交、报告与教师审阅。新尝试未提交时，老师仍看得到先前当前提交。

首版按单次尝试生成报告，断线恢复可包含多个明确分段的会话；不自动拼接多场最佳片段。不同版本或不同尝试的证据不合并成一次独立完成。历史趋势属于后续能力。

### 8.4 逾期

首版建议允许迟交，学生端明确标记已过截止；教师可延期。截止到来不强制中断活动对话。迟交不降低语言表现等级；教师若需要严格关闭提交，须另行配置并提前告知，首版不默认启用。

## 9. 证据与会后分析

### 9.1 每项目标的分析结果

| 字段含义 | 值 / 内容建议 |
| --- | --- |
| 实际涉及的内容 | 已谈主题、涉及表达、相关材料；只描述发生过的内容 |
| 目标机会 | 已获得有效机会 / 未获得 / 未知 |
| 学生表现 | 符合本次目标 / 部分符合 / 已尝试但未符合 / 未观察 / 无法判断 |
| 实际帮助 | 无直接内容提示 / 局部提示 / 完整示范 / 未知；附已发生的来源 |
| 来源 | 作业版本、尝试、会话、轮次、事件及最小必要片段 |
| 覆盖限制 | 中断、截断、ASR 不确定、缺提示因果、缺音频能力等 |
| 下一步 | 与本次事实相关的练习建议；通用建议须标为建议而非诊断 |

系统未能理解某个变体不等于该变体错误。识别不确定、引语、否定、自述“我会了”、只提到关键词、Kai 自己说出目标、同一句重复事件均需要反例约束。

### 9.2 完整任务覆盖

新增独立的作业证据账本，覆盖任务开始至结束期间所有被系统接受的有效轮次及目标机会；不能用前五轮开发观测冒充整场。账本有界、按目标汇总，保留来源及截断标记，不默认存整场逐字稿或音频。

报告生成前检查核心目标覆盖与来源完整性。若达到内存 / 容量上限，记录发生时点与受影响范围；不能在只剩早期样本时生成完整结论。选择最小片段时保留必要的提问、帮助与语境，不抽离成容易误判的单句。

### 9.3 异步分析与校验

建议顺序：固定任务与尝试快照 → 检查权限与证据覆盖 → 按目标产生结构化观察候选 → 校验来源 / 支持 / 不确定性 → 生成双端反馈与教师专属暂评 → 再次核对权限和版本 → 幂等保存。

分析不占用实时语音响应的关键路径。各阶段失败、超时或无法评级均有明确状态。迟到结果不能覆盖更新的当前提交、教师修订或权限变更；历史尝试结果只能落回自己的历史版本。

现有 attempted-only 学习记录保持原语义。新增作业评估独立存储，不能把本次等级或模型分析直接回写为长期 mastered、整体 HSK 提升或真实课程完成。

### 9.4 听力、发音与语流

对已确认的语义问答，可以描述“本次回应了店员对数量的确认”；这只是情境内理解证据，不是整体听力等级。只有学生说得对、ASR 转写正确，都不能证明发音准确。

未具备经验证音频评测时，发音 / 声调 / 流利度诊断显示未评估，不参与等级。可建议跟读、听后确认等练习，但不声称发现了具体发音错误。深入报告必须接入专项音频评测，并单独验证授权、自然对话能力和留存范围；未完成能力准入前不可宣称该 feature 完成。

## 10. 教师专属 A/B/C/D

### 10.1 使用范围与评级前提

等级只描述本次已发布任务中的表现，显示任务目标与难度参照。不作为正式考试、长期掌握或跨级能力排名。AI 给出暂评；教师审阅后可确认或修订，保留两者。

给出等级前至少满足：任务是可评级任务；每项核心目标获得公平且有效的表达机会；相关学生表达和此前支持可归属；证据覆盖足够；目标语义判断和支持归因能力已通过独立评测。缺任一项则显示“证据不足 / 待复核”，等级为空。

当前项目对通用语义、独立使用及提示因果的判断尚未完成验收，因此现有小结不能直接启用自动评级。本地原型可以展示明确标注的合成等级示例；真实自动暂评需完成能力门槛。教师基于获准的可靠证据手动评价时仍需记录依据，不能把未知自动当低等级。

### 10.2 描述量表与判定顺序（建议，需教学校准）

首先按每项核心目标记录“是否符合目标”及“实际支持”。以下按 A → B → C → D 的顺序判断，满足评级前提后才适用；选做挑战不设最低要求。

| 等级 | 本次任务锚点 | 排除条件 |
| --- | --- | --- |
| A | 全部核心目标在相关自然交互中完成；实际证据支持没有直接内容提示，表达可理解 | 不能仅因上下文未记录提示就判独立；不要求超额挑战 |
| B | 全部核心目标完成；至少一项需要局部词语、信息组织或选择提示，仍能继续完成沟通 | 任一核心目标只能靠完整示范复述，或未完成，则不满足 B |
| C | 在较多帮助或完整示范后完成全部目标，或只完成部分核心目标；有效表达中至少有一项目标符合要求 | 仅有词串命中、全程由 Kai 代答不算完成 |
| D | 所有核心目标都未达到；学生已作有效尝试，每项至少有两次不重复的适当机会并提供过合理支持，仍有明显沟通困难 | 无机会、沉默、拒绝、ASR 不可靠、技术故障及不适配任务不判 D |

有一项目标仅部分符合，其余均未符合且未达到 D 的充分机会条件时，保持待复核，不强塞入某档。一次自我更正不自动降档；正常求助是策略行为，具体支持程度按事实记录。

这一量表有意保留“无法评级”，先验证可靠性与教师可理解性。首版不把各档转换成虚假的精确百分制。

### 10.3 辅助维度

教师报告还展示沟通可理解性、目标语言的恰当性、互动与自我修正等描述及来源，不额外按未经校准的权重加总。发生持续误解却被判“完成目标”时，应回查目标语义判断，而不是让高词汇量抵消未完成沟通。

语言错误只有经确认且出现在本次证据内才描述。用“一次需要提示”推断“经常犯错”不允许；“重复出现”建议至少引用两个不同的有效学生轮次，且排除同一事件重发。

### 10.4 教师修订

教师可以确认、调整等级、标记无法评价，或修订事实反馈；每次记录理由与版本。学生看到获准的更新反馈及评语，不看到原等级、改后等级或等级变化通知。

报告重新分析不得覆盖已审阅版本。教师若主动采用新分析，应生成新的审阅版本。学生提出反馈疑问后，教师可将结论改为待核对，不必维持原评级。

## 11. 双端报告与班级概览

### 11.1 学生反馈

内容包括：本次主题及练过的内容、已做到的具体表现、一个优先再练点、少量相关表达 / 活动建议、教师可见于学生的评语、数据覆盖提醒及再练入口。提交后先显示有来源的小结，异步补充分析；无可靠错误证据时不为了完整模板制造“薄弱点”。

学生只获得白名单字段：任务与提交状态、事实反馈、建议、学生可见评语。服务端不给出等级、数值映射、教师内部备注、评分提示词或带等级的分享 / 导出链接。分析文本及 Kai 收尾语也不得泄露等级。

### 11.2 教师个人报告

依次展示当前提交及任务版本、提交 / 迟交 / 技术状态、目标表现与帮助程度、证据覆盖、教师专属暂评与原因、少量证据卡、建议跟进、教师审阅。原始全文、音频和供应商日志不作为默认报告内容。

建议明确区分：主题相关的下一步、可迁移的沟通策略、专项能力未评估项。例如“下次自行提出替代选择”与“声调准确度未评估”可同时出现。

### 11.3 班级概览

每人一行展示姓名、本人任务摘要、提交 / 迟交、核心目标表现、可评 / 待复核、教师专属等级、审阅状态及优先跟进点。支持按未提交、待复核、需要教师介入筛选；不展示学生排行榜。

共性建议按可比目标聚合，带“已观察人数 / 有效机会人数 / 分配人数”。不同目标不能因同属点餐就混为同一能力统计；四人样本只用于演示，不作总体效果推断。

教师可基于建议生成下一份作业草稿；不会自动发送或发布，允许仅作为课堂备课参考。

## 13. 非功能与数据要求

### 13.1 实时体验

沿用既有全双工、打断、渐进字幕、语速及拼音控制。新报表不阻塞语音；目标 / 评价变更不绕过 response / turn 归属、取消和迟到隔离。准备及逐轮预算沿用当前约束，不能为了补齐作业目标无限等待。

报告耗时需实测 P50 / P95，首版显示排队、处理中、失败和重试；试点后再冻结时延服务目标，不在未测时承诺固定秒数。

### 13.2 本地持久化

作业跨课后时间，需保存任务、分配、提交、版本与最小报告，服务重启后可恢复。建议通过本地 Mock HSKai 授权边界保存于 Git 忽略的独立命名空间，与开发观测数据分开；不复用未授权的临时文件当业务数据库。

当前最小 Demo 原始音频默认不持久化；整场逐字稿默认不归档。深入报告新 feature 按已告知并获准的用途，记录师生完整可用文本及必要学生语音片段；采集 / 对齐 / 评测 / 删除边界以新版 tasking 为准。反馈所需最小片段、结构化事实与来源在明确告知和授权策略下留存。建议 POC 测试数据采用可配置的短保留期（默认 7 天，仅为设计建议），并提供任务级 / 学生级删除。真实试点的用途和保留期另行确认后才能采集。

删除覆盖证据片段、报告、导出缓存和未完成分析；保留必要的无内容删除回执。权限撤销后不得向当前无权用户返回旧缓存。真实 transcript、音频、密钥及原始 provider traces 禁止提交 Git。

### 13.3 安全与内容

教师输入、材料及学生发言都是数据，不能覆盖系统角色、安全边界或工具权限。沿用已有安全处理；普通作业报告不得混入敏感风险披露。需要人工跟进时使用授权的独立流程，本地模拟回执不证明真人已收到或处理。

本 PRD 不引入新的法律或供应商保证。外部 HSKai 集成、真实儿童授权、专项发音服务及真实上线治理分别评审。

| --- | --- | --- |
| 文档 / 纸面走查 | 需求、旅程、权限和状态规则是否自洽 | 当前提供设计稿，待用户 / 教师评审 |
| 合成 / 本地契约 | 授权、版本、幂等、证据来源、迟到隔离与报告投影 | 尚未实施；后续运行 verify、replay |
| 真实规划 / 分析模型 | 建议、追问提案与报告候选的语义可靠性 | 未新增调用或验收 |
| 真实语音 provider | 固定任务上下文能否接入，实际对话是否给足机会 | 未新增调用或验收 |
| 浏览器与真人音频 | 采音、播放、字幕、打断和学生控制体验 | 未新增检查或验收 |
| 教学试点 | 量表一致性、反馈帮助及教师工作量变化 | 尚未进行 |

后续 runtime / contract 变更必须执行 `npm run verify` 和 `npm run replay`。合成回放、真实 provider、浏览器音频检查分别报告，不互相替代。

### 14.2 必测场景

1. 一次发布四人共同主题与不同目标；另一案例四人共用目标，均不强造差异。
2. 多作业并存；学生选择自由聊天，不加载作业；切换任务无旧证据 / 字幕残留。
3. 教师越权、learner 参数篡改、权限撤销、缓存命中和分析进行中授权变化。
4. 发布后改标准、改截止、开始前准备过期、已开始任务版本固定、撤回与迟到报告。
5. Kai 只说过目标、学生仅提关键词、引语 / 否定 / 自述会了、重复事件、未知合理改述。
6. 完整示范后复述、局部提示、帮助顺序未知、ASR final 晚到；未知不得记独立。
7. 目标在第六轮以后出现、长会话账本截断、分段重连，报告如实显示覆盖范围。
8. Kai 未给机会、连续代答、学生拒绝、沉默、任务过难、噪声误识别；不判 D。
9. 学生未达到全部目标仍能明确提交；断网重试不重复；报告失败保留提交成功。
10. 重练未提交保留旧当前结果；新提交不自动取最高；旧报告晚到只入旧版本。
11. 学生页面、接口响应、语音收尾、通知、导出、分享及错误信息均不泄露等级。
12. 教师修订、学生反馈疑问、重复分析；修订版本不会被后台结果覆盖。
13. 无可靠音频评测时不诊断声调 / 发音 / 语流，不据此加减等级。
14. 截止时仍在对话不强制断开；迟交状态独立；延期有记录。
15. 删除期间在途分析不能重建数据；安全事件不进入普通教学报告。
16. 教师仅给主题即可前置规划；共享包无 learner 数据；共用包可形成不同或相同的合理私人计划。
17. 编辑 brief、移出学生、取消、部分失败和生成服务重启；无重复生成或过期覆盖；只重做受影响部分。
18. 作业 / 主题服务关闭、未配置及故障时，原 FreeTalk 准备 / 逐轮 / 小结仍按既有契约工作，新服务调用数为零。
19. 新旧 FreeTalk 输入 / 提示词 / 页面与控制对照；不出现作业提醒、主题包、固定目标、教师报告写入或自动场景切换。
20. 原包的词卡 / 例句 / 评估缺口不被默认补齐；指定表达不受支持时明确呈现；发布后开聊不重新选择核心目标。

### 14.3 教学质量验收

准备独立的作者对话集，覆盖四种学习背景及三种任务类型。独立期望与参考评分仅供评估，不进入被测模型上下文。教师在不知道 AI 暂评的情况下标注目标机会、实际支持、任务结果和等级，再比较分歧。

记录可评覆盖率、错误独立判定、错误低评、虚构错误 / 成果、暂评与教师差异。先做校准再设一致性门槛；等级暂时不能可靠生成时，可上线描述反馈和人工评价的试验流程，但必须明确自动评级尚未验收。

## 15. 实施前能力差距与建议顺序

用户最新决定：先以[最小 Demo 蓝图](../teacher-homework-minimal-service-blueprint.md)交付一位教师、一位学生、一份预置计划的发布 / 主题对话 / 明确提交 / 双端事实反馈。执行顺序调整为 G0 → G-Demo → 教师 / 学生 / Kai 角色完善。下表保留完整目标的能力差距，不是最小 Demo 的先决实施顺序；AI 自动备课、多学生与等级后移，计划 / 授权 / 提交 / 报告架构边界不省略。

| 当前基础 | 新需求缺口 | 建议顺序 |
| --- | --- | --- |
| 原仓库主题资源 / 初始化机制可参考，本 FreeTalk 未移植 | 最小教师 brief、后台主题资源、前置按人 TaskPlan、预览与版本发布 | 第一阶段：教师方向到可执行教学包；同时建立必要的本地授权与持久化 |
| 自由聊天，初始正式目标为空 | 独立作业入口与场景边界；FreeTalk 零新增依赖及行为 | 第二阶段：点餐纵向切片；验证关闭新服务仍可 FreeTalk |
| 初始 / 逐轮 Planner 与真实全双工 | 在独立场景执行已发布计划、多目标机会覆盖及主题连续性 | 第二阶段同时验证实际语音行为与旧功能回归 |
| 有来源小结、attempted-only 记录 | 全任务证据账本、通用语义与帮助因果判断 | 第三阶段：先描述反馈，再经验证启用暂评 |
| 前五轮开发观测 | 教师报告、学生反馈、权限投影与异步恢复 | 第三阶段：双端报告和教师复核 |
| 单场观察与四人 Mock | 班级可比目标聚合、下次教学建议、三任务泛化 | 第四阶段：教学试点与量表校准 |

实施切片见[技术方案](../teacher-assistant-technical-design.md)、[完整 tasking](../teacher-assistant-tasking.md)及[Demo tasking](../teacher-assistant-minimal-demo-tasking.md)。原 G1～G4 保留为完整能力验收标号，G-score 仍独立；当前优先执行 G0 和 MD-01～MD-08。当前仍未实施，不因文档完成自动创建运行分支、接入外部服务或修改现有业务合同。
