# 独立中泰 Free Talk 实验入口

2026-10-28。按用户要求单独提供中泰版本，原中英自由对话与教师助教规则保持原样。工程入口已实现并可试用；**真实模型的连续语言遵循与泰语听感尚未验收，不是正式质量完成。**

后续已完成一轮[状态反复验证与修复](free-talk-thai-state-validation.md)：修复 8 项页面 / 语言状态 / 检查问题，849 项工程检查、27 次故障浏览器检查与新旧正常页面通过；真实 6 场 15 轮收齐，自动恢复泰语仍未稳定。下文 844 项和首次未完成记录为入口交付时的历史结果，不覆盖后续发现。

另完成[英文输入配对对照](eval-results/2026-10-28-thai-english-input-control.md)：40 场 / 48 轮真实服务对话收齐。固定提示的九组配对中，中文输入均为中泰，英文输入均变为英泰；多轮历史会影响此表现。实际中泰入口复现，原中英四场保持中英顺序。本轮只新增实验与记录，没有修复产品语言规则；852 项工程检查通过，泰语听感仍未验收。

## 使用

```bash
npm run poc:thai
```

打开 [中泰 Free Talk](http://127.0.0.1:4311)。使用原本机 `.env` 的豆包配置和 MiniMax 配置；可用 `ASK_KAI_THAI_PORT` 改端口，`ASK_KAI_THAI_PROVIDER=replay` 只看未连接预览。没有审核后的真实语音配置时，页面不会假装接通。需要 Node ≥22.19。

选择虚构学习者和初始语速后开始。麦克风只在当前真实 provider 就绪后开启；连接前的准备不是语音就绪。可手动打断、静音、结束，保留中文口头调速和拼音开关；泰语部分不加拼音。没有教师主题、课程或作业入口。

中泰版学习目标仍是中文交流，泰语只做理解帮助。中文优先，初学或理解未知时提供泰语；熟悉表达可减少支架，新表达与求助恢复帮助。可明确说“接下来只用中文”或“加上泰语解释”。宿主有本轮 / 本场范围隔离，但**真实豆包在“这次只用中文”后，下一轮自动恢复泰语的表现仍不稳定**；页面已说明，未恢复时可明确请求泰语。语音模型的文本输出、发音正确、自然度及等义是不同验收项。

## 隔离方式

- 独立应用：`apps/free-talk-thai/`；原入口仍由 `npm run poc` 启动，默认 4310。中泰使用 4311，不修改或重启原服务。
- 独立 `ask_kai_thai_launch` Cookie、`ask-kai.thai.v1` WebSocket 子协议、`/api/realtime-thai` 路径、一次性准备和票据。两种入口的 Cookie 不互换。
- 每次启动中泰进程单独创建 Mock HSKai；身份、三类画像和小结仍经授权端口访问。小结只留此进程内存，重启重置。未接外部 HSKai。
- 中泰本场语言状态与原 `support_language` 分开；不将旧 `zh_en` 解释成泰语，不写回原画像。此入口没有偏好写接口。新会话恢复本场默认。
- `packages/free-talk-thai/` 单独拥有语言状态、语音指令、Planner 适配和文字表面审计。只适配可信静态规则，不全局替换用户输入、画像或供应商输出。原提示词、语言状态、初始化契约和默认 Planner 文件保持原样。
- 初始、逐轮规划继续复用已有预算 / 校验 / 取消；Planner 只在中泰实例中适配系统规则，数据和旧策略契约保留原义，当前支架语种由场景明确提供。仍是 `next_turn_advisory`，不声称每句先规划。
- 共用实时链路只增加可选的调速确认、拼音确认和文字审计注入。没有注入时走完全相同的原中英实现；教师助教不注入它们。没有变更 provider wire 协议。
- 中泰字幕单独使用泰语分词计量；原中文 / 英文字幕文件未改。中文注音、音频队列、回复归属与迟到隔离继续使用已有组件。
- 中泰小结保留有来源中文条目；不显示旧词表的英文释义，也不自动制造未经审核的泰语词卡。取消回复与播放不算掌握。当前没有照搬原页面的画像编辑、观测导出或 Slides 功能。

| 层级 | 结果 | 实际边界 |

| 完整工程回归 | `npm run verify`：844/844 通过，含 9 项中泰新检查 | 包含原中英、教师助教及共享语音事务；不代表教学或音质合格 |

| 原 FreeTalk 冻结基线 | 8 个文件 hash 完全不变 | `npm run check:teacher:isolation`；共享 realtime 接点另外由默认行为回归覆盖 |
| 新中泰页面 | 合成浏览器通过，0 页面错误 | 未配置时阻止采音；中泰字幕 / 中文拼音、手动 / 语音开关、打断清理、小结、390px 无横向溢出；测试器显式替换就绪依赖，产品代码仍拒绝 synthetic 就绪 |
| 新入口真实语音链路 | 已实测真实 MiniMax 初始计划与 Doubao 生成、音频、回复归属 | 作者系统 TTS 输入；没有真人麦克风 / 听感，不能把文字或非静音当作泰语发音验收 |
| 连续语言要求 | **未通过质量门** | 三次有界范围实验均观察到“本轮只中文”后下一轮没有恢复泰文；ASR 对该命令并非完全匹配，宿主状态与模型遵循需分别追查 |

首两轮实验和最终指令版的所有汇总均保留，不能只挑第一次泰语成功。最新三轮结果：求助轮生成中泰文字及音频；本轮中文请求的回复没有泰文；后续词义求助只有中文。后两者不能认定完整作用域验收通过。宿主本轮状态、精确旧话轮隔离和新会话重置已有工程验证，仍不代表模型按音频 / 历史执行。

普通自然聊天也独立补测，完整结果及未完成尝试见 [分层验收数据](eval-results/2026-10-28-free-talk-thai-entry.json)。该文件只包含汇总指标与内容 hash，不包含密钥、完整转写、音频或供应商原始消息。真实服务实验输出不进入学习记录之外的仓库数据；原始音频不保存在此应用。

两次自然聊天采集中，第一次仅收齐第一轮中泰回复，第二轮未完成；一次有界重试在收到 ASR、回复开始及音频后等待完成事件超时，未收齐完整轮次。均保留为未完成，不能算连续自然对话通过。因此此次交付为独立可试用的工程实验入口，连续真实语音和语言质量验收继续开放。

本次页面问题中，已修复独立静态服务将 `.mjs` 返回为 HTML 导致拼音库加载失败；合成测试器取消回执的旧话轮编号也已修正。普通中英页面未受到这两项独立测试问题影响。

## 后续质量门

1. 确认实际 ASR 命令及 native S2S 的本轮语言范围，不用宿主状态成功代替声音模型遵循。稳定自动恢复之前，不去掉实验标识。
2. 泰语熟练者回听中文 / 泰语对应、发音、自然度、数字与专名；现有 S2S 的官方泰语支持范围仍待供应商确认，不能引用独立 TTS 的语种表代替。
3. 真人浏览器麦克风、长对话、插话和调速竞争验证。泰语输入及泰语口头控制没有获得验收，不宣称支持。
4. 若 native S2S 无法稳定执行，再按 [Spike 候选路径](free-talk-thai-support-spike.md)独立验证多语种 TTS；不直接将两路音频拼接后当作完成。
