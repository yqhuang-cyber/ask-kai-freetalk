# GE-01～04：中文输出标准与逐轮目标进展

日期：2026-10-28。范围：教师主题作业 POC；不改 FreeTalk。对应[需求核查](teacher-assistant-status-2026-10-28.md)中 GE-01～04，补 TA-07 / TA-11 / TA-12 / TA-15 的目标执行子集，不宣布这些完整父任务已全部完成。

## 本次行为

教师的新 AI 草案和预置点餐计划都明确要求学生用中文说出口。每项目标保存任务、观察标准、`output_requirement`（固定 `language=zh`、`modality=spoken` 和可接受表达说明），随发布 hash 固定。教师可以编辑说明，接受上下文短答和合理变体，不要求照读；英文求助可以支持，但全英文回答不代替中文输出。

会中 MiniMax 读取有界近期上下文和必要的旧目标证据，逐轮重新判断 `observed / not_yet / uncertain`；程序核对目标、原文、角色、回复状态与来源。模型选择下一目标 / 帮助 / 完成邀请 / 拓展，并提出简短中文问题；程序将它编译成“听到的中文问题 → 要表达的信息 → 中文输出标准 → 允许的支持”，交给后续安全回复边界。没有使用旧 FreeTalk planner。

点餐示例：说出食物后主要引出口味；食物与口味都有表达证据时，肯定具体表现，并提供继续练习或结束的选择。选择继续保留麦克风，不重复弹出邀请；选择结束停止采音，仍需明确提交。学生也可以在目标未练到时结束。会中观察不等于掌握、独立完成、纯听力、发音合格或等级。

## 时限与真实执行边界

原 TA-11 的 2 秒预算在本机真实 MiniMax 初测中 8 项只有 2 项按时得到可接受判断。当前采用 **6 秒异步总预算**，包含权限读取、外呼、至多一次剩余预算内修复、校验和写入前权限复核；语音路径不等待这个结果。超过预算保留未确认，不把旧结果回写新轮，也不凭超时宣布练到全部目标。这是当前作业场景对原 2 秒计划的明确调整，不能表述为达到 2 秒逐轮服务指标。

规划结果为 `next_turn_advisory`。程序在宿主现有安全边界更新上下文；模型提案、上下文 ACK、实际语音是否按建议生成是三回事。页面可以先给出有证据的进展与选择，不能声称每句自动生成语音都先经过该轮规划。

引用由模型选择原话，程序定位唯一匹配的 UTF-16 区间；不要求模型计算汉字位置。英文、Kai 示范、引语 / 转述、词义求助不能制造中文成果。否定 / 更正重新判断；不把每轮结果永久累加。未观察到不解释为不会。模型语义仍需独立教学核对，程序来源检查不能证明解释正确。

## 记录、授权与配置

- 新会话告知更新为 `deep-report-notice-v6`，说明会中必要文本用于 MiniMax 目标引导，提交后另行异步生成深入报告；无需增加勾选。旧 v4 / v5 记录可按原用途读和分析，不因此开启新的会中外传。
- M4 内部 `turn_planning_authorize` 在外呼前和接受结果前检查本人、作业、会话、有效期、当前文本授权 / 用途及 grant 代次；此操作不暴露给浏览器 API。撤回会取消在途规划并清空相关会中上下文，语音仍可继续。
- 近期来源最多 10 条，另保留各目标必要引用，总上下文最多 20 条、每条最多 400 字；过长的当前输入不作为截断成果外传。来源窗口和元数据有界，超出覆盖明确标记。
- 会中引用只作为 `deep_records.live_goal_progress` 归属授权文本记录；封口时再核对 M4 实际原文。它不进入更长保留的基础 evidence / baseline report，随文本撤回、到期和删除清除。双端报告只在当前文本权限通过时读取该观察，离线模型仍独立核对相同发布标准。
- 入口默认沿用 `ASK_KAI_TA_REPORT_TEXT_PROVIDER=minimax`、本地 MiniMax 配置。可用 `ASK_KAI_TA_TURN_PROVIDER=none` 显式禁用会中模型；这不伪装成已有进展判断。不要把 key 写入代码、文档或测试结果。
